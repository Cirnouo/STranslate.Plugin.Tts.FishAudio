# Framework and coverage compatibility

Status updated 2026-10-28: current Unreleased coverage compatibility implementation. The preserved observations apply only to their recorded source/build identities. Nine representative sessions have passed collection, diagnostic review and case admission. The public actual-index entry also passed one synchronous case through snapshot preparation, normal execution, collection and admission, preserving the original index bytes and tree. These are bounded capabilities, not a complete migration or reusable product baseline. The [test-system specification](../specs/test-system.md#isolated-coverage-compatibility) owns the collector/admission contract; [DD-070](../adr/current/DD-070.md) records the framework foundation and [DD-071](../adr/current/DD-071.md) records isolated coverage admission.

## Selected execution route

Ordinary framework execution uses NUnit 4.6.1, NUnit3TestAdapter 6.3.1 and Microsoft.NET.Test.Sdk 18.11.0 through VSTest on SDK 10.0.403. Exact versions remain in the [test project](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/STranslate.Plugin.Tts.FishAudio.Tests.csproj), lock files and [global.json](../../global.json). The [modern profiler pin](../../.config/dotnet-tools.json) is dotCover CLI 2026.2.3.1. The unified driver retains normal Release/full validation; coverage uses separate Release output with matching portable symbols and auto-packaging disabled.

The coverage collector independently discovers the actual coverage assembly, resolves one exact canonical leaf and profiles that leaf in its own process tree. It launches the selected SDK's `sdk/10.0.403/vstest.console.dll` directly with `dotnet exec` under the fixed modern dotCover CLI, then exports the resulting native snapshot. Each isolated execution has separate raw artifacts and supervision. This route does not depend on a profiler-generated per-test relation table and does not subtract cumulative coverage snapshots to invent individual case results.

Original native first-use state, same-owner chains and watchdog responsibilities remain authoritative. A direct shared-STA construction probe or an isolated child sample does not establish migration of the existing cold settings/popup profiles. Compatibility observations do not authorize splitting a native workflow, warming it up or rerunning setup to obtain attribution. The complete legacy catalog and both complete NUnit catalogs remain mandatory in the hybrid commit gate and PR/main validation.

## Public commands and validation scope

The public entry is [Test.ps1](../../tools/Test.ps1). In these examples, `$newResults` is a fresh absolute directory outside the repository, and `$existingSessions` is an existing parent containing admitted `session-*` directories. Stage the intended source inputs before an execution scenario: preparation freezes the actual index, respects `GIT_INDEX_FILE` and excludes unstaged/untracked changes. New snapshot/preparation helpers must be present in that staged tree.

```powershell
./tools/Test.ps1 -Mode Compatibility -Scenario IsolatedCase -CaseId 'compat.sync/api-key-format' -ResultsDirectory $newResults
./tools/Test.ps1 -Mode Compatibility -Scenario Performance -EvidenceDirectory $existingSessions -ResultsDirectory $newResults
```

`IsolatedCase` performs normal exact framework execution and the isolated modern coverage fallback for the selected case. `SameHost` selects the ordinary A/B framework pair, followed by separate isolated coverage sessions; it does not claim shared-host native profiler attribution. `ChildAttribution` selects two representatives: direct STA view construction and the supervised legacy child. Omitting explicit IDs in the default scenario selects the current nine representatives, not the complete product catalog.

`-Mode DiscoverCoverage` restores the pinned CLI on its default build path, prepares separate coverage Release binaries and discovers both catalogs. It executes no cases and establishes no full baseline. `Performance` reads existing admitted evidence and verifies its bound records and representative controls without running tests or the profiler. Public preflight, misplaced-parameter and raw transport controls have passed. Snapshot preparation has separate disposable-Git evidence, including alternate/split indexes and raw bytes. The successful public actual-index invocation independently exercised its single selected leaf; it does not extend that result to the nine representatives or the complete catalog.

[Snapshot preparation](../../tools/New-TestSnapshot.ps1) keeps source and build paths in a short fresh temporary owner and records its context separately. It retains raw Git bytes and index identity rather than copying the live working tree. Extended/device namespace paths and components containing a tilde followed by ASCII digits are conservatively unsupported. Failed outputs, private pointers and earlier attempts remain available for diagnosis; they are not rewritten into successful evidence.

The modern export review is restricted to observed framework state-machine warnings. Its rule binds the selected SDK/TestHost binaries, module identities, embedded source and exact warning blocks, and preserves the unresolved zero-hit nodes in the raw aggregate. It does not reclassify arbitrary profiler errors or infer missing product coverage. A new or changed warning requires its own review; a prior reviewed sample does not authorize accepting new diagnostic bytes.

Console review separately consumes all four captured cover/export stdout/stderr streams. The current versioned rule accepts the observed fixed Windows x64 banner and CP936 copyright bytes, complete ordered progress messages and valid timestamps, with empty stderr. Its seventeen controls and replays of all nine preserved stream sets passed. Other encodings, extra diagnostics and truncated output remain unreviewed and are rejected; another machine's encoding needs explicit evidence before extending the rule.

The A/B evidence contains three unique product-report method hits for each case and two shared hits in both; the other case's three unique methods are absent. These are checked report observations, not a completed Roslyn source-symbol mapping. The current child sample binds the owned apphost to the current test host and source/request/case, verifies its normal exit and records genuine EOF on both child pipes. Test-host lifecycle and external Job/profiler completion retain their separate meanings. The direct STA sample still does not replace the original native watchdog. The repository-resource sample legitimately has zero product coverage and binds `.config/dotnet-tools.json` to its recorded source SHA-256 dependency.

The earlier owned-child compatibility sample predates the explicit pipe-EOF fields required by the current evidence reader and remains raw evidence. It cannot acquire a current admission receipt by inferring those missing observations. Later admitted child evidence does not change that earlier sample or any failed attempt's status.

## Timing reference

The nine admitted representatives recorded these ranges on one Windows machine. The external recorder wall time covers each collector process; leaf and phase durations have narrower meanings. These are observations, not acceptance thresholds or a measured full-catalog forecast.

| Measurement | Observed duration | Scope |
|---|---|---|
| NUnit leaf | 6.696–2913.415 ms | The selected leaf as reported by NUnit/TRX. |
| Supervised cover phase | 10.667–14.115 s | The profiler/direct-VSTest phase, including owned process completion and output drains. |
| Supervised export phase | 1.474–1.604 s | Export of the completed native snapshot. |
| Per-case recorder wall time | 25.7–30.2 s | The external recorder's complete collector-process observation, including metadata, collection and admission work. |
| Native snapshot | About 6.76 MB per case | The retained `.dcvr` file. |
| Aggregate JSON | About 5.82 MB per case | The retained coverage report. |
| Admitted case JSON | About 4.57 MB per case | The admitted record, which still retains unresolved report observations. |

Builds are outside the per-case collector wall range. XML exports, logs, discovery, lifecycle and child-proof artifacts add to the three listed file sizes. Cover/export values alone exclude the remaining collector work, so their sum is not total collection time. Callback/prologue intervals are observed envelopes; subtracting them does not isolate pure startup or test-execution cost.

The nine collections were observed serially, one session at a time against an immutable build. That scheduling observation is separate from the existing-evidence `Performance` report, whose `coverageConcurrency` is null because it performs no new measurement of overlap. No parallel coverage speedup, full-catalog cost or stable overhead has been established. The existing [execution budgets](../policies/verification.md#test-ownership-and-budget-preflight) retain their meanings; these measurements add no performance budget, and cover/whole-assembly execution receive no new overall deadline.

No formal coverage baseline, complete source/dependency closure, affected-case selector or impact-based CI transition has been implemented or published by this work. The Roslyn capability probe establishes only its two documented semantic bindings. Per-case coverage observations retain unresolved source mappings until a later admission step can bind them honestly.
