# DD-048: Keep voice totals separate from accessible pagination

**Status:** Current.

**Recorded:** 2026-10-20.

## Context

The provider now returns approximate totals and accessibility-window metadata. Converting `total` directly into a page count can offer unreachable pages. Real responses contain both `max_offset=1000` and `accessible_upper_bound=1002`, so these values cannot simply be treated as the same count. See the [voice-list reference](../../references/voices-list.md) and [real evidence](../../evidences/2026-10-20/README.md).

## Decision

Represent reported total, total exactness, accessible page bound and next-page availability separately. Optional DTO fields preserve the difference between absence, zero and false. Treat `max_offset` conservatively as the exclusive window for a request's starting offset, while `accessible_upper_bound` limits accessible records. Combine applicable bounds without rejecting a partial final page: page 167 at size six starts at offset 996 and remains permitted under a 1000-record window.

An explicit `has_more=false` or raw empty page stops forward navigation. Approximate totals alone cannot authorize arbitrary jumps. Without a known upper bound, allow already visited pages and the currently permitted next page. Preserve old `total/items` responses; when total and metadata are both missing, a raw full page allows one further attempt. Do not automatically chase empty pages.

Commit pagination with the successful query and results, before cover resolution. Failed or stale requests cannot replace that state; editing an unsubmitted query cannot change a subsequent page request. Page arithmetic uses wide intermediates. Count raw provider records before filtering explicit non-TTS types; missing type remains accepted for legacy compatibility. Apply the same explicit-type selection rule to by-ID lookup.

### Search-criteria amendment, 2026-10-24

The committed query is now a complete immutable session criteria object: query text, nullable scalar language and sort enum. The accepted credential remains separately captured and is never included in printable criteria. Search/Enter capture the visible text with successfully applied options. Apply captures the visible text with drafts, closes the native popup and performs exactly one page-one GET even when the options are unchanged. Reset drafts All + Relevance first and Close discards drafts; neither requests data. Options are session-only. Successful current-owner UI publication commits criteria, results and navigation together, after provider mapping validates and before cover/cache enrichment; queued work rechecks its owner. Request failures and replacement/credential/disposal retirement preserve the previous successful relationship. Enrichment failure cannot partially fail the already valid metadata snapshot.

Use a compact embedded action and a 324-DIP clamped native popup, with one flag/name ComboBox and three localized sort radios. Intersect the visible ancestor scroll presenter bounds with owner and monitor bounds on both axes; prefer above the trigger when needed and height-limit/scroll content when the natural popup cannot fit. Relevance first maps to `score`, Most used first to `task_count`, and Newest first to `created_at`; the radios display titles only, without helper descriptions. This label choice does not assert a score formula or documented direction. The reference distinguishes first-page descending observations from the provider contract. Keep six raw records per page and preserve existing numeric entry and independent By-ID behavior.

A per-view token owner is shared with language overflow. The actual native ComboBox child popup is owned input without treating unrelated dropdowns as owned. First Escape closes the child, second closes the main popup and returns focus. Outside press, tab/page scrolling, deactivation, hide, rebind and unload retire the overlay; movement, resize and DPI changes reposition it. Subscriptions exist only during ownership, and a stale release cannot retire its successor. This keeps the native selection behavior and separate popup presentation sources within an explicit lifecycle boundary.

Keep the existing numeric ViewModel properties for compatibility. Display approximate totals with `≈`, unknown values with `?`, and accessible upper bounds with `≤`. Navigation uses the applied policy's `HasNextPage`, not the presentation number. Explain the provider window in all seven UI locales.

## Consequences and limits

Users can browse the permitted tail page and narrow a search to find more voices. An accessible upper bound does not guarantee every page will remain populated in a changing library. Exact `max_offset` boundary semantics were not live-tested at the provider's window edge; this is a conservative client interpretation with deterministic boundary tests. It does not change synthesis model discovery or ranking.
