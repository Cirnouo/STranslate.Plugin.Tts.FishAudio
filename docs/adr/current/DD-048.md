# DD-048: Keep voice totals separate from accessible pagination

**Status:** Current.

**Recorded:** 2026-10-20.

## Context

The provider now returns approximate totals and accessibility-window metadata. Converting `total` directly into a page count can offer unreachable pages. Real responses contain both `max_offset=1000` and `accessible_upper_bound=1002`, so these values cannot simply be treated as the same count. See the [voice-list reference](../../references/voices-list.md) and [real evidence](../../evidences/2026-10-20/README.md).

## Decision

Represent reported total, total exactness, accessible page bound and next-page availability separately. Optional DTO fields preserve the difference between absence, zero and false. Treat `max_offset` conservatively as the exclusive window for a request's starting offset, while `accessible_upper_bound` limits accessible records. Combine applicable bounds without rejecting a partial final page: page 167 at size six starts at offset 996 and remains permitted under a 1000-record window.

An explicit `has_more=false` or raw empty page stops forward navigation. Approximate totals alone cannot authorize arbitrary jumps. Without a known upper bound, allow already visited pages and the currently permitted next page. Preserve old `total/items` responses; when total and metadata are both missing, a raw full page allows one further attempt. Do not automatically chase empty pages.

Commit pagination with the successful query and results, before cover resolution. Failed or stale requests cannot replace that state; editing an unsubmitted query cannot change a subsequent page request. Page arithmetic uses wide intermediates. Count raw provider records before filtering explicit non-TTS types; missing type remains accepted for legacy compatibility. Apply the same explicit-type selection rule to by-ID lookup.

### Search-criteria amendment, 2026-10-24

The committed query is now a complete immutable session criteria object: query text, a detached read-only language set in preset order and sort enum. The accepted credential remains separately captured and is never included in printable criteria. Search/Enter capture the visible text with successfully applied options. Apply captures the visible text with drafts, closes the native popup and performs exactly one page-one GET even when the options are unchanged. Reset drafts All + Relevance first and Close discards drafts; neither requests data. Options are session-only. Successful current-owner UI publication commits criteria, results and navigation together, after provider mapping validates and before cover/cache enrichment; queued work rechecks its owner. Request failures and replacement/credential/disposal retirement preserve the previous successful relationship. Enrichment failure cannot partially fail the already valid metadata snapshot.

Use a compact embedded action and a 324-DIP clamped native popup, with eleven equal 32-DIP language ToggleButtons in two columns with 6-DIP gaps and three localized sort radios. Intersect the visible ancestor scroll presenter bounds with owner and monitor bounds on both axes; prefer above the trigger when needed and height-limit/scroll content when the natural popup cannot fit. Relevance first maps to `score`, Most used first to `task_count`, and Newest first to `created_at`; the radios display titles only, without helper descriptions. This label choice does not assert a score formula or documented direction. The reference distinguishes first-page descending observations from the provider contract. Keep six raw records per page and preserve existing numeric entry and independent By-ID behavior.

All languages owns only the left cell of its first row; specific pairs preserve en/zh, de/ja, fr/es, ko/ar and ru/pt. All is exclusive with specifics; clearing the last specific restores All, while all ten specifics remain filtered. Criteria validate every input code, copy/deduplicate and order by these presets, expose a read-only snapshot, and serialize repeated `language` keys in one request. Unknown/blank/case-altered codes still fail fast. All omits the parameter. Official arrays and SDK serialization support multiple languages, but the provider determines combination semantics; no AND/OR promise is made.

A per-view token owner is shared with language overflow. Escape closes the popup and returns focus. Native Enter/Space on tile/radio choices stays local; Apply is the explicit request action. The finite scrolling body leaves header/footer actions reachable, and long captions trim without shrinking native text or losing full accessible names/tooltips. Outside press, tab/page scrolling, deactivation, hide, rebind and unload retire the overlay; movement, resize and DPI changes reposition it. Subscriptions exist only during ownership, and a stale release cannot retire its successor. This keeps native toggle behavior and the popup presentation source within an explicit lifecycle boundary.

Keep the existing numeric ViewModel properties for compatibility. Display approximate totals with `≈`, unknown values with `?`, and accessible upper bounds with `≤`. Navigation uses the applied policy's `HasNextPage`, not the presentation number. Explain the provider window in all seven UI locales.

### Applied menu intent amendment, 2026-10-25

This replaces only the successful-response ownership of applied menu language/sort in the 2026-10-24 search-criteria amendment. Accepted Apply validates and detaches all options before publishing any state, then commits an immutable options-only session snapshot synchronously before the network await. Reopening while English is pending therefore shows English; failure, malformed data, cancellation and accepted credential retirement (including A → B → A) preserve that intent. The indicator reflects latest applied nondefault options. Rebuilding starts All + Relevance first; settings storage is unchanged.

The full successful query/filter/sort, results and navigation remain a separate atomic current-owner response publication. Paging uses that complete last-successful criteria even when newer menu intent is pending or failed; its response cannot overwrite menu intent. Explicit Search captures the current visible query with latest applied options. Open popup input drafts remain detached: an English response cannot overwrite a German draft, while closing/reopening restores applied English. Disposed owners and invalid Apply actions publish no intent and issue no request. The existing explicit one-GET Apply, no-GET draft/reset/dismissal, credential/cache, cancellation and stale queued-publication fences remain active.

### Native popup presentation amendment, 2026-10-24

Use restrained native Fluent chrome for both search adjustments and read-only language overflow: 324/290-DIP maximum shells, dynamic host flyout resources, measured fixed headers/actions and scrolling bodies. Reserve the actual expanded native scrollbar part plus 4 DIP rather than copying its template or assuming a fixed thumb width. Keep the lane for the open lifetime, reacquire replaced parts and detach on retirement. If neither trigger side can fit localized fixed chrome and one complete option, clamp across the trigger within the visible viewport; refuse/close when fixed chrome cannot fit at all.

The desired material is transient Acrylic on the exact popup HWND through the already installed public toolkit APIs. Use the documented Windows 11 22621 floor, a nonlayered source selected before creation, transparent client composition and successful frame/attribute readback before removing the opaque WPF fill. The host main Window is outside this ownership. Failed/unsupported capability uses explicit native opaque flyout chrome. Readback is capability evidence only; visible material and physical input require installed-host acceptance. The [current popup contract](../../specs/voice-browsing-and-preview.md#shared-popup-chrome-and-native-material) records source versions, geometry, lifetime and evidence limits. No API key, provider request, additional Window or dependency is introduced.

### Shared popup Mica amendment, 2026-10-25

This replaces only the transient Acrylic request in the 2026-10-24 native popup presentation amendment. Both owned popup shells now request the pinned host's Mica family through the existing public toolkit `BackdropType.Mica` API. Only successful frame/readback with `DWMSBT_MAINWINDOW` (2) enables the transparent WPF shell; Desktop Acrylic (3) and failed capability retain explicit opaque native flyout chrome.

Keep the documented 22621 floor, precreation nonlayered source, transparent composition/frame, exact popup ownership, native theme/corners and independent failure/cleanup/source retirement. No host HWND change, new Window/dependency/controller or activation manipulation is introduced. Correct request and accepted readback establish capability; composed appearance, policy-dependent solid material and installed-host matching remain separate acceptance. See the [current popup contract](../../specs/voice-browsing-and-preview.md#shared-popup-chrome-and-native-material).

A bounded compiled-popup experiment demonstrated exact background discovery using the existing localized heading as native window text. Retain that optional source-local heading lease for both shells: bounded prior read, same-live-source checks, compare-before-update/restore, other-writer retention and fresh ownership on reopen. Its failures remain independent from material/input, and destroyed sources are skipped. This supplies native identity without a visible caption or an accessibility claim; it does not verify composed Mica appearance.

### Fresh popup measurement amendment, 2026-10-25

Keep the existing side policy: below when the complete natural shell fits; otherwise above when it fits; otherwise the larger usable side, with below on ties. Refresh every element on the body's owning measure path through the shell before both synchronous body-excluded chrome and restored-body natural measurements. Changing only the body's MaxHeight leaves ancestor invalidation deferred; a still-valid Grid/shell can reuse chrome as natural height, or natural height as chrome during live resize. These observed cache boundaries require fresh measurement, without retained placement state or a changed fit/refusal threshold. Use the current owned native source and preserve both popup clients, physical callback coordinates, viewport intersections, insets, fixed localized chrome, scrollbar ownership and source retirement. The compiled causal regression and existing responsive-language lifetime case cover the two directions of stale measurement. This amendment is implemented in unmerged Unreleased sources; final integrated and installed-host gates remain pending.

## Consequences and limits

Users can browse the permitted tail page and narrow a search to find more voices. An accessible upper bound does not guarantee every page will remain populated in a changing library. Exact `max_offset` boundary semantics were not live-tested at the provider's window edge; this is a conservative client interpretation with deterministic boundary tests. It does not change synthesis model discovery or ranking.
