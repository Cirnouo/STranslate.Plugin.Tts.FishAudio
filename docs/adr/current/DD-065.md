# DD-065: Select explicit regression contracts and retain complete CI coverage

Status: accepted for the current executable regression runner.

Current interpretation: [DD-069](DD-069.md) replaces the local pre-push requirement below with an installed staged-tree pre-commit full bootstrap gate. Affected selectors remain diagnostic tools; complete PR/main CI remains required during this migration stage.

## Context

The offline runner accumulated many focused entry points alongside one sequential full invocation. Local failures could occur late, leave later coverage unexecuted, and require manual reconstruction of a suitable recovery command. Native rendering matrices also made total runtime difficult to attribute. Source directories alone do not establish independence: compiled views, dispatch, theme resources, storage and test helpers cross domain boundaries.

## Decision

Keep explicit executable registration and assign stable logical group/case IDs and execution partitions. Listing is metadata-only. Invalid or empty selection is an error, and legacy focused entry points retain their existing scenarios and proof-output arguments.

When an aggregate is replaced by independent cases, retain its exact old ID as a selection and unfinished-report recovery alias. Expand aliases to current registered leaves in catalog order without adding another default execution or inferring leaf passes from an old aggregate pass. Unknown IDs and empty expansions remain errors.

Use a small, reviewable source/shared-dependency map for local affected recommendations. Combine matching rules, include working-tree changes, and expand unknown dependencies conservatively. Keep selection finer than process or CI partition boundaries. A continuous same-owner workflow remains one replayable case even when its internal phases are measured separately.

Persist source/configuration, selection reasons, monotonic timings, actual outcomes and unexecuted coverage in ignored local run reports. Preserve previous reports. Failure recovery covers failed/incomplete cases and contracts affected by the final repair; it does not turn an earlier failed full command into a pass.

The original local pre-push verification requirement is superseded by DD-069's staged-tree pre-commit gate. Focused affected commands remain available for diagnosis. Every new PR/main validation commit still executes the complete CI regression set during bootstrap. The local recommendation never supplies cross-commit CI status reuse or weakens required checks.

## Consequences

Ordinary local iteration gains a predictable entry point and inspectable coverage without a test-framework migration, automatic call graph or result-cache service. The mapping is intentionally conservative and must be updated when shared ownership changes. Native execution isolation, watchdogs and rendering efficiency remain separate implementation concerns; this decision does not change functional timing assertions or claim a measured performance limit.

Implementation and maintenance rules are owned by the [build specification](../../specs/build-and-release.md) and [verification policy](../../policies/verification.md).
