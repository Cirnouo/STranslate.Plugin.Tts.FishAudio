# DD-006: Latency text is shown temporarily after manual refresh

**Status:** Current.

**Recorded:** 2026-05-06.

**Amended or extended by:** [DD-039](../current/DD-039.md).

**Current interpretation:** Only manual credit refresh displays measured request latency, for four seconds. CreditRefreshCoordinator owns the DispatcherTimer; startup and post-TTS silent refresh do not display latency.

**Migration review:** The timer moved from SettingsViewModel into CreditRefreshCoordinator; the four-second interaction remains unchanged. The startup reference is now [DD-039](../current/DD-039.md).

## Recorded rationale

The original rationale below is retained for traceability; where a migration review narrows it, the current interpretation and linked successor take precedence.

**Context:** The API latency value (`XXX ms`) is only meaningful right after a refresh. Leaving it visible permanently may mislead users into thinking it's a live indicator.
**Decision:** After a manual credit refresh, show the latency text for 4 seconds, then auto-hide it. A `DispatcherTimer` handles the timeout. Startup credit checks do not show latency at all (see [DD-001](../history/DD-001.md)).
**Affects:** `SettingsViewModel.StartLatencyHideTimer()`, `FetchCreditAsync` `showLatency` param.

Reviewed against the current repository baseline (v1.1.2 behavior, SDK 1.0.15); source inspection is not a claim of live API or audio-device verification.
