# DD-057: Keep nucleus sampling above zero as a client compatibility rule

**Status:** Current.

**Recorded:** 2026-10-20 UTC.

**Amends:** The `top_p` numeric boundary in [DD-031](DD-031.md). Temperature and other parameter ranges remain unchanged.

**Precision amendment:** [DD-058](DD-058.md) replaces stored slider-step quantization with displayed decimal precision for direct entry. The positive floor, invalid-value fallback and request-boundary rule below remain active.

## Context

The user reported synthesis errors at `top_p=0`. The current native OpenAPI and HTTP reference still publish the inclusive range `[0,1]`, while the streaming best-practice page recommends `0.1–1.0`. No new live synthesis test establishes the backend's exact rejection rule or model coverage. Treating a client safeguard as a corrected official schema would lose that distinction.

## Decision

Use `0.05–1.0` with the existing `0.05` step for the plugin's nucleus-sampling control. `0.05` is its smallest positive step, a client compatibility floor rather than a claimed provider minimum. Convert stored zero and smaller positive values to at least `0.05` after step rounding. Keep negative, non-finite and greater-than-one values on the established `0.7` default. Preserve valid step-aligned values and the default.

Centralize this rule for settings normalization and both native/HTTP request construction, so a raw in-memory Settings value cannot bypass it and serialize zero. Normal settings may canonically save the repaired value; future/duplicate-schema read-only protection still prevents writes. Advance no schema version.

Keep settings step quantization separate from the request boundary guard. A valid raw fractional request value such as 0.82 retains its precision; outgoing requests apply only the shared validity/default/floor protection. Loading or editing settings still uses the established 0.05 step.

Keep Temperature zero valid. Numeric domains and visual geometry are independent: both native sliders retain the same physical track width, aligned endpoints and value-label width, even with different minimum values. Do not display zero while silently transmitting a different value.

## Consequences and implementation basis

The reported zero boundary cannot be selected or transmitted by the client. This does not claim a newly measured provider restriction or guarantee that every positive value has been tested. Preserve the official discrepancy in [field references](../../references/tts-fields.md), and revisit the guard if authoritative backend behavior becomes available.
