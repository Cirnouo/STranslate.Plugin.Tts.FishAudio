# DD-047: Download public voice previews through host HTTP before local playback

**Status:** Current.

**Recorded:** 2026-10-20.

**Amends:** [DD-034](DD-034.md), [DD-035](DD-035.md), [DD-040](DD-040.md).

## Context

Both preview entry points opened a remote sample URI in WPF MediaPlayer. Metadata and media consequently used different networking paths, and the plugin could not apply its own download deadline or byte bound. Public sample GETs still work and `samples[].audio` remains a string; neither the provider schema nor a failed standalone URI probe establishes a universal cause for the reported playback failure. See [issue #2](https://github.com/Cirnouo/STranslate.Plugin.Tts.FishAudio/issues/2) and the [dated resource evidence](../../evidences/2026-10-20/README.md).

## Decision

Download the existing sample through the host's `IHttpService`, then give a seekable memory stream to a local NAudio player. Do not send account or dummy authorization to an asset and do not synthesize replacement audio. A single operation token covers refresh, resource acquisition and successful-body copying within fifteen seconds. Copy at most eight MiB plus one detection byte; empty and oversized audio fails before player creation.

Keep URL validation and the thirty-second signed-URL refresh window. A resource 403/404 may consume one detail-refresh budget and retry the returned sample once. A prior expiry refresh consumes that budget too. Other errors and repeated failures do not retry. The host stream interface does not expose or let the plugin bound the host's internal unsuccessful-response body handling; the byte cap describes the returned stream copied by this plugin.

One operation generation protects both entry points through download and output start. Stop, replacement, selection changes, originating-card removal and disposal invalidate pending work. Publish playback state only after successful local `Play`, and ignore old device callbacks. The controller owns the stream even when construction/open/play fails, and progress uses device output position rather than decoder read-ahead.

NAudio.Core and NAudio.WinMM 2.3.0 provide seekable MP3/WAVE reading, Windows ACM MP3 decoding and WaveOut output. The stable ViewModel commands and Voice-ID-based preview state remain. Local tests replace network and audio devices; they do not establish physical sound.

The plugin is a class library and the packaging SDK archives its output directory without adding missing NuGet runtimes. Select the two private NAudio runtime items from NuGet's resolved assets and include them in standard copy-local output. Do not enable blanket copying of the host SDK and UI framework. Package verification fails if either audio assembly is absent; a passing test project alone cannot establish that a separately installed plugin has its dependencies.

## Consequences

Preview can use host HTTP proxy routing and has an explicit, bounded local buffer. It downloads one complete, bounded public sample before playing. Formal TTS has a separate playback contract and must not adopt this whole-sample buffering design. Native decoding and sound-device behavior still require Windows integration verification.

## Search playback ownership amendment, 2026-10-24

The [current preview ownership contract](../../specs/voice-browsing-and-preview.md#preview-ownership-and-download) separates accepted search audio from its presentation object. Search/query/Apply/page publication can remove that object after successful Play without stopping or redownloading accepted audio. The controller retains the player/buffer until natural end/failure or intentional Stop/replacement, selection/clear, credential retirement or disposal. Exact origin membership remains mandatory before acceptance, including removal during Open/Play with a different same-ID card still visible. By-ID replacement and originating Favorite removal retain their existing accepted-playback stop semantics.

Accepted-state callbacks may synchronously reenter search publication or explicit retirement. The coordinator recognizes successful acceptance during that handoff, detaches only a removed search origin and preserves operation retirement checks. An old continuation cannot stop a successor, and the controller rechecks its player generation after state publication before installing its timer. No new player, transport, sample request or audio cache is introduced. See the [retention regressions](../../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/SearchPreviewRetentionSuite.cs).
