# DD-052: Decode incrementally into a bounded PCM ring with an independent pump

**Status:** Current.

**Recorded:** 2026-10-20.

**Related:** [DD-047](DD-047.md), [DD-050](DD-050.md), [DD-053](DD-053.md). Preview remains a separate bounded whole-sample path.

## Context

A fixed output buffer does not bound a decoder expanding a full audio event before yielding. Chunks split PCM samples, MP3 frames and metadata. A startup timeout checked only on input cannot start a short prefix during upstream silence. Provider finish and decoder read-ahead do not establish drain.

## Decision

Use signed little-endian 44100-Hz s16 mono for PCM, carrying a leftover byte and rejecting an odd final tail. This is an empirically supported engineering interpretation, not an explicit provider signedness/byte-order guarantee. MP3 keeps one persistent Windows ACM decompressor, validates bounded metadata/residuals and yields one decoded frame at a time. Reuse the two prior MP3 fixtures unchanged; exclude the old SSE/full-POST path.

Write aligned slices into a five-second PCM ring, apply pressure at four seconds and resume at three. Install an independent clock/device pump before production. Initialize and play at 250 ms buffered, 100 ms from first PCM, or completed short audio. Publish playback start only after successful Play and cancellation/device checks. Upstream silence cannot prevent the clock threshold.

Underflow supplies output silence and permits later real PCM. Track the device/source cursor including silence and the final real-PCM tail separately. Require actual position to reach that tail after input completion. Extend the wrapping WinMM position and fail unexpected stop or ten seconds without progress while real PCM is outstanding. Independently clean every decoder/output/cancellation resource; preserve earlier failures and surface cleanup-only failures. Cancellation interrupts startup, pressure, input and drain, including uncooperative input.

## Consequences and implementation basis

Large messages cannot bypass PCM pressure. NAudio Core/WinMM and Windows ACM become runtime dependencies; inspect the distributable. Output start remains a software milestone. Physical sound, coexistence and live latency require separate evidence.
