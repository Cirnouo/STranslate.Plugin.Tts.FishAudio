# DD-062: Prefer configured credentials for voice metadata requests

**Status:** Current.

**Recorded:** 2026-10-23.

**Supersedes:** [DD-004](../history/DD-004.md).

## Context

The user wants metadata endpoints that support keyless use to honor an API Key when configured. Always using dummy prevents the provider from applying the configured account context, including access to its voices. Browsing must still work before a key is entered and must remain independent of synthesis validation.

## Decision

Use the complete configured value for `GET /model` and `GET /model/{id}` when it is nonblank; use `dummy` only for a missing or whitespace value. Search, By-ID, favorites, startup selected-voice refresh and preview metadata recovery share this rule. Do not validate metadata keys through the TTS/credit preflight, retry a rejected configured key with dummy, or introduce extra provider requests.

After a key edit is saved successfully, invalidate pending metadata/preview operations and clear old cards/selected metadata snapshots. Preserve selected Voice ID as an ID-only selected card with Clear and bookmark actions, and preserve favorite IDs. On a rejected or failed save, restore the accepted input value and preserve its metadata. Metadata operations use the accepted settings key, not the input draft. Partition the shared cache by a request-captured private credential digest plus Voice ID under one global 300-entry bound and existing TTL; constructing an uncommitted replacement facade cannot clear another partition. Cache events carry their captured scope and recheck it inside deferred UI publication. Startup metadata commits and deferred UI apply also verify the captured key still matches. Public sample and cover resource requests carry neither real nor dummy authorization. TTS and credit requirements remain unchanged.

## Verification and limits

Offline fake HTTP assertions cover configured and blank credentials, startup refresh, favorites, search/By-ID, bounded preview recovery, no-auth sample requests, rejected-key no-fallback and stale search/favorite/startup/cache publication, failed/retired saves, failed replacement construction and ID-only selection. Existing cover regressions protect unauthenticated resource downloads. This decision does not claim new live provider, private-voice or audio-device verification.
