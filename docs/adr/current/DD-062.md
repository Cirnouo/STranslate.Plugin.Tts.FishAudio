# DD-062: Prefer configured credentials for voice metadata requests

**Status:** Current.

**Recorded:** 2026-10-23.

**Supersedes:** [DD-004](../history/DD-004.md).

## Context

The user wants metadata endpoints that support keyless use to honor an API Key when configured. Always using dummy prevents the provider from applying the configured account context, including access to its voices. Browsing must still work before a key is entered and must remain independent of synthesis validation.

The display-retention amendment on 2026-10-23 separates credential ownership from the lifetime of information the user has already viewed. Resetting every card on each edited character discarded browsing work. Retaining those display snapshots does not authorize a response-cache hit under another key.

## Decision

Use the complete configured value for `GET /model` and `GET /model/{id}` when it is nonblank; use `dummy` only for a missing or whitespace value. Search, By-ID, favorites, startup selected-voice refresh and preview metadata recovery share this rule. Do not validate metadata keys through the TTS/credit preflight, retry a rejected configured key with dummy, or introduce extra provider requests.

After a key edit is saved successfully, invalidate pending metadata/preview operations while retaining Search/By-ID result objects, search pagination/query/expansion, Favorites card metadata and the selected display/CachedVoice snapshot. Preserve cover sources, preview availability, selected Voice ID, favorite IDs and synchronized action states. Do not refresh these cards merely because a character changed. Subsequent explicit requests use the newly accepted key. This replaces only the earlier display-reset clause; configured-key preference, cancellation and captured-credential ownership remain active. On a rejected or failed save, restore the accepted input value and preserve its metadata. Metadata operations use the accepted settings key, not the input draft. Partition the shared cache by a request-captured private credential digest plus Voice ID under one global 300-entry bound and existing TTL; constructing an uncommitted replacement facade cannot clear another partition or promote retained display metadata into a new partition. Cache events carry their captured scope and recheck it inside deferred UI publication. Startup metadata commits and deferred UI apply also verify the captured key still matches. Public sample and cover resource requests carry neither real nor dummy authorization. TTS and credit requirements remain unchanged.

## Verification and limits

Credential identity is runtime state, separate from the digest that indexes reusable cache entries. Successful leased publication rotates it only for an accepted key change and preserves the currently accepted token on ordinary writes, so a reentrant outer save cannot restore a historical token. Startup checks the captured key/token at response, conditional-save and deferred-display boundaries. Rebinding an event delegate that captures the accepted token also protects an old notification when an earlier subscriber reenters A → B → A. No token is serialized or stored in a cache entry. The no-lease compatibility facade rotates only after save returns and retains its preexisting temporary mutation window; it does not gain leased transaction semantics.

Offline fake HTTP assertions cover configured and blank credentials, startup refresh, favorites, search/By-ID, bounded preview recovery, no-auth sample requests, rejected-key no-fallback and stale search/favorite/startup/cache publication, failed/retired saves and failed replacement construction. The amendment also checks retained card fields and identities, applied browsing state, saved selected snapshots, subsequent new-key requests without cross-key cache promotion, A → B → A startup and queued/reentrant event publication, current-owner disposal, and identity retention across ordinary/failed/reentrant saves. Existing cover regressions protect unauthenticated resource downloads. This decision does not claim new live provider, private-voice or audio-device verification.
