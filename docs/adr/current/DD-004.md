# DD-004: Voice search and voice-by-ID use dummy API Key when user key is invalid

**Status:** Current.

**Recorded:** 2026-05-06.

**Amended or extended by:** [DD-030](../current/DD-030.md).

**Current interpretation:** Voice browsing uses the dummy bearer token independently of the user API Key. The production discovery coordinator applies this to both search and by-ID lookup.

**Migration review:** The original Affects list names methods from the former monolithic ViewModel; VoiceDiscoveryCoordinator now owns the HTTP workflow.

## Recorded rationale

The original rationale below is retained for traceability; where a migration review narrows it, the current interpretation and linked successor take precedence.

**Context:** Fish Audio's model list (`GET /model`) and model detail (`GET /model/{id}`) endpoints do not require a valid API Key. Users should be able to browse and preview voices even before entering their key.
**Decision:** Pass `"dummy"` as the Authorization bearer token for search and get-model calls. These endpoints do not require a valid API Key, and this avoids coupling browsing behavior to TTS/credit preflight state.
**Affects:** `SettingsViewModel.EffectiveApiKeyForSearch`, `ExecuteSearchAsync()`, `SubmitVoiceIdAsync()`.
