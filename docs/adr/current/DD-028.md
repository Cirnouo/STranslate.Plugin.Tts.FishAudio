# DD-028: GitHub Actions publishes tagged releases from the matching changelog section

**Status:** Current.

**Recorded:** 2026-05-07.

**Amended or extended by:** [DD-043](../current/DD-043.md).

**Current interpretation:** Tag releases build and test the Windows package and publish only the matching version section of CHANGELOG.md. Separate pull-request/main validation was added with SDK 1.0.15; it does not publish releases.

**Migration review:** The original record describes tagged publication. Current validation additionally runs for pull requests and pushes to main; see the build spec.

## Recorded rationale

The original rationale below is retained for traceability; where a migration review narrows it, the current interpretation and linked successor take precedence.

**Context:** The repository needs a repeatable release path that builds and tests the Windows package, then publishes a GitHub Release with notes limited to the version being shipped.
**Decision:** Trigger the release workflow on pushed `v*` tags, run `build.ps1 -Release -Clean -Test`, extract only the matching `CHANGELOG.md` section into a temporary release notes file, publish the root `.spkg` with `softprops/action-gh-release`, and use the tag name itself as the GitHub Release title. The command was updated by [DD-043](../current/DD-043.md) when the build CLI adopted a single Release switch.
**Affects:** `.github/workflows/dotnet.yml`, `CHANGELOG.md`, `CLAUDE.md`, `AGENTS.md`.

## Implementation basis

Reviewed against the current repository baseline (v1.1.2 behavior, SDK 1.0.15); source inspection is not a claim of live API or audio-device verification.
