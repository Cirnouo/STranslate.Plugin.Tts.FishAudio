# DD-058: Separate slider interaction steps from precise numeric editing

**Status:** Current.

**Recorded:** 2026-10-21.

**Amends:** The stored step quantization in [DD-031](DD-031.md) and [DD-057](DD-057.md). Their parameter bounds, defaults and positive top_p compatibility floor remain active.

## Context

The four slider settings already display decimal values, but their labels cannot be edited. Requiring pointer movement for a precise value is awkward, and snapping settings to slider ticks during loading would silently discard a manually entered value such as `0.82`. A separate form or permanently visible input would change the established settings-card layout.

## Decision

Use one reusable inline numeric editor beside each configuration slider. Its resting state is a clickable numeric text label. Editing replaces that label with an input in the same fixed bounds, initialized from the displayed value. Keep measurement units outside the editor. All four values use two decimal places and a common `0.01` drag, wheel and direct-entry precision. The amendment below replaces the original `0.05`/`0.1` slider ticks and one-decimal Volume display.

Edit a draft string rather than the bound setting. Commit a valid finite value on focus loss or Enter and cancel on Escape; invalid, empty or out-of-range drafts restore the current committed value. Parsing and formatting follow the same explicit culture, with an invariant decimal-point fallback. [DD-059](DD-059.md) narrows accepted draft syntax and paste behavior without changing these numeric bounds. Editing must not change unrelated preferences or issue an API call.

Normalize valid stored settings to their displayed decimal precision with midpoint-away-from-zero rounding, rather than to slider ticks. Consequently, manually entered `0.82` and `0.83` remain unchanged after saving and reopening. Keep defaults for malformed stored values and retain the shared top_p request guard independently of UI/storage precision. Do not advance the settings schema for a precision-preserving representation change.

## Consequences and verification

Slider dragging remains convenient, while direct entry supplies the precision already promised by the displayed value. Fixed display/editor geometry and a separate unit avoid moving neighboring controls. Cover real compiled controls at narrow and normal widths, culture-sensitive parsing, draft isolation, focus transitions, invalid values, keyboard actions, slider synchronization and storage/reload. Distinguish these deterministic tests from installed-host pointer and focus observations.

The host theme normally adds a focused nonempty TextBox delete button. In this compact editor it takes space from the number, so disable that adornment locally rather than widening the editor or changing the application's TextBox style. Check the resolved text viewport against formatted glyphs, including `-10.00` and `-10,00`; equal outer bounds alone do not establish readable input.

See the [settings contract](../../specs/settings-and-model-policy.md), [normalizer](../../../STranslate.Plugin.Tts.FishAudio/Configuration/SettingsNormalizer.cs) and [inline-editor tests](../../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/InlineNumericEditorSuite.cs).

Wheel adjustment uses the same `0.01` precision as slider dragging and direct entry. After the hover gate below qualifies the target, clamp and persist through the existing bound value; consume that gesture to prevent page movement. An active text editor and separate unit do not handle this route, preserving ordinary scrolling during typing. Accumulate incomplete wheel notches only within the qualified current target's hover session.

**Hover gate amendment (2026-10-23, threshold amended 2026-10-24):** Require 350 ms of continuous pointer presence on the slider or resting numeric label before it consumes wheel input. Users scrolling past a configuration should retain ordinary page movement until that intent signal. Use monotonic elapsed time, discard prequalification deltas, and rearm after leave/reentry, editing, unload or template replacement. Descendant motion inside one slider does not rearm it. Keep the existing precision, bounds, qualified bubble and manual drag/direct-edit behavior; no additional setting is needed.

**Amendment (2026-10-23):** Extend the resting numeric label's wheel interaction to its paired slider, including the track and thumb. Use `0.01` for all four controls and all three input methods, including Volume normalization and its two-decimal display. The earlier coarse drag/Volume increments were client choices, not upstream step constraints; see the [numeric parameter schema](../../references/tts-fields.md#numeric-parameter-granularity). Reuse the native slider value bubble during wheel adjustment, close it after the idle interval or leave/unload, and preserve real drag ownership and theme geometry. Share bounded precision arithmetic so targets cannot diverge. A changed slider value cancels an older text draft under the existing external-value rule; an unchanged bound does not discard a draft. Existing parameter ranges, the positive top_p floor and schema 2 remain unchanged.

**Zero representation:** Decimal arithmetic and floating-point values can retain a negative sign on zero. Canonicalize a result that rounds to zero before Volume's equality/save boundary and at supported numeric producers, rather than hiding a minus sign in display text. Keep the native slider's local near-zero value and TwoWay source consistent without a second value-change/save cycle. Preserve range coercion, valid negative hundredths and read-only settings rules. This supplies `0.00` in both the label and native value bubble without introducing a separate tooltip format.

**Point-click amendment (2026-10-24):** Enable the native Slider move-to-point option on all four settings controls. A track click selects the clicked position immediately using the existing hundredth ticks, bounds and binding/save path. Retain native drag and tooltip ownership. The shared hover threshold for slider and resting numeric text is now 350 ms; no wheel input qualifies before that exact monotonic boundary. Verify compiled routed track presses and persisted values separately from installed-host pointer acceptance.

**Compact numeric geometry amendment (2026-10-24):** Use 52 × 32 DIP for both the resting button and native TextBox, right-aligned text, 2-DIP horizontal padding and fixed 1-DIP borders. Reserve a transparent resting border and change only its brush on focus so the number keeps its position. The custom button presenter consumes the control's padding and alignment instead of hardcoding a centered label. Put Speed's × and Volume's dB in a content-sized adjacent unit column with a 4-DIP gap; collapse that column for Temperature and top_p. Keep the outer settings-card rows and 180-DIP sliders unchanged. Compiled theme-state fixtures cover all seven UI locales plus comma-decimal fallback, both themes, narrow/normal widths and 100/125/150% actual WPF root DPI. Check the resolved text viewport, actual numeric right edges and leading/trailing caret positions for `-10.00`/`-10,00`; this does not establish installed-host pointer or focus behavior.
