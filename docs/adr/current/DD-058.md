# DD-058: Separate slider interaction steps from precise numeric editing

**Status:** Current.

**Recorded:** 2026-10-21.

**Amends:** The stored step quantization in [DD-031](DD-031.md) and [DD-057](DD-057.md). Their parameter bounds, defaults and positive top_p compatibility floor remain active.

## Context

The four slider settings already display decimal values, but their labels cannot be edited. Requiring pointer movement for a precise value is awkward, and snapping settings to slider ticks during loading would silently discard a manually entered value such as `0.82`. A separate form or permanently visible input would change the established settings-card layout.

## Decision

Use one reusable inline numeric editor beside each configuration slider. Its resting state is a clickable numeric text label. Editing replaces that label with an input in the same fixed bounds, initialized from the displayed value. Keep measurement units outside the editor. Speed, Temperature and top_p use two decimal places; Volume uses one. Preserve the existing slider interaction steps of `0.05` and `0.1` respectively.

Edit a draft string rather than the bound setting. Commit a valid finite value on focus loss or Enter and cancel on Escape; invalid, empty or out-of-range drafts restore the current committed value. Parsing and formatting follow the same explicit culture, with an invariant decimal-point fallback. [DD-059](DD-059.md) narrows accepted draft syntax and paste behavior without changing these numeric bounds. Editing must not change unrelated preferences or issue an API call.

Normalize valid stored settings to their displayed decimal precision with midpoint-away-from-zero rounding, rather than to slider ticks. Consequently, manually entered `0.82` and `0.83` remain unchanged after saving and reopening. Keep defaults for malformed stored values and retain the shared top_p request guard independently of UI/storage precision. Do not advance the settings schema for a precision-preserving representation change.

## Consequences and verification

Slider dragging remains convenient, while direct entry supplies the precision already promised by the displayed value. Fixed display/editor geometry and a separate unit avoid moving neighboring controls. Cover real compiled controls at narrow and normal widths, culture-sensitive parsing, draft isolation, focus transitions, invalid values, keyboard actions, slider synchronization and storage/reload. Distinguish these deterministic tests from installed-host pointer and focus observations.

The host theme normally adds a focused nonempty TextBox delete button. In this compact editor it takes space from the number, so disable that adornment locally rather than widening the editor or changing the application's TextBox style. Check the resolved text viewport against formatted glyphs, including `-10.0`; equal outer bounds alone do not establish readable input.
