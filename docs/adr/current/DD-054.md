# DD-054: Persist favorite IDs separately and share browsing caches

**Status:** Current.

**Amended by:** [DD-062](DD-062.md) scopes metadata to configured credentials and invalidates retained metadata on key changes. ID-only persistence, cache bounds/TTL and cover ownership remain unchanged.

**Recorded:** 2026-10-20.

## Context

Search provides temporary voice cards, while By-ID confirmation previously applied its result immediately. Users need persistent bookmarks and a chance to inspect an ID before replacing their selected voice. Bookmarks, remote voice metadata and local cover images have distinct lifetimes. No provider favorites API is established by the repository references.

## Decision

Add Favorite Voices to the right of Search and By ID, with a matching tab icon; Simplified Chinese uses “收藏的声音”. All three browsing panels share Preview, a vector star and a selection action; [DD-056](DD-056.md) unifies its Tick/Cross state. The already-selected voice also has a favorite star, synchronized by Voice ID with the three panels. Bookmarking remains independent of selection: unbookmarking does not clear selection, and clearing/replacing selection does not remove a bookmark. By-ID confirmation only publishes one independent result; explicit Apply/Clear actions change the selected Voice ID and CachedVoice. Edited inputs, replacement queries and disposal invalidate former lookup/card identities.

Persist a plain UTF-8 JSON array of ordered canonical Voice IDs at `Path.Combine(context.MetaData.PluginSettingsDirectoryPath, "favorite-voices.json")`. The SDK's settings directory is documented for persistent plugin settings/data; its cache directory is disposable and its install directory is source code. Never guess a machine path or use an install/cache fallback when the host data directory is unavailable. Keep bookmarks plugin-wide across profiles sharing that directory. Do not add a Settings field or advance schema 2.

Bound reads to 32 KiB plus one detection byte. Reject malformed/non-array/non-string/oversized files and files containing more than 300 distinct valid IDs; preserve their bytes and show an unavailable state. Ignore noncanonical ID strings, deduplicate valid IDs in first-seen order and retain the existing absolute lowercase-hex validator. A missing file is an available empty list. Adding at the 300-ID cap rejects with a localized hint without eviction. A 301-ID file is an error, not a silently truncated collection.

Serialize explicit add/remove intent with a per-canonical-path in-process gate and re-read the latest file before each mutation. Flush a same-directory temporary file and atomically replace/move it. Publish UI state only after success. A failed write preserves both the previous file and displayed IDs/stars. Reuse SettingsStore's persistence authorization gate to linearize active write leases with retirement; it does not mutate Settings or hold the short snapshot lock. Lock order is VM persistence, SettingsStore persistence authorization, store instance, path. No UI callbacks/notifications occur under these gates. Reload on Favorites entry and mutation; no file watcher or cross-process writer contract is introduced.

Own one in-memory VoiceMetadataCache per plugin Main instance and reuse it across initialization generations. Search, By ID, visible favorite-page misses and preview detail refresh use/populate this cache. Cache entries are detached immutable values, capped at 300 with LRU eviction and an explicit fifteen-minute monotonic client TTL. Bound title/description/author/remote-cover-source/sample-URL strings to 512/8192/256/4096/8192 UTF-16 units. The TTL does not claim provider validity, and sample expiry/403/404 always bypasses the metadata cache before replacing its entry. Add no disk metadata or audio-byte cache.

Only active visible favorite pages fetch missing voice metadata. Publish ID placeholders first, with loading/unavailable feedback, removable stars and Apply disabled until valid metadata exists. Cache hits fill immediately without a detail GET. A not-found or failed lookup cannot delete a bookmark. Page replacement, tab exit, removal and disposal cancel owned loads and reject stale originating-card completions. Keep six-item local pagination, exact counts and immediate final-page clamping after a successful removal.

Search and Favorites each have a compact count/chevron ToggleButton and collapsible body. Start expanded, retain independent view-local state across tab switches/list updates, and support keyboard and automation toggling. Use host theme brushes, accessible names and all seven UI locales. Whole PCM bitrate visibility is described by the settings specification and DD-053; DD-055 removes the former proxy controls.

Search, By-ID and Favorites resolve canonical remote cover sources through the same existing CoverImageCacheDisplayManager and `cover_images/<VoiceId>.jpg` namespace under PluginCacheDirectoryPath. A cached image is reused across panels. Clearing covers removes no bookmark IDs or shared metadata; a later search, By-ID lookup or favorite-page resolution can download through that same resolver again. Never copy a cover into bookmark storage or add another image-cache folder.

Preserve both shared Voice ID presentation state and originating card object identity in preview ownership. Removing a favorite card or replacing a By-ID result invalidates its preview even if another matching ID remains. Refresh the shared metadata cache and matching cards without applying a browsed voice. Retain the existing URL policy, one-refresh budget, host downloader, memory bound and playback owner.

## Consequences and limits

IDs survive plugin restart independently of the in-memory cache. On a cold restart, visible favorites may require public detail requests; unavailable voices remain removable placeholders. Metadata-cache hits avoid detail calls, while every preview still downloads its sample for that play. There is no provider account synchronization or reusable audio cache. Offline storage, cache, cancellation, cover reuse and compiled-view tests establish software behavior; physical output and host acceptance are separate evidence.

This amends By-ID selection behavior and broadens card membership in DD-040, DD-047 and DD-049. Their download, credential and playback ownership constraints remain active.
