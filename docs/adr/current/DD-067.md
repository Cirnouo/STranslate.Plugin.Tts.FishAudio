# DD-067: Separate native geometry dimensions from behavior ownership

Status: accepted for the current executable regression runner.

## Context

The card layout matrix repeated the same description, header, date and loading transitions in every localized geometry context. Shared native layout work made late full-run failures expensive to recover. Merely counting layout calls cannot establish a speedup: each fresh view and native source also costs time, and warmed full-group execution differs from an isolated sample.

## Decision

Retain all original static locale/theme/DPI/width/mode contexts, their stable IDs and first-use order. Move repeated dynamic transitions into independently selected behavior groups only where their dependencies justify reducing dimensions. A UI resource dictionary does not set inherited text Language or provider payloads; static localized resources/accessibility remain complete, dynamic script payloads stay intact, and explicit font/culture/flow changes retain their own owner. Keep theme/DPI/width dimensions for description and header rendering. The voice specification owns the coverage mapping.

Each fresh fixture still owns a selected/active pair, its native source and complete cleanup. Keep every same-object mutation/restoration and lifecycle chain continuous. Preserve actual native glyph/raster, short-author readability, finite ellipsis, historical sampling phases, input timing and loading/selection assertions. Do not substitute geometry-only checks for behavior or enlarge functional deadlines.

Expose existing independently dispatched native matrix callbacks as lazy metadata descriptors in their original catalog slots. Retain legacy selector delegates, proof arguments and traversal semantics, including numeric-bottom's collect-then-assert wrapper. Former aggregate IDs remain explicit selection/recovery aliases as established by [DD-065](DD-065.md); they are not duplicate default cases. Process ownership and protection remain governed by [DD-066](DD-066.md).

Use safe phase measurements to distinguish fixture construction, resources/source setup, static assertions, each dynamic chain, layout substages and cleanup. Preserve the original statements/readiness and remove temporary profiling hooks afterward. Compare complete original and optimized native groups under the same process boundary and environment, and repeat representative hotspots. Layout counts describe work removed; only measured commands establish elapsed-time changes.

## Consequences

Local selection and failure recovery can address independent native owners without replaying an entire aggregate. Static coverage remains broad while dynamic work follows its actual risk dimensions. More fresh fixtures and report records can offset savings, so measured results and remaining bottlenecks must be reported separately from coverage claims. Complete PR/main CI remains mandatory for every new validation commit.

The [voice contract](../../specs/voice-browsing-and-preview.md#creation-dates-and-card-rows), [build specification](../../specs/build-and-release.md) and [verification policy](../../policies/verification.md) own current behavior and contributor choices.
