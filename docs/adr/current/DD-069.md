# DD-069: Validate ordinary commits from their actual index snapshot

Status: accepted for the staged-tree bootstrap gate. This amends DD-065's local pre-push requirement; its focused diagnostic selectors and complete PR/main CI remain available.

## Context

Working-directory verification can accidentally include an unstaged repair or untracked source that is absent from the proposed commit. A repository script alone does not install a Git hook, and linked worktrees must not silently borrow another checkout's hook configuration or source files. Message hooks can also change the index after pre-commit finishes.

## Decision

Install a worktree-private pre-commit entry and check Git's actual entry and exit-code propagation. Preserve existing pre-commit behavior before freezing the index. Respect GIT_INDEX_FILE and materialize the resulting tree from raw Git blobs into an independent directory without changing the user's files or index.

Build, inspect the current Release package and run the complete legacy regression catalog from that snapshot. Bind repository input lookup and source identity to an explicit snapshot context. Verify the final durable report against the exact current catalog and build identity without invoking scenarios again. A missing or partial report never establishes full coverage.

After successful verification, recheck the original tree and index bytes. Retain prepare/message hook behavior and install a final commit-msg guard that checks the completed gate receipt after the prior message hook. This last guard performs no repeated tests and rejects an index change before Git creates the commit.

Use the explicit mode `bootstrap/full/legacy-runner` until framework discovery, coverage baselines and impact analysis are separately implemented and verified. Keep PR/main full legacy validation during this stage. No test gate runs at pre-push, and no migration commit is exempt from the installed pre-commit.

## Consequences

The first migration commit can be tested without trusting a future selector or baseline. Full local runs cost more than eventual affected selection, but every successful commit is tied to its actual staged sources. Snapshots, logs and raw reports remain private run evidence; none is a formal main coverage baseline. The process watchdog, native first-use order, functional deadlines and release publication boundary remain unchanged.

The [test-system specification](../../specs/test-system.md) owns the current protocol, and the [verification policy](../../policies/verification.md) owns contributor obligations.
