# DD-051: Prepare a lazy readable prefix and gate the tail on output start

**Status:** Current.

**Recorded:** 2026-10-20.

**Related:** [DD-050](DD-050.md), [DD-032](DD-032.md).

## Context

Whole-input normalization defeats duplex startup. Splitting only at sentences can still scan an arbitrarily long first sentence. Blind flushes inside markup can alter interpretation, while network audio does not establish output success. The protocol documents no flush-complete acknowledgement.

## Decision

Visit at most 100 Unicode scalars in the first window and 300 in later windows, preserving surrogate pairs and original text order. Prefer safe sentence, newline, whitespace and then scalar boundaries inside that window. Preserve bounded state for recognized paired tags, phoneme spans, bracket directions and angle tokens; defer flush across open spans. Unknown/oversized tokens pass through unchanged with bounded recognition storage. Do not claim full markup parsing or grapheme preservation.

After the first safe readable prefix and flush, leave remaining input unread until local output Play succeeds. An open atomic span can span multiple bounded events before the first safe flush. Short/incomplete final input stops directly. Receive, decode and the output clock remain independent; terminal cancellation releases the tail wait.

## Consequences and implementation basis

For ordinary text, an arbitrarily large untouched tail cannot change first-prefix preparation. This guarantees local bounded work, not provider first-word latency. Unknown grammar, unclosed markup and initial generated silence remain explicit limitations. Guarded-suffix tests establish laziness; concatenation checks establish exact preservation.
