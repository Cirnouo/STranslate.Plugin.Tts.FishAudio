# DD-055: Use the system proxy without plugin network settings

**Status:** Current.

**Recorded:** 2026-10-20.

**Amends:** The editable native-proxy portion of [DD-053](DD-053.md). Its format migration and model policy remain active.

## Context

Formal TTS uses a native WebSocket while account queries, voice discovery and preview use the host HTTP service. Exposing another set of proxy modes and credentials complicates setup and creates an independent configuration users must understand. The required product behavior is to use the system proxy without a plugin proxy interface.

## Decision

Set the native ClientWebSocket proxy to `HttpClient.DefaultProxy`. Provide no direct/custom mode, address, credentials, network group or proxy setting in the plugin. Keep REST and preview on the host HTTP service; this does not claim that host-specific HTTP overrides are automatically copied into a native socket.

Remove the former mode/address fields from current Settings, ViewModel and immutable synthesis requests. Continue using schema 2. Treat old schema-2 proxy fields as obsolete: ignore their values, including malformed or credential-bearing values, and remove them on an ordinary canonical save. They cannot select direct/custom routing or block synthesis. Preserve future/duplicate-schema read-only protection and every unrelated preference.

Document system-network troubleshooting rather than instructions for removed controls. Historical acceptance records may retain the old interface only when explicitly marked superseded.

## Consequences and implementation basis

Users configure their system networking once. The plugin holds no custom proxy address or credential setting. Native socket routing and host HTTP still have different owners. No provider request shape, synthesis model, audio format or retry policy changes with this decision.
