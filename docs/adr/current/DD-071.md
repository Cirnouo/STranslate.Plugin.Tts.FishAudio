# DD-071: Admit isolated NUnit coverage without a complete-baseline claim

Status: accepted for the current bounded compatibility implementation.

Recorded: 2026-10-28 (Asia/Shanghai).

Amends: [DD-070](DD-070.md)'s temporary exclusion of coverage experiments from the unified driver. Its complete hybrid validation and native ownership obligations remain active.

## Context

The fixed official MTP integration collected named test boundaries, but its actual JSON/XML exports did not expose usable case relationships. Native per-test export is therefore unavailable for the tested route. Modern dotCover can instead cover one framework-selected leaf and its necessary lifecycle/owned child in a separate session. File count, a nonzero total percentage or CLI success alone cannot establish that relationship or collection completeness.

## Decision

Retain NUnit/VSTest as the unified daily platform and use pinned modern dotCover isolated sessions for bounded coverage compatibility. The framework owns discovery, execution, lifecycle, assertions and results. Each session resolves one canonical leaf from its actual discovery, checks the exact terminal result set and binds source tree, build, matching DLL/PDB identities, commands, original pipes and process observations. Independent session output and source/binary rechecks prevent reuse of another case's artifacts.

Preserve raw collection before admission. Review the observed profiler processes, managed cover/export diagnostics and all four console streams against versioned narrow rules. The current console rule is limited to the observed Windows x64 CP936 bytes. Unknown warnings, errors, output encodings, incomplete children, missing results, stale artifacts and failed export remain rejected. A legitimate repository-resource case may have empty product coverage only with its explicit dependency record. Tests, collection, admission and future baseline publication retain distinct outcomes.

Expose explicit compatibility scenarios and coverage discovery through the unified PowerShell entry. Actual-index preparation materializes raw Git objects from the staged tree, respects alternate/split indexes, reads its helper from that same tree and preserves the original index bytes. Ordinary full framework execution and the real hybrid commit gate remain unprofiled; these diagnostics do not create a commit receipt or skip a new commit's gate.

## Consequences

The representative sync, async, parameter-row, A/B, direct STA, supervised-child and repository-resource sessions establish bounded isolated attribution. The public actual-index path has separately passed one synchronous case. Report observations still have unresolved source mappings and make no complete-baseline claim. Group aggregates must not be copied to independent cases or subtracted to invent attribution.

Existing native cold prefixes, same-owner chains, action/startup/cleanup budgets and external watchdog remain independently required in the legacy catalog. Their migration needs a framework lifecycle/control bridge and verified attribution or dependency closure. Complete catalog conversion, main baseline publication, Roslyn impact selection and CI switching remain later stages. Measurements guide scheduling and do not add a performance threshold.
