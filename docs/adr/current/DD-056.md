# DD-056: Share selection state across every voice card

**Status:** Current.

**Recorded:** 2026-10-20.

**Amends:** The Apply presentation in [DD-054](DD-054.md); its lookup and bookmark ownership remain active.

## Context

The same Voice ID can appear in the selected card, Search, By ID and Favorite Voices. Showing a clear action in one location and an apply action in another for that same ID makes the selection state ambiguous. Bookmarking and selection also represent different user intent and must remain independent.

## Decision

Use the current Voice ID as the single source of selection state. An unapplied card shows a Tick action; every matching applied card shows a Cross action. Applying a different voice updates all cards; Cross from any matching card clears the selection. Keep the selected card's clear action consistent with these controls. Use the same borderless icon presentation with localized tooltips/accessibility names and visible keyboard focus.

Valid metadata is required to apply an unselected card. Clearing the already-selected matching ID remains possible without metadata. Querying an ID does not select it. Removing a favorite never clears selection, and clearing/replacing selection never removes a favorite ID. The favorite star on the selected card uses the same durable ID store and state as the browsing cards.

Keep lookup, selection and paging visually distinct: the By-ID query uses the same magnifier as Search; Search/Favorites paging uses bare left/right chevrons with localized previous/next action names. Inline paste actions occupy reserved space inside their input's right edge, so editable text and the caret cannot overlap them.

## Consequences and implementation basis

Users can identify and cancel the applied voice from any matching card without learning panel-specific state. Icon-only actions retain keyboard and assistive-technology support. Shared ID state does not merge card object identity: preview ownership and stale-response rules remain unchanged.
