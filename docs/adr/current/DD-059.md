# DD-059: Validate complete input drafts before accepting edits

**Status:** Current.

**Recorded:** 2026-10-23.

**Amends:** [DD-058](DD-058.md).

## Context

An unrestricted numeric draft can display letters, excess precision or an arbitrarily long string even when committing eventually rejects it. A TextBox length limit alone can truncate pasted text into a different valid value. Voice IDs likewise have a narrow canonical alphabet; silently extracting, trimming or lowercasing a clipboard value would disguise a malformed identifier.

## Decision

Validate the entire proposed draft, including the current selection replacement, before accepting text composition or paste. Numeric drafts allow ASCII digits, one decimal separator and a leading minus only when the parameter permits negative values. Accept the display culture's decimal separator and the invariant point, but never two separators. Limit integer and fractional digits using the parameter bounds and displayed precision: Speed, Temperature and top_p have four-character inputs with two decimal places; Volume has six characters with two decimal places, including a possible minus (`-10.00`), under the uniform precision amendment in DD-058. Incomplete drafts remain editable; focus loss or Enter still requires a finite in-range number. Escape or an invalid commit restores the committed setting. Recheck the grammar at commit so programmatic text changes cannot bypass it.

Voice ID drafts allow only zero to 32 lowercase hexadecimal characters; lookup still requires exactly 32. Apply the same draft rule to typing, native paste and the embedded paste action. Reject an invalid clipboard payload as a whole, preserving the existing draft and lookup result. Do not trim, extract, normalize case or truncate it. These are editing rules, not a replacement for validation at storage and request boundaries.

Hide native clear adornments locally for plugin inputs. Keep text and caret space separate from embedded paste actions and verify the resolved native content viewport in both resting and focused states. Do not change global host styles or shrink the resting viewport to conceal a focus regression.

## Consequences and verification

The controls reject malformed edits immediately while preserving legitimate partial entry and precise off-tick values. Tests cover selected replacement, whole-payload paste rejection, malformed separators, excess digits, Unicode digits, exponent notation, incomplete drafts and independent commit validation. Native theme geometry requires compiled-control checks and installed-host acceptance; equal outer control dimensions alone are insufficient.

See the [settings contract](../../specs/settings-and-model-policy.md), [voice browsing contract](../../specs/voice-browsing-and-preview.md) and [verification policy](../../policies/verification.md).

**Compact numeric geometry amendment (2026-10-24):** The numeric fields in DD-058 now use 52 × 32 DIP bounds, fixed 1-DIP borders and 2-DIP horizontal padding. Preserve the existing whole-draft grammar and isolated commit behavior within that smaller field. Keep units outside editable text, with × for Speed, dB for Volume and no reserved unit column for the other two settings. Verify the actual native 46-DIP text viewport and caret positions at both ends of signed six-character drafts, including dot/comma decimal forms, under both themes and 100/125/150% DPI. A theme-state fixture forces the native focused/nonempty clear-button setter while the local override keeps it collapsed; it is separate from installed-host focus acceptance.
