# DD-016: Voice ID format validation before API call

**Status:** Current.

**Recorded:** 2026-05-06.

**Supersedes or replaces part of:** [DD-002](../history/DD-002.md).

**Amended or extended by:** [DD-046](../current/DD-046.md).

**Current interpretation:** Voice-by-ID lookup checks the existing 32-lowercase-hex Voice ID format before HTTP. SettingsValidation owns this check; API Keys now have a separate validator under [DD-046](../current/DD-046.md).

**Migration review:** The original shared-regex claim is superseded by [DD-046](../current/DD-046.md). API Key and Voice ID validators must not be merged again.

## Recorded rationale

The original rationale below is retained for traceability; where a migration review narrows it, the current interpretation and linked successor take precedence.

**Context:** Voice IDs follow the same 32-hex format as API Keys. Calling `GET /model/{id}` with a malformed ID always returns 404, wasting a network round-trip.
**Decision:** Check `Settings.IsValidVoiceIdFormat(id)` before calling `GetModelAsync`. On format failure, show localized "Voice ID format incorrect" error inline (`VoiceIdError`) and skip the API call. The regex is shared with `IsValidApiKeyFormat` — both use `HexId32Regex`.
**Affects:** `SettingsViewModel.SubmitVoiceIdAsync()`, `Settings.IsValidVoiceIdFormat()`.
