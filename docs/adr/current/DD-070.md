# DD-070: Discover NUnit cases while retaining complete legacy validation

Status: accepted for the current framework foundation and full hybrid gate.

Recorded: 2026-10-27 UTC.

Amends: [DD-069](DD-069.md)'s execution mode and final evidence receipt, and [DD-065](DD-065.md)'s test-registration boundary. Their staged-source, conservative legacy selection and complete-new-commit obligations remain active.

## Context

Adding ordinary tests through a central catalog makes registration part of every test change. A framework can own discovery, fixture lifecycle, assertions and terminal results while the remaining legacy scenarios continue to preserve their existing native source ownership, cancellation, ordering and supervision. Discovery alone cannot establish that those responsibilities migrated.

A staged snapshot and successful process exit also leave an evidence-admission gap: the reported cases may differ from the requested cases, or a final message hook may change admitted evidence after pre-commit. The outer gate needs independent reads of framework-authored artifacts bound to the same staged source and built binaries.

The bounded modern coverage experiment used dotCover CLI 2026.2.3.1 with Microsoft.Testing.Platform 2.4.1 and JetBrains.dotCover.Framework 1.0.2. The actual test host successfully collected named test-boundary blocks, while the fixed JSON/XML exports had empty test indices and no machine-readable case relations. Collection success and the separate controller warning did not admit an imported product-method/case matrix. This observation is limited to that candidate and export path.

## Decision

Use NUnit 4.6.1, NUnit3TestAdapter 6.3.1 and Microsoft.NET.Test.Sdk 18.11.0 through VSTest for ordinary framework execution. Keep the exact .NET SDK and package resolution pinned in the repository. New ordinary cases use NUnit attributes without central registration. Parameter rows need stable explicit names; an optional unique `FishAudioCaseId` provides identity independent of a display name. Runtime numeric discovery IDs are metadata.

Retain the complete legacy catalog as an independent validation obligation. A migration must account for the old assertions, same-owner chains, cleanup, process-global/native state and deadlines before retiring that responsibility. Direct shared-STA compatibility observations do not establish replacement of the legacy root-action protocol or external watchdog. The executable entry point keeps internal child/verifier dispatch first and retains explicit legacy commands; VSTest owns framework execution.

Provide metadata-only discovery and exact/full framework execution through `tools/Test.ps1`. Use normal Release builds, locked restore, fresh results directories, strict canonical-ID selection and exact NUnit XML/TRX result verification. Keep raw phase outputs and source/binary/artifact identities. Assign the waiting launch shim to its Windows Job before starting real targets, and retain ownership through descendant exit and both drains. Whole builds and multi-action test assemblies receive no new 120-second performance deadline; the existing root-action contract remains authoritative.

Upgrade the installed gate to protocol 2 and mode `bootstrap/full/hybrid`. Every commit validates its exact staged snapshot with the complete legacy catalog and both complete discovered NUnit catalogs. The outer gate independently reparses raw discovery and verifies terminal XML/TRX with the snapshot-built metadata tool. Its final receipt guard checks admitted artifact hashes as well as the original tree/index identity after the prior commit-msg hook. PR/main validation retains all legacy partitions and adds a complete framework obligation with independent evidence admission. No affected selection or previous-commit reuse is introduced.

The initial foundation kept coverage experiments outside the unified driver pending final report and warning classification. [DD-071](DD-071.md) amends that boundary with explicit bounded compatibility modes and isolated-case admission; ordinary full execution remains unprofiled. A portable-PDB identity helper, a bounded workspace probe or passing compatibility examples do not establish a complete product coverage baseline or formal test-impact analysis.

## Consequences

Ordinary framework cases can be added without editing a central registry, and complete discovered sets become reviewable machine evidence. The transition temporarily keeps legacy and framework execution as separate obligations. Counts come from their current catalogs and discovery rather than permanent constants. Installed-hook boundary controls, actual NUnit execution, coverage collection and baseline publication retain distinct evidence meanings.

An older worktree-private hook installation must be reinstalled and checked before committing under protocol 2. Successful current runs cover only their source/binary identities and admitted outcomes. Formal baseline publication and impact-based reuse need later decisions and verified admission rules.
