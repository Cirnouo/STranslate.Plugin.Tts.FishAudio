# DD-050: Formal TTS owns one native streaming session through device drain

**Status:** Current.

**Recorded:** 2026-10-20.

**Amends:** [DD-009](DD-009.md), [DD-039](DD-039.md), [DD-041](DD-041.md). Their settings, credit and architectural constraints remain active; this replaces formal transport/output ownership and the old continue-through-reinitialization behavior.

## Context

The previous formal route waited for a complete HTTP MP3 response and invoked host byte-array playback. The native ordinary WebSocket supports audio before all text is sent, but that alone does not provide bounded output, cancellation or drain. A preview's whole-sample download is appropriate for a small existing asset and unsuitable for streaming synthesis. The provider silently selects a paid model for absent/unknown values.

## Decision

Use one single-use ClientWebSocket session at exact native `/v1/tts/live`, binary MessagePack and exact captured model. Send empty-text start, bounded ordered text/flush and stop; receive concurrently through successful finish. Check exact model-policy membership before connection, every send and in the watchdog. Do not retry synthesis, substitute a model, fall back to HTTP/SSE or reuse an ordinary connection.

Main freezes request values before its first await and links caller cancellation with initialization lifetime. A successor cancels its predecessor and waits for completion including cleanup; every successor includes predecessor retirement in its own completion. Reinitialization/disposal cancels old playback. Only the captured ViewModel owns activity and post-success silent credit refresh.

Bound messages to eight MiB separately from a 32 × 16 KiB encoded queue. Pressure may delay control-message observation; keep one receiver and independent cancellation. Use 15-second connect, 120-second first playable PCM, 30 active seconds without audio after playback starts, and 10-second device-progress budgets. Exclude the union of actual encoded/PCM pressure waits from active idle. Disable active keepalive timeout to avoid pressure-induced false PING/PONG failure.

Provider finish closes encoded input; success also requires playable PCM, successful output start, all workers observed and device drain. Preserve the first worker failure and cancel siblings. Log fixed messages, safe exception types and qualified timing stages, never raw transport/provider contents.

## Consequences and implementation basis

Long text can start output without preparing its whole tail. Session, decoder and output ownership become plugin responsibilities. Exact client model checks cannot prevent future server-side model migration. Offline tests and provider probe timings do not establish production audible latency.
