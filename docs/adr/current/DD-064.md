# DD-064: Map main governance to actual Fish Audio validation contexts

**Status:** Current.

**Recorded:** 2026-10-23.

## Context

The user requests the same main protection and ruleset as debugging-cdp-targets. Its observed active `main governance` ruleset has no bypass actors, strict required checks, PRs with zero required approvals and squash-only merges, linear history, deletion/force-push prevention and a CodeQL high-security gate. Its legacy branch-protection endpoint returns 404 because effective rules are provided by the ruleset.

The reference's eleven check contexts include Node/JavaScript, macOS and Real Chrome scenarios that this Windows/WPF plugin does not implement. Requiring their names would block every Fish PR without validating the plugin. Repository merge defaults are separate from branch rules.

## Decision

Preserve the reference's main-only scope, no administrator bypass, strict checks, zero-approval PR policy, squash/linear history and scanning severity. Match squash-only repository settings with PR-title/blank-body defaults; retain disabled auto-merge and automatic branch deletion.

Map required contexts to actual successful Fish Windows build/test/package, commit-message, NuGet supply-chain and C#/Actions CodeQL checks. Enable workflows and inspect their first successful PR/main runs and scan results before requiring their exact emitted names and GitHub Actions integration. Do not claim the mapping is byte-identical to the source's product-specific contexts.

Before settings writes, preserve private pre-change JSON. Use portable payloads and read back configured/effective rules after applying them. A missing classic protection record is not a reason to add competing legacy protection. Do not create a temporary bypass or require nonexistent checks.

## Consequences

Maintainers receive the same governance boundaries with checks that exercise this product. New required-check names need workflow and ruleset coordination. No-bypass rules make failed/missing checks actionable rather than skippable. The [governance policy](../../policies/repository-governance.md) owns operation and verification rules; successful code/CI and actual remote readback are distinct evidence.
