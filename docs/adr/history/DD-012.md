# DD-012: API Key commit on validation success

**Status:** Historical — superseded.

**Recorded:** 2026-05-06.

**Superseded by:** [DD-030](../current/DD-030.md).

This record preserves the replaced design and its motivation. It is not a current implementation requirement. Classification follows the replacement relationship, not the age of the record.

## Recorded rationale

The original rationale below is retained for traceability; where a migration review narrows it, the current interpretation and linked successor take precedence.

**Context:** `OnPropertyChanged` no longer auto-saves `ApiKey` to `_settings` (see [DD-005](../current/DD-005.md)). But `Main.PlayAudioAsync` checks `Settings.ApiKey` (the `_settings` object) to guard TTS calls. Without committing the key on validation, `_settings.ApiKey` remains empty/stale.
**Decision:** `ConfirmApiKeyAsync` is the sole writer of `_settings.ApiKey`. On valid result → write key and save. On invalid result → write empty and save. `Dispose` does not touch `_settings.ApiKey` (see [DD-003](../history/DD-003.md)).
**Affects:** `SettingsViewModel.ConfirmApiKeyAsync()`.
