# Architecture and initialization lifecycle

Status: current implementation. Baseline and scope are defined by the [spec index](README.md).

`Main` implements `ITtsPlugin`, composes initialization, exposes settings UI and owns formal playback replacement. Configuration owns settings schema, migration, normalization, model policy and the host persistence boundary. FishAudio owns host HTTP request construction/preflight. Streaming owns the native socket, protocol, lazy text and session liveness; Playback owns incremental decoding, bounded PCM and output lifetime. Lifecycle owns initialization publication, Runtime owns clock choice, Caching owns cover-image I/O, and Presentation owns UI workflows behind the stable SettingsViewModel facade. Public binding names and established namespaces are compatibility contracts.

Initialization declares a generation before entering its transition gate. An overtaken attempt rechecks before host load. The old complete state remains available while replacement settings and any needed ViewModel are prepared. Successful publication atomically replaces the complete state; load/construction failure restores the old lease without committing a partial replacement.

SettingsStore serializes host load/save, lease changes and runtime publication. Leased loads clone the host object into a detached runtime Settings instance. Updates work on detached candidates, save through the captured host boundary and publish runtime changes only after successful host I/O. Retired leases cannot save. Host file location, atomic replacement and backup remain host responsibilities.

Startup work includes a bounded online UTC check, conditional selected-voice metadata refresh and a non-blocking credit cycle. Each update checks its initialization identity, revision, lease and relevant Voice ID/API Key before saving or applying UI state. Lazy ViewModel publication retries if a competing settings commit replaces its publication credential. Observable setters, disposal, cancellation callbacks and host I/O run outside the state gate; transition/SettingsStore ordering prevents old writes from overwriting a replacement load.

Internal initialization-work capture preserves the original startup Task and the same per-initialization retirement holder across record copies, without constructing a ViewModel. The holder records the Tasks already returned by retirement's existing `ContinueWith`; it does not await or reschedule production work. An existing ViewModel separately exposes the original pending credit observer Task, or null when no asynchronous observer was started. Invalidation and disposal retain that observation handle. `PendingStartupTask` continues to represent metadata/fetch work and does not include the observer or retirement continuation. Fixtures capture these identities before retirement, release their own held responses, join each original operation and then join retirement cleanup. Joining an observer that enqueues a UI callback does not prove the callback was consumed. Capture of the current published state does not expose a prepared state that failed before publication.

A formal TTS call captures one initialization's Context, detached Settings snapshot, optional ViewModel and lifetime token before its first await. Capture releases the state gate before cloning; snapshot and complete-copy publication share a short settings-object lock. Capture does not acquire the global persistence gate or wait for a blocked replacement host load. Host callbacks do not run under that object lock. The captured initialization token is cancelled when the old state retires.

Main cancels its predecessor and awaits completion including cleanup before starting a successor session. Caller cancellation, supersession, reinitialization retirement and disposal stop the owned session. This replaces the old complete-buffer HTTP rule that a call continued through reinitialization on its captured host AudioPlayer. That dependency remains in the initialization record for compatibility; current formal playback owns local output. A retired call must not unlock, show errors through or refresh credit on a replacement ViewModel. Disposed ViewModels reject late silent refresh work. API Key/credit activity uses counted state with a shared publisher gate and setters outside the gate; overlapping operations release the input lock only after the final active operation ends. See [formal TTS](tts-and-credit.md) and [DD-050](../adr/current/DD-050.md).

The activity-dispatcher regressions keep failure and cancellation as separate native owners with real background publications and a real WPF command listener. Their playback checks are intentionally synchronous so they inspect state before queued UI retirement drains. The separate queued-retirement owner preserves that ordering contract; a property-only fake or extra Dispatcher pump does not replace these observations.
