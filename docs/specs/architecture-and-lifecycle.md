# Architecture and initialization lifecycle

Status: current implementation. Baseline and scope are defined by the [spec index](README.md).

`Main` implements `ITtsPlugin`, composes initialization, exposes settings UI and owns the formal TTS operation. Configuration owns settings schema, migration, normalization, model policy and the host persistence boundary. FishAudio owns request construction/preflight. Lifecycle owns initialization publication, Runtime owns clock choice, Caching owns cover-image I/O, and Presentation owns UI workflows behind the stable SettingsViewModel facade. Public binding names and established namespaces are compatibility contracts.

Initialization declares a generation before entering its transition gate. An overtaken attempt rechecks before host load. The old complete state remains available while replacement settings and any needed ViewModel are prepared. Successful publication atomically replaces the complete state; load/construction failure restores the old lease without committing a partial replacement.

SettingsStore serializes host load/save, lease changes and runtime publication. Leased loads clone the host object into a detached runtime Settings instance. Updates work on detached candidates, save through the captured host boundary and publish runtime changes only after successful host I/O. Retired leases cannot save. Host file location, atomic replacement and backup remain host responsibilities.

Startup work includes a bounded online UTC check, conditional selected-voice metadata refresh and a non-blocking credit cycle. Each update checks its initialization identity, revision, lease and relevant Voice ID/API Key before saving or applying UI state. Lazy ViewModel publication retries if a competing settings commit replaces its publication credential. Observable setters, disposal, cancellation callbacks and host I/O run outside the state gate; transition/SettingsStore ordering prevents old writes from overwriting a replacement load.

A formal TTS call captures Context, Settings, optional ViewModel and host AudioPlayer together. A call spanning reinitialization continues with that original set; it must not unlock, show errors through or refresh credit on a replacement ViewModel. Disposed ViewModels reject late silent refresh work. API Key/credit activity uses counted state with a shared publisher gate and setters outside the gate; overlapping operations release the input lock only after the final active operation ends.
