# Voice browsing, preview and cover cache

Status: current Unreleased implementation. Browsing and preview do not require the user's synthesis API Key. All `/model` and `/model/{id}` requests use the configured API Key unchanged when nonblank, and `dummy` only when it is missing or whitespace. This applies to search, By-ID lookup, favorite-page metadata, selected-voice startup refresh and preview URL recovery. Metadata requests keep their 15-second timeouts and do not use TTS/credit key-format preflight; a rejected configured key is not retried with `dummy`. [DD-062](../adr/current/DD-062.md) supersedes the former always-dummy decision. Only a detail 404 maps to not-found; other request errors remain distinguishable. By-ID lookup validates Voice ID shape and rejects explicit non-TTS types. Missing/blank type remains compatible with old responses.

After an API Key edit is saved successfully, pending metadata and preview work is invalidated while the displayed voices remain. Search and By-ID keep their result objects and metadata; search also retains its applied query, pagination and expansion. Favorites and the selected voice keep their displayed title, description, author, popularity, resolved cover and sample/preview entry, alongside the selected Voice ID, favorite IDs and action states. The saved selected CachedVoice snapshot is retained. Editing a key does not trigger another lookup or reload the favorite page. A later explicit operation uses the newly accepted key and may update its results. This retains presentation, not authorization or freshness: a retained display snapshot is never inserted into another credential's request-cache partition. Rejected or failed saves restore the accepted key and leave its metadata intact. Old responses cannot republish results or save a selected metadata snapshot after credentials change. Requests capture the accepted settings key, independently of an uncommitted input draft. The cache partitions entries by a private credential digest and Voice ID under one global 300-entry bound; constructors do not change another facade’s partition. Events carry that captured scope and recheck it inside queued UI work. Startup UI publication also rechecks its captured key. Unused partitions retain the ordinary TTL and bound; no raw key is retained or printed by the cache. Samples and covers continue to use resource requests without account or dummy authorization; TTS and credit retain their real-key requirements.

Credential-string equality alone cannot reject an old A response after an accepted A → B → A edit. An opaque, nonserialized runtime credential identity changes at the final successful leased settings publication, alongside the key under the short settings lock. Same-key writes retain the current identity, including after a reentrant save; failed writes and uncommitted facades do not advance it. Startup captures key, voice and identity together, and checks the identity after the response, in the conditional save and inside deferred UI apply. Metadata-event subscriptions capture the accepted identity and are rebound after successful key edits; an in-progress notification's subscriber snapshot and queued callbacks retain their original identity. Digest-based cache partitions and their reusable entries are unchanged. The legacy facade without a lease rotates identity after its save returns successfully and retains its existing temporary mutation window; production Main uses leased writes.

## Voice language metadata

Provider `languages` values travel through Search, independent By-ID results, favorite-page detail loads, the shared metadata cache, selected-voice persistence, startup refresh and preview detail refresh. Cards expose `Languages`; the selected facade exposes `CachedVoiceLanguages`. These collections contain language codes only. They trim surrounding whitespace, lowercase invariantly, replace underscores with hyphens, omit null/empty entries and deduplicate in first-seen provider order. Unknown codes remain available, and a presentation limit must not truncate the retained metadata.

Published metadata owns a detached read-only language collection. Settings snapshots, leased host-storage copies and cache-to-settings conversions retain independent metadata ownership. Missing or null language fields default to an empty collection. Authoritative empty refreshes replace former languages; clearing selection and resetting a favorite to an ID placeholder also clear the former tags. Refreshing metadata does not apply a browsed voice or change favorite IDs. Existing originating-card, generation, cancellation and accepted-credential checks govern these assignments.

Offline [language metadata regressions](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/VoiceLanguageSuite.cs) cover fake HTTP mapping, refresh/clearing, immutable cache values, selected settings round trips and copy isolation. They do not establish provider language accuracy or physical playback.

### Responsive language pills

The selected card and the shared Search/By-ID/Favorites template use the compiled [VoiceLanguageTags control](../../STranslate.Plugin.Tts.FishAudio/Presentation/View/VoiceLanguageTags.xaml). Its language-list and UI-locale dependency properties are presentation inputs; changing the UI dictionary does not mutate metadata or perform a request. Language names come from .NET `CultureInfo.DisplayName` under the explicitly selected UI culture. Any temporary `CurrentUICulture` assignment is synchronous and restored in `finally`; the process default is never changed. A `DynamicResource` locale marker and caption in each of the seven dictionaries update an existing control and its open popup.

The inline row has one 20.5-DIP line, a 7-DIP leading margin and 5-DIP following gap. It never wraps. Each capsule has an 11-DIP name, 14 × 10.5-DIP decorative flag, 4-DIP flag/name gap, a neutral 1-DIP border, padding `5,1,7,1` and a 10.25-DIP corner radius. Using a radius of 999 in WPF scales the corners toward an ellipse; the actual half-height radius preserves flat top/bottom edges and semicircular ends. Pills have a 4-DIP gap. The focusable text `+N` button shares the 20.5-DIP height and has a 30-DIP minimum width, so overflow does not raise the row or move the author baseline. An empty language list collapses the entire row and both margins.

Fit the largest provider-order prefix whose full flag/name pills, gaps and measured remaining-count trigger fit the finite content-column width. There is no three-language cap or monitor-width breakpoint. If all languages fit, omit the trigger. If even the first full name plus the remaining trigger does not fit, retain one flag/name capsule and ellipsize its name to the remaining width. A single language uses the available width without an overflow button. Tooltips and automation names retain the full localized name and normalized code. Recompute after width, DPI, inherited font-family/weight/style/stretch, language-list and locale changes. Popup entries are exactly the suffix after the current visible prefix; no language is duplicated or omitted.

Flags use the embedded, fixed-index [flag-icons 7.5.0 raster atlas](../../STranslate.Plugin.Tts.FishAudio/Assets/Flags/README.md), with no network requests, SVG runtime or provider-derived resource paths. Bare normalized `en`, `zh`, `ar` and `pt` use US, CN, SA and PT. Explicit region tags use their own country. Other recognized neutral and script-qualified cultures use the runtime's .NET specific-culture region; for example the current Windows table chooses HK for neutral `zh-Hant`, while explicit `zh-Hant-TW` uses TW. `uk` is Ukrainian/UA. Unknown codes retain their text and use the bundled neutral globe. Numeric macroregions without an indexed country flag retain their localized name and use that same globe. Flags are decorative and create no separate automation elements. The full upstream MIT notice is packaged.

The native popup contains only remaining languages, with a localized heading and remaining count. Its shell has a 290-DIP maximum width and 12-DIP padding. A fixed localized heading/count remains above the finite scrolling body. Full-name capsules wrap inside it; their 12-DIP labels use 18-DIP line height, vertical padding 3 and radius 13. The body viewport is at most 280 DIP and shrinks to the available visible height after measuring fixed chrome. Custom WPF placement coordinates and sizes are device pixels; convert only the design insets from DIP, preserving containment at fractional DPI.

One overlay is owned by each settings view. The same trigger toggles it; outside presses and window deactivation close it without forcing focus. Escape is observed through the owning dispatcher's input pipeline, including the popup's separate presentation source, closes the overlay and returns focus to a surviving trigger. Tab, Enter, Space and an expand/collapse automation pattern retain native button behavior. `StaysOpen=true` avoids capture-based dismissal on trigger mouse-down followed by accidental reopening on Click. Hide, unload, rebinding, language replacement, trigger removal and ancestor scrolling close it; window movement/resizing repositions it. Input, window and scroll subscriptions exist only while it is open and are detached even if WPF closes its native window. Existing card commands, hit targets and parent numeric-draft commits remain independent.

The [compiled pill regressions](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/VoiceLanguageTagsSuite.cs) cover partitions, responsive fit, all seven live dictionaries, culture/region/unknown mappings, popup input/lifecycle, theme resolution and real compiled cards/native popup rasterization at 320/400/480/640 DIP and 100/125/150% rendering DPI. This is local offline WPF evidence, not installed-host, physical pointer, provider accuracy or audible-output acceptance.

### Shared popup chrome and native material

Both shells use the host font and dynamic `FlyoutPresenterBackground`, `FlyoutBorderThemeBrush`, `FlyoutBorderThemeThickness` and `OverlayCornerRadius` resources (native defaults: 1-DIP stroke, 8-DIP corners). The body alone scrolls. `PopupScrollbarLane` resolves the actual visible `PART_VerticalScrollBar` after every layout, translates its complete bounds into viewer coordinates and reserves that trailing width plus 4 DIP through native presenter padding. The lane can grow for expanded/replaced parts, and remains reserved until close to avoid overflow oscillation. It never clones the native templates or overlays selectable content. Both popup lifetimes detach layout/unload handlers and restore original padding. Shared `PopupViewport` intersects actual owner, rendered ancestor scroll presenters and monitor work area, preserves 8-DIP screen insets and measures localized fixed chrome before constraining the body. Measuring chrome does not collapse the focused body.

`PopupMaterial` owns only the exact popup `HwndSource`. On Windows 11 build 22621 or later, it chooses `AllowsTransparency=false` before source creation, clears the composition target, extends the client frame and requests the existing public toolkit `BackdropHelper` Acrylic11 and dark-mode/corner APIs. The pinned host is STranslate 2.0.10 (`2a75118fe0fabc1135a619f4393eb3a8d936c5cd`), SDK 1.0.15 and Modern 0.10.2.1 (upstream `f00f1c6cc233ee14a38f9603931c4ee457223f9c`). Only successful frame HRESULT and documented `DwmGetWindowAttribute(DWMWA_SYSTEMBACKDROP_TYPE)` readback returning `DWMSBT_TRANSIENTWINDOW` enable the transparent WPF shell. The helper's unchecked boolean and the toolkit's opaque Acrylic-named brush are not material evidence. Unsupported platforms or failed/wrong readback retain the explicit opaque native flyout brush; an already created nonlayered fallback also receives that opaque composition-target color and native corner/dark-theme hints. No toolkit layered `ThemeShadowChrome` margin is combined with the nonlayered path: the HWND footprint is the clamped shell, with system-owned corner/shadow policy and no synthetic outward shadow allocation.

Live native brush replacement updates theme state. Close, unload and source retirement detach exact subscriptions and remove only owned popup material; reopen reacquires its source. The host Window's material is untouched. A narrow injectable native boundary exercises unsupported, frame failure, readback failure and wrong-type fallback deterministically without global test flags. Optional native application/chrome errors are contained at that boundary as opaque fallback; the first failure identity/HRESULT is retained privately and cleanup failure is separate, without raw public diagnostics. Pre-HWND initialization failures propagate after input/overlay retirement. Source creation callbacks never intentionally throw optional interop failures into WPF. Successful attribute readback establishes requested capability, not visible desktop blur, user transparency settings or installed-host acceptance. Fixture rasterization composites native chrome for layout review and cannot capture DWM material. Tests log actual popup/child DPI separately from requested owner-root DPI; changing owner-root DPI does not establish that the separate popup source changed DPI, and these fixtures do not change OS display settings.

Fixed-chrome fit uses the current native presentation source. Before creating it, the shell is bounded to the visible viewport; immediately after creation, the same opening operation synchronously measures localized fixed chrome and closes/releases ownership if either axis cannot fit. A retired PopupRoot suspends layout, so its previous constrained desired sizes cannot authorize reopening. Horizontal fit measures the complete native Search footer and Close slot, or the language popup's fixed remaining count, including their margins/gaps and the shell's current padding and border. Header titles may wrap. Resize uses the same source-based fit decision, and refusal leaves drafts unapplied and permits reopening when sufficient space returns.

## Search and pagination

The search result list, window hint and pagination share a collapsible body controlled by a compact count-and-chevron ToggleButton. It starts expanded and becomes visible after a search has been applied. Its keyboard/automation toggle collapses the existing content without clearing the query, result objects, page or selected voice. Expansion is local view state retained while that settings view exists; switching tabs or completing another search does not override it. Existing page-input focus-loss commits still apply when the user leaves an edited page field. All seven UI locales provide action hints.

Search and Favorites fold controls use WPF's keyboard-navigation focus adorner, with a primary-text outline that contrasts in either theme. Mouse-acquired focus does not paint a persistent outline after the pointer leaves. Both controls retain Tab reachability, native keyboard/automation activation, themed hover and pressed surfaces, localized names/tooltips and fixed geometry. This focus treatment is scoped to the fold controls; browse-mode tab styles are unchanged. The [compiled focus regression](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/SettingsInputInteractionSuite.cs) reproduces native focus/pointer states and rasterizes the installed keyboard-focus template at narrow/normal widths in both themes; it does not claim physical Tab or installed-host pointer acceptance.

Search is explicit through its button or Enter, using the visible text and successfully applied options. The internal immutable request criteria captures title text, a detached read-only language set in preset order and a sort enum; the accepted API Key is captured separately. Every GET explicitly sends `sort_by=score`, `task_count` or `created_at`, with six raw provider records per page and escaped title text. All languages omits `language`; multiple specifics send repeated `language=en&language=zh` keys in one GET; the language presets, in order, are `en`, `zh`, `de`, `ja`, `fr`, `es`, `ko`, `ar`, `ru` and `pt`. UI titles are Relevance first, Most used first and Newest first (Simplified Chinese: 相关优先、热门优先、最新优先). The radio choices display titles only, without helper descriptions. Relevance first is the chosen presentation name for provider `score`; it does not imply a known scoring formula, numeric score or sort direction. The [provider reference](../references/voices-list.md) separates the documented values from bounded live observations.

Provider pagination and metadata mapping are validated before changing successful state. One current-owner UI publication commits criteria, results and navigation before cover/cache enrichment. A successful new Search or Apply resets to page one; paging reuses the complete committed snapshot, so unsubmitted text or option drafts cannot alter an existing result set. Failed, replaced, credential-retired or disposed operations retain the previous successful results/options/page and cannot publish late state, including work retired after it was queued for WPF. Cover/cache enrichment failures retain that valid metadata snapshot and use a fixed diagnostic without remote text or URLs. Boundary buttons hide without moving the center control. Search options are session-only and never enter settings storage.

The native Search input retains its font, baseline, left/top/bottom padding and disabled clear adornment. Its right padding reserves an embedded 28 × 28-DIP adjustment action with a 4-DIP right inset; the external magnifier and 36-DIP row remain. A small accent indicator reflects successful nondefault options, never drafts or in-flight candidates. The [compiled SearchAdjustmentControl](../../STranslate.Plugin.Tts.FishAudio/Presentation/View/SearchAdjustmentControl.xaml) opens a native popup with a 324-DIP maximum shell width, clamped to the settings viewport and monitor work area with device-pixel custom placement. Visible bounds intersect the owner with every ancestor ScrollViewer's rendered ScrollContentPresenter, rather than its full scrolled content or logical item counts. Placement prefers above the trigger when below does not fit. If neither side fits the natural height, the popup uses the larger side. When neither side fits measured fixed chrome plus one 32-DIP option, it clamps across the trigger within the complete visible viewport. A viewport that cannot fit fixed chrome refuses/closes the overlay and releases ownership. Insets use the native screen transform; callback sizes/offsets are already device pixels. It presents eleven equal 32-DIP-high native ToggleButtons in two equal-width columns with 6-DIP gaps. All languages occupies only the left cell of its first row; the pairs below are en/zh, de/ja, fr/es, ko/ar and ru/pt. All has text/check only; specifics use the existing explicit-culture names and bundled flags. Selected tiles use a subdued themed fill, accent border and check. Full localized names remain in tooltips and automation while constrained labels ellipsize at native text metrics. Live seven-locale replacement preserves the entire draft set. The 14-DIP Semibold title and quiet 28-DIP Close remain in a fixed header with a 12-DIP gap. Language/sort captions use 12-DIP secondary text; three native sort radios retain their checked ring, 32-DIP minimum rows and no extra row gaps. The fixed footer has a subtle divider and 32-DIP minimum native Reset/Apply actions with a 12-DIP gap. Apply uses the installed toolkit's `AccentButtonStyle`; Reset retains its standard native style. Both localized labels remain outside body scrolling.

Opening initializes drafts from successfully applied options. All is exclusive with specifics; selecting All clears them, selecting a specific exits All, and clearing the final specific restores All. All ten presets remain a filtered set because the provider supports other language values. Criteria synchronously reject unsupported codes, copy and deduplicate ordinally, then expose a read-only snapshot in preset order. Multiple-language combination semantics are delegated to the provider; official sources do not establish AND/OR conclusively. Reset changes drafts to All + Relevance first; Close discards drafts. Neither causes a request. Apply captures the visible query with the drafts, closes the popup and immediately starts exactly one page-one GET, including when the options are unchanged. Enter/Space on native tile/radio choices stays local; explicit Apply keyboard activation issues one request. Blur does not search. New Search/Apply operations cancel and replace prior searches without synthesis, retries or automatic model selection.

Search adjustments and language overflow share per-settings-view token ownership. Opening either closes the other; stale releases cannot remove a later owner. Escape closes adjustments and returns focus to a surviving trigger. Outside press, tab change, ancestor page scroll, hide, rebind, unload and deactivation close the overlay; move/resize/DPI changes reposition it. Internal body scrolling is distinct from ancestor page scrolling. Input, scroll and window subscriptions exist only while ownership is active and close/release are idempotent.

Screen containment uses the native HWND's actual monitor transform; injected visual-root DPI is not an OS display-scale change. These tests do not establish installed-host physical focus, provider ranking accuracy, synthesis or audible output.

Search and Favorites retain native centered 40-DIP page TextBoxes with explicit TwoWay draft bindings. The shared [page-input behavior](../../STranslate.Plugin.Tts.FishAudio/Presentation/View/PageInputBehavior.cs) validates the whole proposed selection replacement, accepts only ASCII digits and rejects mixed, multiline or missing-text paste wholesale. Space is blocked; ordinary editing, selection and copy shortcuts remain native. Empty/zero drafts and valid leading zeros remain editable. A positive draft above the effective maximum immediately becomes that maximum without navigation or Settings persistence; digit-string comparison avoids overflow even for oversized paste. Bound changes recheck the draft with binding-preserving normalization and guarded reentry.

Enter or focus loss commits a normalized valid target; empty, zero, malformed and out-of-policy drafts restore the applied page. Commands independently validate programmatic drafts. An unchanged target canonicalizes its text without a request, cancellation, results rebuild or metadata reload. Enter followed by blur, repeated blur and a pending Search commit do not duplicate navigation. Favorites places this guard at the input-commit boundary: real bookmark mutations and explicit reloads still refresh the same numbered page. Page entry remains transient navigation state and never saves plugin settings.

[VoiceSearchPagination](../../STranslate.Plugin.Tts.FishAudio/Presentation/VoiceSearchPagination.cs) keeps reported total, exactness, last accessible page and Next availability separate. `max_offset` restricts starting offsets; `accessible_upper_bound` limits accessible records. Precise `total` can add a bound; approximate `total` cannot authorize jumps. The minimum applicable bound still permits a partial final page, such as page 167 at offset 996 under a 1000-record window. Window limitation can be inferred when a hard bound truncates an exact total, even if the flag is missing.

An explicit `has_more=false` or empty raw items stops forward navigation. Raw full pages without any total/metadata allow one further attempt; raw short pages stop unless the server explicitly permits more. Without a known bound, only visited pages and the currently permitted next page are reachable. Empty pages are not automatically retried or skipped. Raw record counts govern paging before explicit non-TTS records are filtered from selectable cards.

Pagination is published before cover resolution. The canonical policy shares one overflow-safe maximum between domain navigation and the read-only Search input bound. A known bound uses `LastAccessiblePage`; unknown extent uses the greater of the highest visited page and the currently permitted next page (or current page when Next is unavailable), capped at the integer limit. Returning backward therefore retains access to a previously visited higher page. The stable numeric facade properties remain, but their presentation fallback and approximate reported totals cannot authorize navigation. Publish the new canonical bound before the applied page draft so view normalization cannot clamp it against a stale maximum. Favorites uses its exact local page count. UI uses `≈` for approximate counts, `?` for unknowns and `≤` for accessible page bounds; all seven UI locales explain the window. Exact provider window-edge semantics have not been live-tested at every offset; see [DD-048](../adr/current/DD-048.md).

The offline [page-entry regressions](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/PageEntrySuite.cs) exercise compiled fields, staged DataObject paste without changing the system clipboard, immediate clamping/source updates, canonical provider/unknown bounds, page/maximum publication transitions and no-op/pending Favorites ownership. Existing discovery and favorite suites retain failed/stale request, committed-query, server-window and mutation-refresh coverage. These fixtures do not establish installed-host physical focus or clipboard interaction.

## By-ID lookup and local favorites

Each By-ID validation, not-found or request error remains visible for five seconds from its own publication. Repeating an identical error restarts that lifetime. Editing the ID or beginning another lookup clears the previous error immediately; successful lookup leaves no error. Expiry clears only `VoiceIdError`, preserving the input draft, result cards and selected voice. Complete lookup validation still checks the raw, untrimmed lowercase Voice ID independently of input editing constraints.

The [discovery coordinator](../../STranslate.Plugin.Tts.FishAudio/Presentation/VoiceDiscoveryCoordinator.cs) owns one disposable one-shot timer, with an injectable `TimeProvider` and a version per occurrence. Replacement, clearing and disposal retire that occurrence; an expiry callback rechecks its version and facade lifetime inside the UI dispatch before publishing. Request cancellation and operation generations continue to reject stale success and failure responses, including transports that ignore cancellation. This is transient presentation state and never saves settings. The offline [discovery regressions](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/VoiceDiscoverySuite.cs) cover 4999/5000 ms, identical replacements, edits, pending/successful lookups, queued older expiries, disposal and late fake HTTP completions. These tests do not establish installed-host acceptance.

The tab order is Search, By ID, Likes (the existing Favorites browse mode), with one active panel at a time and an icon on each tab. Simplified Chinese names the third tab “喜欢”; Traditional Chinese uses “喜歡”. All seven locales use compact tab captions with the existing peer icon allocation and label metrics. Selection uses the host accent background while all labels retain the same font metrics and bounds, so switching modes does not move neighboring tabs. Native hover/pressed surfaces retain that accent: a primary-text overlay lightens the selected fill in dark mode and darkens it in light mode, with a stronger pressed treatment. Native focus behavior and paired on-accent text remain active. Empty Search and By-ID panels use equal input/action row height and bottom spacing, keeping the following Model section in place. The By-ID query button uses the same magnifier as Search; clicking it or pressing Enter retrieves one independent voice card. Lookup success, not-found, validation failure and other errors preserve the currently selected Voice ID and selected metadata. A new lookup or edited ID invalidates the previous result card and pending request, and a late replaced or disposed response cannot restore it. By ID has no pagination or fold control.

All three browsing panels use one card template. Together with the selected card they show the existing Favorite voice state as Like/Unlike with one repository-owned closed heart contour: full rounded lobes, a shallow curved notch and a rounded lower cap. Both outline and filled states use this same silhouette from the compiled [view resource](../../STranslate.Plugin.Tts.FishAudio/Presentation/View/SettingsView.xaml), without an external artwork dependency. Unliked hearts have transparent fill and native primary-text strokes; liked hearts use the shared fixed reference red `#FC3D49` for fill and stroke in both themes. Cards retain their 32-DIP targets, 18-DIP vector width and 1.5-DIP strokes. Uniform stretch with intrinsic height preserves the wider, shorter silhouette in the centered action slot. The tab uses the same aspect-preserved contour at its 12-DIP width, outlined with its native label foreground while inactive and filled/stroked with the shared red while active. Its background and label retain their native brushes. Tooltips, accessibility names, empty/fold states and storage feedback use Like/Unlike/Liked voices in all seven UI locales through existing DynamicResource keys. State is synchronized by Voice ID across all four locations and remains independent of preview and selection. Existing saved favorites become the same liked items immediately, with no new file or migration. Provider popularity remains `task_count`, not account likes. The public Favorites classes, commands, bindings and `favorite-voices.json` identifier remain unchanged.

The offline [Like presentation regressions](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/VoiceLikeSuite.cs) exercise the rounded notch/lower cap, shared outline/filled card and tab geometry, legacy ID-file loading, real selected/browse mutations, restart/order compatibility, reference red across accent changes, native inactive outlines, rendered aspect and localized action/tab state. Physical-raster coverage retains the original exact Cross/star classifier using a test-only reference star at the declared historical phase; product hearts retain the same half-physical-pixel bound, exact native outline-to-ring checks and fixed-crop displacement sensitivity. The current three-action title strip also checks the refined heart beside the original 36-DIP preview and selection action before avatar relocation. The headless fixture supplies an opaque accent palette for native controls because OS accent initialization is absent. These fixtures do not establish installed-host appearance or audible output.

Selection actions are borderless icons: Tick applies an unselected card; Cross clears the currently selected Voice ID. Every matching card, including the selected card, shows Cross for that ID. Applying another voice or clearing selection updates all matching cards. An unselected metadata placeholder cannot apply, while an already-selected matching ID can still be cleared without metadata. Action tooltips/accessibility names follow the state, and keyboard focus remains visible. See [DD-056](../adr/current/DD-056.md).

Favorites persist only ordered Voice IDs in `Path.Combine(context.MetaData.PluginSettingsDirectoryPath, "favorite-voices.json")`, a plain UTF-8 JSON string array. SDK 1.0.15 documents that directory for plugin settings/data and lets the user retain it during uninstall. There is no install-directory or machine-specific fallback. The file is plugin-wide across profiles sharing the same directory; it contains no voice metadata, sample URLs, image copies, audio bytes or account credentials. Settings remains schema 2, with no favorites property.

[FavoriteVoiceStore](../../STranslate.Plugin.Tts.FishAudio/Configuration/FavoriteVoiceStore.cs) reads at most 32 KiB plus one overflow-detection byte. Canonical IDs use the existing strict 32-lowercase-hex validator with absolute string boundaries. Invalid ID strings are ignored; duplicate canonical IDs keep their first-seen order. Missing files mean an available empty list. Invalid JSON, a non-array root, non-string entries, unreadable storage, unavailable host directory, oversized bytes or more than 300 distinct valid IDs mean an unavailable collection: preserve the file and show a localized failure rather than silently overwrite it or truncate a 301-ID list. An ordinary addition at 300 rejects with a localized hint and evicts nothing.

Writes serialize explicit add/remove intent, re-read the latest file under a shared canonical-path gate, flush a same-directory temporary file to disk, then atomically replace/move it. Separate in-process profile instances cannot overwrite one another's updates. UI IDs/hearts/counts change only after successful persistence. Disposal and active Settings write-lease authorization linearize file commits with generation retirement without taking the short settings snapshot lock. No UI callback or notification runs inside persistence/path gates. Other profiles' changes become visible when entering Favorites or performing a mutation; no file watcher or cross-process write coordination is implemented.

[VoiceMetadataCache](../../STranslate.Plugin.Tts.FishAudio/Caching/VoiceMetadataCache.cs) is a single plugin-instance-owned in-memory cache shared across reinitialization. Search responses, By-ID detail, favorite-page detail and preview-detail refresh populate it. Entries are detached immutable values, bounded to 300 with LRU eviction and a fifteen-minute monotonic **client** TTL. Metadata strings are bounded to 512/8192/256/4096/8192 UTF-16 code units for title/description/author/canonical remote cover source/sample URL; negative popularity becomes zero. This TTL does not describe provider validity or sample URL expiry. No metadata or audio file cache is added.

Favorites has six cards per page, exact local counts, previous/next chevrons and numeric page entry committed with Enter or focus loss. Search and Favorites paging actions use bare left/right icons without visible words or a rectangular surround; localized tooltips/accessibility names retain their meaning. Cached metadata displays synchronously and avoids a detail GET. Cache misses publish ID-title placeholders first and fetch only the visible favorite page when its tab is active. Loading/failure cards remain bookmarked and removable; they cannot apply without metadata, but may clear their already-selected matching ID. A missing/not-found/unavailable voice never deletes an ID. Page replacement, unbookmarking, tab exit and disposal cancel owned loads; generation and originating-card checks reject late responses. A metadata-cache miss after process restart therefore requires a public detail request; bookmark IDs survive independently.

Removal immediately updates the successfully persisted list/count. Removing the only final-page card clamps to the preceding page. Empty lists remain at page one with a localized empty-state hint, while storage failure has its own persistent error state. Favorites uses its own compact count-and-chevron ToggleButton and collapsible body, initially expanded, with keyboard/automation support and view-local state retained through tab switches and list changes. Search expansion stays independent. All three panels use the existing cover-cache resolver keyed by Voice ID; Favorites adds no second image folder. See [DD-054](../adr/current/DD-054.md).

## Preview ownership and download

Selected metadata is cached with settings; browsing cards are independent observable objects. Preview state remains keyed by Voice ID, keeping the selected card and matching cards in all three panels synchronized. Both public commands allow a second click during pending work to stop it.

The first click publishes the preparing Voice ID synchronously, before metadata or resource requests can await. Both entry points show an indeterminate spinner and a cancel square throughout refresh, download and local output preparation. Matching selected/search cards, including duplicate result IDs, share that state. A second click on the same Voice ID cancels rather than starting another request, even through the other entry point. A click on a different Voice ID replaces the old operation and transfers the preparation indicator.

Preparation is separate from actual playback: it has no percentage or simulated playback progress. Only a successful local Play return enables the output-position progress ring; the square then stops playback. Idle, preparing and playing buttons expose localized tooltip and accessibility names in all seven UI locales. Completion, timeout, failure, explicit cancellation, selection/clear, removal of the originating result and disposal clear the owned preparation state. A late canceled response or queued old UI publication cannot clear a newer request's spinner. See [DD-049](../adr/current/DD-049.md).

[PreviewAudioUrlPolicy](../../STranslate.Plugin.Tts.FishAudio/Presentation/PreviewAudioUrlPolicy.cs) still permits only HTTPS `platform.r2.fish.audio` and non-empty subdomains of `r2.cloudflarestorage.com`. Unsigned allowed URLs are reusable. Signed URLs refresh thirty seconds before expiry; missing, duplicate, malformed or overflowing timing data requires conservative refresh.

URL/metadata reuse is distinct from audio-byte caching. Both the v1.1.2 remote-WPF-MediaPlayer baseline and current implementation have no plugin-managed reusable audio cache. The baseline opened the remote URL; any OS/network behavior was outside plugin cache ownership. Current playback downloads the sample through host HTTP into a new MemoryStream for that play, then disposes it on stop/end/failure. CachedVoice stores metadata and the sample URL, while CoverImageCache stores image files. Neither stores reusable sample audio. A reusable unexpired/unsigned URL therefore avoids a detail refresh, not the sample GET.

The same thirty-second signed-URL policy existed in the baseline; current resource 403/404 recovery adds one bounded detail refresh. All list/detail sample URLs in the [2026-10-20 captures](../evidences/2026-10-20/README.md) were unsigned, with no query or separate expiration field. The schema exposes `title`, `text`, `task_id` and string `audio`; it does not promise permanent unsigned URLs. Signed-URL handling remains defensive compatibility behavior, not a claim about those captures.

[PreviewRefreshCoordinator](../../STranslate.Plugin.Tts.FishAudio/Presentation/PreviewRefreshCoordinator.cs) owns one operation generation through refresh, download and output start. Selected refresh saves complete current CachedVoice metadata; search refresh updates its current card. A fresh response without a sample is authoritative. Expiry refresh failure never falls back to the old URL. A sample 403/404 can consume one detail-refresh budget and retry its newly returned URL once; an earlier expiry refresh already consumes that budget. Other errors and a repeated 403/404 do not retry. No preview path invokes TTS.

[PreviewAudioDownloader](../../STranslate.Plugin.Tts.FishAudio/Presentation/PreviewAudioDownloader.cs) retrieves the sample using host `IHttpService`, with no account or dummy authorization. A single fifteen-second operation token includes metadata refresh, resource request and successful body reads. It copies into seekable memory, checking at most eight MiB plus one overflow-detection byte. Empty, oversized and failed downloads do not create playback. The host stream API internally handles unsuccessful response bodies before returning; the plugin's cap describes its returned-stream copy, not all host-owned error buffering.

Stop, selection changes, entry switching, result removal and disposal invalidate pending work and stop owned playback. Late streams are disposed and cannot publish state, change a new card or restart output. Logs identify operation and exception type without publishing signed resource URIs.

By-ID and favorite cards reuse this same preview pipeline, including URL refresh, 403/404 retry, host download, timeout and memory bounds. Refresh updates the shared metadata cache and matching cards, while preserving the selected voice until Apply. Sample expiry or 403/404 deliberately bypasses the metadata TTL cache before putting the authoritative detail response back into it. Preview ownership includes the originating card object: changing the favorite page, unbookmarking the originating favorite or replacing the By-ID card cancels pending work and stops its playback even if a matching ID remains in another panel. A late removed-card response cannot re-add a favorite or replay it.

## Local audio and progress

[PreviewPlaybackController](../../STranslate.Plugin.Tts.FishAudio/Presentation/PreviewPlaybackController.cs) takes ownership of the memory stream on every start, including factory/open/play failure. [NAudioPreviewAudioPlayer](../../STranslate.Plugin.Tts.FishAudio/Presentation/NAudioPreviewAudioPlayer.cs) uses NAudio.Core/WinMM 2.3.0, seekable MP3/WAVE reading, Windows ACM MP3 decompression and WaveOut output. Client volume is 1.0. The memory stream is independent of the already closed HTTP response stream.

Playback state is published only after local Play returns successfully and the player generation remains current. A 50 ms dispatcher timer reports device output position against total duration; decoder read-ahead is not presented as played progress. End/failure stops output and clears state. Old events are ignored after switch/disposal, including callbacks already queued to the dispatcher. Controller cleanup releases timer, player and buffer even when a stop/dispose step fails.

Offline tests inject player doubles and do not prove physical sound. [Installed-host acceptance](../evidences/preview-host-2026-10-20.md) records both entry points with and without an API Key, output-position progress, explicit stop and natural completion, with its observation limits. The bounded whole-sample preview design does not apply to formal TTS streaming. Rationale: [DD-008](../adr/current/DD-008.md), [DD-034](../adr/current/DD-034.md), [DD-040](../adr/current/DD-040.md), [DD-047](../adr/current/DD-047.md).

## Cover cache

[CoverImageCacheService](../../STranslate.Plugin.Tts.FishAudio/Caching/CoverImageCacheService.cs) stores `cover_images/<voiceId>.jpg` under the host cache directory. Search, By-ID and Favorites all resolve the same canonical remote cover source through this service. A local hit wins; a miss displays CDN content and downloads in the background. A ten-second token and 256 KiB plus one detection byte limit downloads. Only non-empty JPEG/PNG/GIF/WebP-looking content up to 256 KiB is cached. Cache usage rescans actual JPG files. Cleanup is scoped to cover_images, exposes busy state, recovers its button after ten seconds and prevents a late old task from unlocking a newer operation. It cannot remove persistent favorite IDs or the in-memory metadata cache. Existing cards switch back to their remote display source; a later search, By-ID lookup or favorite-page resolution can download through the same cache again.
