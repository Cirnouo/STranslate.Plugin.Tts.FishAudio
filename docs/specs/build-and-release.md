# Build, package and release behavior

Status: current Unreleased implementation. The plugin targets .NET 10 Windows/WPF and references STranslate.Plugin 1.0.15. The distributable version is owned by `STranslate.Plugin.Tts.FishAudio/plugin.json`, independently of the SDK version and settings schema. The verified host baseline is STranslate v2.0.10; no unsupported minimum-host-version manifest field is invented.

The repository [global.json](../../global.json), Validation, CodeQL C# extraction and Release publication pin the SDK to `10.0.403`, independently of the plugin version. The hybrid validation and aggregate jobs use a dedicated installation directory and assert that actual SDK. This exact SDK input avoids floating-channel selection; the pinned setup-dotnet action separately attempts its Runtime LTS installation, so the SDK pin does not freeze every runtime component. Lock files cover the maintained project graphs. The dependency-audit restores, framework driver and CodeQL builds explicitly request locked resolution.

Preview and formal streaming audio depend on NAudio.Core and NAudio.WinMM 2.3.0. Streaming MessagePack 3.1.12 also requires MessagePack.dll, MessagePack.Annotations.dll and Microsoft.NET.StringTools.dll. Package verification includes these private runtime assemblies alongside the plugin, all seven UI XAML dictionaries and their seven localized metadata JSON files (en, zh-cn, zh-tw, ja, ko, ru and tr), and the Octicons and flag-icons license notices without bundling the host SDK/UI framework. The language flag atlas, trusted country index and generic globe are embedded in the plugin assembly; compiled regressions require all three resources. The [asset provenance and reproduction instructions](../../STranslate.Plugin.Tts.FishAudio/Assets/Flags/README.md) pin the upstream archive and atlas hash. Normal regression tests inject outputs and do not require a physical audio device.

[build.ps1](../../build.ps1) defaults to Debug and exposes only -Release as its configuration switch. An unfiltered Release -Test builds and checks the current package, then uses [TestHybrid.ps1](../../tools/TestHybrid.ps1) and the independent [Assert-HybridSession.ps1](../../tools/Assert-HybridSession.ps1) consumer to cover the complete current legacy/NUnit owner plan once. Explicit legacy selectors and `-LegacyOnly` retain their diagnostic scope; Debug `-Test` also remains a legacy diagnostic. Debug packaging invokes the SDK target; Release uses automatic packaging. Output directories isolate Debug and Release, and the distributable is copied to the repository root. Build and explicit packaging invocations pass `--disable-build-servers`, `-p:UseSharedCompilation=false` and `-nodeReuse:false`; the output-path property query also passes `-nodeReuse:false`. These options disable compiler and MSBuild server reuse for the owned invocations. The separate `FishAudioCoverage=true` output/intermediate roots retain Release build semantics for bounded coverage work; normal framework execution uses normal Release output.

An ordinary build cleans repository/plugin/test intermediates first and retains newly produced intermediates. -Clean defers that cleanup to finally on success or failure; it leaves an already copied root .spkg intact. -CleanOnly performs the same cleanup and exits. A retained package is not proof that a later build succeeded.

The standard combined full verification command is `./build.ps1 -Release -Clean -Test`. It checks the current package, executes the complete legacy catalog and executes both complete NUnit catalogs before final cleanup. [Program.cs](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Program.cs) retains its direct legacy behavior and accepts an optional leading `--legacy`; internal child and report-verifier dispatch retain priority. Build and CI pass the explicit prefix. VSTest loads NUnit fixtures without invoking that entry point. Legacy metadata listing and framework discovery construct no execution fixtures. Normal tests are offline and require no Fish Audio credential or synthesis request.

Every commit uses the installed protocol-3 pre-commit gate to validate a raw-blob snapshot of the exact index tree. The implemented `bootstrap/full/hybrid` mode separately invokes the snapshot's `build.ps1 -Release` to build and inspect the current package, then builds both test projects with the standard normal Release flags. The snapshot's `tools/TestHybrid.ps1 -NoBuild` executes the complete fixed logical slot plan and disjoint framework tail; the separate `Assert-HybridSession.ps1` independently reconstructs current catalogs and admits each actual legacy or framework owner from its raw results. No complete legacy report or merged framework result is synthesized. Worktree-private `pre-commit` and `commit-msg` entries retain prior hooks in an atomic immutable installation bundle, including the digest-bound minimal receipt consumer. After the prior commit-msg hook, the final guard checks the frozen manifest, original tree/index identity, retained artifact bytes and physical attempt/committed-generation inventories without rebuilding or rediscovering the cleaned snapshot. Upgrade older installed copies with `-Install` followed by `-Check`. `FISHAUDIO_EXPECTED_TREE` optionally freezes the intended tree before the signed commit command. No tests run at pre-push. The [test-system specification](test-system.md) owns the detailed protocol and evidence contract.

Gate sources and build outputs use an independently owned short temporary directory, with an apphost-path-length preflight before materialization. Reports and logs stay in Git-private run state. An available actual snapshot package is retained there as `package.spkg` with its SHA-256 before the source/build directory is removed, including when later tests or validation fail. A retained package does not establish a successful run. Cleanup runs for successful and failed validation, independently of package-retention failure, and checks creation ownership and the resolved target before recursive removal; it must preserve an existing primary failure. The test-system specification owns the retention and cleanup details. These implementation boundaries do not independently establish a successful run.

For local iteration, `./build.ps1 -Release -Test -Affected` freshly builds and inspects the package while a small explicit source/shared-dependency map recommends legacy regression groups from the merge-base with `origin/main`, committed changes and the working tree. Unknown dependencies expand the recommendation conservatively. `-TestBase` selects another comparison ref. `-TestGroup` and `-TestCase` select logical groups and exact stable IDs; repeated selections are combined. `-TestPartition` limits the execution partition, `-TestResults` selects the legacy report destination, and `-RerunFailed` recovers failed/incomplete legacy coverage from a prior report. Selection options require `-Test`; `-TestBase` additionally requires `-Affected`. Debug and focused legacy commands retain their legacy scope. These commands do not replace the full commit gate.

The direct legacy runner supports `--list`, `--all`, `--group`, `--case`, `--partition`, `--results`, `--affected`, `--base` and `--rerun-failed`, with the optional `--legacy` prefix first. Unknown or empty selections fail. Explicit compatibility aliases expand former aggregate IDs to their current registered legacy leaves for case/group selection and unfinished-report recovery, preserving catalog order and deduplication. Aliases are not additional default cases and do not synthesize leaf passes from a previous aggregate pass. After all streaming-playback leaves move to NUnit, their legacy case/group selectors and aggregate replay are retired and reject selection instead of widening to unrelated legacy cases. Select those leaves with `tools/Test.ps1 -Mode Full -CaseId <id>`. The temporary `--streaming-output-tests` diagnostic retains its proof-output argument semantics, but does not establish catalog selection or full hybrid gate success. Run reports record source/configuration, selection reasons, per-case outcomes and monotonic durations; interrupted or unexecuted coverage cannot be reported as passed. Reports stay in ignored local workflow state by default. Gate reports additionally bind the explicit snapshot context. This legacy recommendation map does not establish formal test-impact analysis or a reusable coverage baseline.

The framework driver supports metadata-only `-Mode Discover`, complete `-Mode Full`, exact `-CaseId` selection and `-Workers 0..4`. Its normal Release builds use locked restore; `-NoBuild` requires existing normal Release test/tool inputs. Each run owns a fresh results directory, raw adapter discovery, standard NUnit XML, TRX and phase logs. Requests expand complete execution profiles before scheduling; each phase must execute its exact planned selection. The driver and outer gate reject missing, unexpected, duplicate or non-passing cases from that expanded set. New ordinary NUnit cases are automatically discovered; existing legacy scenarios remain required until their behavioral ownership has migrated. Full driver execution covers its two framework catalogs; the combined build command also covers the remaining legacy catalog. See the [test-system specification](test-system.md#framework-discovery-and-execution) for process ownership, canonical IDs, native compatibility limits and artifact admission.

Native matrix descriptors expose existing independently dispatched owners as stable cases, retaining their original catalog slots and order. The Like aggregate alias excludes its earlier standalone template invocation; input and Search aliases exclude separate core diagnostic cases. A legacy focused wrapper traverses the same callbacks and parameters. Numeric-bottom's legacy wrapper retains its original shared soft-failure collection through the final assertion, while each selected leaf collects its own failures through cleanup. The [card contract](voice-browsing-and-preview.md#creation-dates-and-card-rows) owns static-versus-behavior coverage; metadata creation never constructs a view, starts a Dispatcher or changes resources.

## Regression process isolation

One freshly built runner supervises each remaining nonempty selected legacy partition serially. The complete hybrid plan retains all five logical slots; fully migrated core, native-settings and native-input use their actual framework owners rather than empty legacy children. Logical groups remain finer than these process boundaries. Each child executes its exact selected catalog order on its own shared STA when needed; it never rebuilds. Voice-card ink remains before numeric DPI geometry in `native-settings`, and Search remains before native keyboard state in `native-popups`. Each new process has its own cold first use. A legacy selector runs its unchanged delegate and optional group/proof argument in one supervised child, retaining its original mixed-scenario order.

An independently owned root action receives a monotonic timestamp before Dispatcher queueing or invocation of a non-STA owner. The child installs its context in the actual callback and keeps it across awaits, off-STA continuations, nested dispatch and cleanup. Completion is published only from that callback's final unwind. The parent warns at twenty seconds and continues waiting; at 120 seconds it permanently records a hard timeout. Entry, nested calls, phases and cleanup cannot renew that deadline. Process startup and initial Dispatcher startup each have their own 120-second guard. Independent non-STA playback methods use the same root ownership when invoked directly or through the legacy aggregate. Non-STA work and gaps between roots are bounded without applying a single deadline to a long multi-action suite. Functional timing assertions remain independent.

Failure diagnostics have at most ten seconds in total for scheduling, observing the same task, draining output and reporting. Output cannot renew the allowance; a blocked writer can remain incomplete, and subsequent writes retire. The parent monitors outside the STA, drains stdout and stderr independently, and terminates the failed child process tree within the bounded failure handling. No action is retried or replaced. Other selected process groups continue, with confirmed passes retained and remaining coverage explicitly not-run.

The parent owns the merged versioned report. A completion event names a uniquely indexed immutable snapshot containing the matching request/run, exact selected IDs and partition, source/build identity and consistent completed prefix. The parent reads those snapshots while the child runs. The child publishes its canonical manifest once, without overwriting an existing path, after its final immutable snapshot; it never replaces a live manifest. The parent reads that canonical manifest only after confirmed exit, when it must agree with the final immutable snapshot. This avoids Windows sharing conflicts from repeated file replacements. EOF, an old file, exit zero, missing completion or mismatched evidence cannot pass. Hard expiry remains the primary timeout even when late completion, a late owned fault or a pipe fault also arrives; later cases cannot become reusable passes from the polluted group. Protocol records use fixed safe stages, case IDs and monotonic timestamps through a writer captured before tests can redirect the global console; private proof arguments and arbitrary exception messages are excluded. Rationale: [DD-066](../adr/current/DD-066.md).

Parent report updates also flush a new immutable generation before updating the requested JSON path. The requested path remains a readable best-effort projection; a sharing/access failure of that projection cannot fail a test or discard its durable outcome. The report reader validates the projection against its same-run generation and resolves the latest committed generation, rejecting tampering, identity mismatches and malformed latest data. If projection identity cannot be validated because it is unreadable, recovery expands conservatively instead of authorizing selective reuse. Schema-1 standalone reports remain readable with their original conservative source-recovery rules. Preserve the JSON and generation sidecar together when retaining interrupted-run evidence; a copied standalone JSON cannot establish newer unprojected coverage. Console output supplies concise live progress independently of report readers. The final summary includes every failed/timed-out case with its safe exception type, fixed stage and action ordinal, plus explicit failed and not-run counts.

## Validation and publication

[Validation](../../.github/workflows/validation.yml) runs on pull requests, including title edits, pushes to main and reusable workflow calls. Independent read-only jobs audit all six maintained NuGet project graphs and validate actual submitted commit subjects plus the PR title. Every new validation commit runs one complete `Hybrid validation` Windows job using [TestHybrid.ps1](../../tools/TestHybrid.ps1), followed by an independent [Assert-HybridSession.ps1](../../tools/Assert-HybridSession.ps1) admission. It executes the complete current plan in five fixed logical slots (`core`, `native-settings`, `native-input`, `native-popups`, `native-cards`) and the framework tail. Each logical slot has exactly one current legacy or migrated framework owner; a fully migrated slot does not require an empty retired legacy execution. The complete core framework slot owns its mapped ordinary successors across both assemblies; its standard lazy-text successor has a fresh host. The exact historical child operation remains separately supervised only for declared compatibility. The framework tail contains all remaining discovered cases from both assemblies, excluding every core/native slot member. The current migration map, immutable legacy reference and fresh discovery jointly define the complete obligation. PR/main both use this full transition; CI does not select affected cases, publish a complete baseline or reuse results from another commit.

The original `build-test-package` check remains an always-scheduled aggregate and requires successful supply-chain, commit-message and hybrid dependencies. It downloads all hybrid attempts from the exact workflow run, obtains the complete paginated jobs snapshot and independently rebuilds the current metadata tool and both test assemblies through the standard discovery driver. [VerifyHybridCi.ps1](../../tools/VerifyHybridCi.ps1) then runs the independent hybrid consumer against the selected raw session. Current source, build pins, ordered slot owners, all selected cases and exact raw discovery/NUnit XML/TRX or authoritative legacy generations must agree. Missing, failed, cancelled, skipped, neutral, incomplete or extra owners cannot pass. Rechecking metadata executes no test delegates. Only after complete admission does the aggregate freshly build and inspect the Release package, run the unchanged offline API-probe and release-tool self-tests, and canonicalize the package. Ordinary behavioral checks require neither a Fish Audio key nor a physical sound card; dependency restoration/auditing retains its separate NuGet boundary.

Each hybrid attempt retains its entire raw session, independent producer admission and `ci-owner.json` under `hybrid-report-<commit>-<run>-<attempt>`, for thirty days without overwrite. The owner binds repository, checkout commit/tree, workflow run/attempt, producer job, exact SDK, checkout/temp/executable paths and an ordered digest/length inventory of every retained file. Requested legacy reports, all committed generation records, framework requests, discovery, XML/TRX, process proofs and logs remain byte for byte; no combined report, merged terminal file or rewritten absolute path substitutes for the original evidence. Whole-session ownership replaces the retired per-legacy-job CI stamp: the optional `ci` field stays null or absent in legacy records. The aggregate explicitly rejects every nonnull stamp (and casing aliases) in retained legacy parent generations, child/request records and other slot JSON; it never fabricates a `regression` job identity or silently ignores a foreign owner. The aggregate also retains its fresh independent admission and complete jobs snapshot under its own immutable attempt artifact. The historical [VerifyFrameworkCi.ps1](../../tools/VerifyFrameworkCi.ps1) remains a diagnostic compatibility boundary and is not a second active CI admission flow.

The pinned downloader can produce a flat single bundle or wrapped canonical attempt directories. Admission recognizes exactly those layouts, rejects mixed/unknown entries and reparse points, and validates the selected owner's complete file inventory. Raw process/request records contain absolute paths. The aggregate therefore requires the producer's checkout, temp, shell and dotnet paths to match this runner's expected paths. It computes the one permitted destination itself from the current runner temp root and trusted commit/run/attempt, requires it to be absent, and copies the verified bytes only there. A different runner layout fails with `hybrid-ci-unsupported-runner-layout`; no downloaded JSON chooses an arbitrary destination and no evidence is rewritten. This fixed-layout contract requires an actual Windows CI integration run; source controls do not establish portability.

For a rerun of the same commit and workflow run, admission chooses the latest **actual executed hybrid job** or artifact attempt before reading outcomes. A missing, corrupt, failed or unfinished newest owner cannot borrow an older green bundle, and failed prefixes are never combined into casewise success. The complete `filter=all` jobs snapshot includes authenticated UTC start fences for every workflow attempt. A cached sibling advertised with a newer job ID/attempt is recognized only when its complete successful execution finished strictly before that attempt and exactly matches one unique earlier execution's controlled name, API head, runner, timestamps and ordered steps. Advertised IDs alone do not establish a new execution or artifact owner. A gate-only rerun may admit the previous complete actual hybrid attempt; rerunning hybrid repeats its whole complete plan. This transition temporarily removes partition-job recovery granularity while retaining all five logical slots and the complete framework obligation. The 90-minute job limit remains unchanged; source review and earlier local timings do not prove that the final CI job fits it. Actual CI duration and selective-rerun behavior remain separately required integration evidence. Rationale: [DD-068](../adr/current/DD-068.md).

Pull-request admission keeps the synthetic merge checkout/artifact source bound to `GITHUB_SHA` while the Actions job API head must match the original immutable runner event's PR head. The target repository must match and the checkout must have exactly two ordered parents equal to that event's base and head. Push and reusable tag validation require the same checkout/API head commit. No moving PR REST ref supplies historical identity. The required external check contexts remain `Supply chain security`, `Commit messages`, `build-test-package`, `CodeQL (csharp)` and `CodeQL (actions)`; the hybrid job is an internal prerequisite of the existing aggregate. This source change does not modify remote branch rules, authorize a release or establish a successful new-head CI run. The reusable release caller retains read-only Actions capability; publication keeps its separate contents-write boundary.

The separate [CodeQL workflow](../../.github/workflows/codeql.yml) analyzes C# and Actions for PR/main and scheduled runs. C# extraction builds the plugin, regression project, API probe, release tool, testing tool and its tests with .NET 10 on Windows, then verifies a representative source entry for each in its database archive. Actions analysis needs no build. These are declared workflow contracts; successful actual runs and initial scan findings must be reviewed before their emitted contexts become required under [repository governance](../policies/repository-governance.md).

[Release](../../.github/workflows/dotnet.yml) admits only new, nondeleted, nonforced annotated canonical stable `vM.m.p` pushes, without prerelease/build/fourth-component aliases. The [release tool](../../tools/FishAudioRelease/README.md) verifies Int32 component bounds, original pushed and remote tag objects, peeled commit, event/checkout identity, main ancestry and exact source/packaged manifest versions. STranslate 2.0.10's upgrade parser and marketplace URL construction motivate stable-only admission. The workflow reuses complete Validation at the tagged commit; ordinary PR/main runs do not publish.

For a release validation, the freshly built SPKG is canonicalized by sorting its entries, fixing ZIP timestamps/attributes and using no compression, preserving every entry name and uncompressed byte. This makes container metadata independent of build time/order; it does not normalize or rebuild the payload. Unsafe, duplicate and case-colliding names fail. The canonical package is verified before artifact upload. Its unique name includes the verified SHA, run ID and validation attempt and flows through reusable workflow outputs; publication-only reruns consume the original successful validation output instead of guessing the current attempt's name. Uncompressed containers can be larger than SDK-produced compressed packages.

The publisher downloads that exact artifact and does not rebuild or transform it. It generates English `What's Changed` scaffolding around the unique matching dated Changelog body, optionally retains generated contributor bullets and links the latest published stable comparison. Fenced fake headings, duplicate/invalid dates and empty changes fail. It creates or resumes a matching draft, verifies uploaded package bytes while draft, rechecks remote tag identity and only then publishes stable with the exact tag title. Already-published matching reruns verify classification, package bytes and tag identity before skipping unchanged. Failures never delete releases or tags. Only publication has contents-write permission and uses the built-in token; same-tag runs queue.

The [API probe](../../tools/FishAudioProbe/README.md) self-tests exercise free-model/deadline guards, redaction and bounded evidence capture through local fixtures. The release helper self-tests use fake Git/GitHub/HTTP boundaries for notes, event admission, transaction order, package identity/canonicalization, reruns and token redirect isolation. Passing them does not claim an actual publication or installation. This migration creates no real release tag or GitHub Release.

The [release policy](../policies/releases.md) owns changelog editing and publication procedures: Unreleased contains cumulative net changes from the latest verified published stable release, under canonical English category headings with Chinese prose; published historical sections remain intact. No automatic version bump or release date is inferred. Checks cover the final intended state under the [verification policy](../policies/verification.md).
