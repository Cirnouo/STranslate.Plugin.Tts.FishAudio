# Test system and staged-tree commit validation

Status: current Unreleased bootstrap implementation. The product regressions still use the executable [runner](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Program.cs) and explicit [catalog](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Runner/RegressionCatalog.cs). The local commit gate conservatively builds the exact staged snapshot and runs the complete legacy catalog. NUnit discovery, test-impact analysis and reusable formal baselines are later migration stages; this bootstrap does not claim that they are implemented. The [verification policy](../policies/verification.md) owns contributor obligations, and the [build specification](build-and-release.md) owns package and CI behavior.

## Frozen staged tree

The unit validated by a commit is the Git index tree, called `S` here. It is neither the live working directory nor merely the current HEAD commit. The existing pre-commit hook runs first, then the gate captures `S`, validates it and requires that same tree again before success. Existing prepare/message hooks retain their normal Git order. The final commit-msg guard runs after the prior commit-msg hook and rejects any change to the validated index. A prior hook failure or a change to `S` blocks the commit. Unstaged changes and untracked files are excluded from the test source snapshot, including when they would make a live working-directory run pass.

An ordinary commit captures `S` itself. A caller that has already frozen the intended staged state may set `FISHAUDIO_EXPECTED_TREE` to the output of `git write-tree`; the gate requires the actual staged tree to equal that value. The environment value does not replace the actual index check. Changing staged files after freezing them requires a new freeze and validation.

The snapshot is materialized from the selected tree's raw Git blob bytes, without checkout filters or line-ending normalization. This preserves captured evidence and other byte-sensitive fixtures. The gate does not copy live working files or include untracked helpers. Build outputs and reports are private run artifacts, not staged sources.

Source files and build outputs use a short temporary directory named `fa-s-<run-id>` under the process's temporary directory. They are independent of the repository's Git-private evidence directory so a deep worktree/Git path does not lengthen the Windows runner apphost path. Before materializing sources, the gate rejects a runner apphost path of 260 characters or more. This is an execution-path preflight, not evidence that a build or regression run succeeded.

## Snapshot-root identity

The gate supplies `FISHAUDIO_SNAPSHOT_CONTEXT` as the path to a private JSON context file with `schemaVersion: 1`, the explicit snapshot `root`, staged `tree`, `sourceCommit` and tracked `files`. The source commit records provenance; it does not replace `S` when the index contains uncommitted changes.

The runner binds repository-contract lookup and source reporting to that context. A snapshot lookup is confined to the explicit snapshot root and listed files. A missing source, specification, fixture or other repository file fails there; lookup must not walk upward into a live ancestor checkout or another repository to obtain a passing result. The source report marks `snapshot=true` and identifies the supplied tree and source commit. Snapshot recognition establishes source identity only and is not a formal test-impact baseline.

## Hook installation and execution

[Install-TestHooks.ps1](../../tools/Install-TestHooks.ps1) exposes `-Install` and `-Check`, with optional `-RepositoryRoot <path>` on either operation. Installation creates worktree-private hook state, including a private copy of the tracked [TestGate.ps1](../../tools/TestGate.ps1), and installs the tracked [pre-commit entry](../../.githooks/pre-commit) and [commit-msg entry](../../.githooks/commit-msg). Existing pre-commit runs before validation. Existing prepare/message hooks retain their normal order and failure behavior; prior commit-msg runs before the final receipt guard. Each worktree installs and checks its own hooks.

The check verifies the installed chain and exit-code plumbing. It does not run product regressions and cannot establish a passing build, package or test result. A subsequent ordinary `git commit` executes the gate. No tests run at pre-push, and installation does not authorize a commit, push or release.

The current gate mode is `bootstrap/full/legacy-runner`. After checking `S` and materializing its snapshot, the gate launches that snapshot's `build.ps1 -Release -Test -TestResults <private-report>`. The build inspects the freshly produced distributable and the runner executes the complete catalog using its existing process isolation, action deadlines, assertions and cleanup. There is no affected-case selection or previous-result reuse in this gate. Documentation-only commits use the same conservative full mode.

The same snapshot's built runner then handles `--verify-snapshot-report <private-report> <S>` through [RegressionSnapshotVerifier](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Runner/RegressionSnapshotVerifier.cs). This is a metadata/evidence check that never invokes scenarios. It reads the authoritative report with the runner's generation reader and requires completion, the exact ordered current catalog IDs and partitions, passing outcomes, matching snapshot source identity, Release configuration and the built SDK. A passing subset report cannot establish full-catalog success.

After validation and the final pre-commit index check, the gate writes a receipt identifying the successful run, `S`, original index path and index-file hash. The commit-msg entry runs the preserved prior message hook, then requires a completed successful gate manifest and that same actual tree, index path and hash. It consumes the receipt after a successful check. This final guard catches index changes made by prepare/message hooks and does not build or run tests again.

## Results and failure boundaries

Per-run state is under the repository's private `git --git-path fish-audio-testing/runs/<uuid>` location. A gate manifest records `schemaVersion: 1`, mode `bootstrap/full/legacy-runner`, `snapshotTree`, `sourceCommit`, completion, exit code and references to raw runner reports and logs. Controlled failure diagnostics retain stage/reason tokens and exception types without arbitrary exception text. Preserve the raw reports and their immutable generation sidecars together: the generation reader establishes the authoritative latest committed evidence rather than trusting a stale requested JSON projection. Public documentation and diagnostics must not disclose private machine paths, credentials, user text or signed resource URLs.

After publishing a failed child's authoritative snapshots and final event, the runner attempts an optional `.child.json.failure-<ordinal>.json` sidecar within the existing shared exit/drain allowance. It binds the request, run, case and source identities to at most twelve physical frames from the test assembly (filename only, source line, type and method) and strictly validated fixed native-keyboard context. Missing symbols remain partial metadata. Exception messages, raw stack text, arbitrary exception data and absolute paths are excluded. The evidence collector preserves these sidecars byte for byte; they never establish test outcomes, replace the original exception or make a failed run complete.

Before source cleanup, the gate retains an available snapshot distributable as `package.spkg` in the private run directory and records its SHA-256 in the gate manifest. This also preserves a package produced before a later regression or validation failure. Retention does not establish that the build, package checks or regressions passed; the recorded current outcomes establish those claims. A run that produced no package, or whose retention failed, may have no retained distributable. Reports, context, logs and a retained package remain separate from the temporary source/build directory.

The gate cleans its owned temporary source/build directory on success and failure, requiring creation ownership, checking the resolved directory's parent and run-specific name, and rejecting a reparse-point root before recursive removal. Cleanup must not remove a pre-existing or foreign directory and must preserve an earlier validation failure. Package-retention failure must not prevent the independent source-cleanup attempt. Cleanup failure prevents a successful gate result. The retained snapshot context records provenance after cleanup; its temporary root is not a permanently retained checkout or a reusable baseline.

A pass requires completed successful build/package/regression execution for `S`, exact full-catalog evidence and the final receipt guard's unchanged original index tree/path/hash. A nonzero prior hook or child exit, interruption, incomplete evidence, missing snapshot file or staged-tree drift cannot become a pass. A previous gate result is evidence for its recorded tree and invocation; it does not skip a new commit's gate or establish a reusable baseline. The [verification policy](../policies/verification.md#incremental-verification-and-failure-recovery) governs focused diagnostic recovery and accurate reporting of failures and not-run coverage.

## Current CI and later switch points

PR/main CI remains the complete five-partition legacy validation described in [build and release](build-and-release.md#validation-and-publication). This stage changes local commit validation and snapshot identity; it does not enable CI selection, remove required checks or alter release publication.

The planned migration proceeds through separately reviewable switch points: framework discovery must preserve existing behavioral ownership and compatibility coverage; test-impact selection must establish trustworthy source/dependency identities and conservative fallback; formal baseline reuse must have its own validated evidence and admission rules. Until those implementations and their verification are present, the executable catalog, full bootstrap commit gate and complete PR/main legacy CI remain authoritative.
