# Test system and staged-tree commit validation

Status: current Unreleased full hybrid implementation. NUnit owns discovery, fixture lifecycle, assertions and framework results for ordinary new tests. The executable [runner](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Program.cs) and explicit [legacy catalog](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Runner/RegressionCatalog.cs) retain the remaining product scenarios. The local commit gate runs both complete framework catalogs and the complete legacy catalog from its exact staged snapshot. A verified reusable coverage baseline and formal test-impact selection remain later stages. The [verification policy](../policies/verification.md) owns contributor obligations, and the [build specification](build-and-release.md) owns package and CI behavior. [DD-070](../adr/current/DD-070.md) records this transition.

## Framework discovery and execution

[Test.ps1](../../tools/Test.ps1) supports `-Mode Discover` and `-Mode Full`, optional `-CaseId <id[]>`, `-Workers 0..4` (default 4), a fresh absolute `-ResultsDirectory`, `-NoBuild` and `-RepositoryRoot`. It uses the versions pinned in the project files and lock files: NUnit 4.6.1, NUnit3TestAdapter 6.3.1 and Microsoft.NET.Test.Sdk 18.11.0 through VSTest. The exact .NET SDK is selected by [global.json](../../global.json). Both test projects are built in normal Release output with locked restore unless `-NoBuild` is requested; that option requires both test assemblies and the metadata tool's normal Release inputs to exist. Coverage output is separate and cannot satisfy the normal-output preflight.

`-Mode DiscoverCoverage` prepares the separate coverage Release outputs and discovers their catalogs without executing cases. Its default build path restores the profiler pinned by the local tool manifest. It does not collect a full coverage run or publish a baseline. `-Mode Compatibility` delegates the bounded compatibility scenarios described below; ordinary `Full` continues to execute its complete normal framework catalogs without enabling profiling.

The two catalogs belong to [the plugin test project](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/STranslate.Plugin.Tts.FishAudio.Tests.csproj) and [the testing-tool test project](../../tests/FishAudio.Testing.Tests/FishAudio.Testing.Tests.csproj). Ordinary cases use NUnit attributes and require no registration in `RegressionCatalog`. Parameter rows have explicit stable names. A unique `FishAudioCaseId` property supplies a canonical ID when present; otherwise the admitted full name is the ID. Adapter runtime numeric IDs remain discovery metadata and are not stable cross-run keys. Catalog sizes come from fresh discovery rather than fixed case-count constants.

Discovery invokes `dotnet vstest <assembly> --ListTests` with generated runsettings and no case filter. The driver copies the adapter's current `D_` XML dump into its owned phase after the process exits. Metadata sources must not construct execution fixtures, start a Dispatcher or perform runtime I/O. An execution-only constructor marker must remain absent after discovery. `Discover` parses both catalogs and completes without invoking test cases. The [NUnit evidence parser](../../tools/FishAudio.Testing/Evidence/NUnitEvidence.cs) rejects incomplete, non-runnable, ambiguous and duplicate discovery identities.

`Full` without selectors executes both complete discovered catalogs. A focused request resolves exact, unique canonical IDs across those catalogs before execution; unknown, duplicate, ambiguous and empty requests fail. Selected full names are encoded as anchored regular expressions in NUnit TSL quoted literals through an XML writer, preserving quotes, backslashes, XML characters and Unicode. The driver verifies the exact executed NUnit XML and TRX sets independently of console counts. An exit of zero, a display name or a result from another selection cannot establish success. A focused run records assemblies with empty selections without claiming their execution.

For selections that would exceed the command-line limit, `Full -SelectionPath <absolute-json-file>` reads exactly `{ "schemaVersion": 1, "ids": ["canonical-case-id"] }`. This option cannot accompany an explicitly supplied `-CaseId`, and discovery and compatibility modes reject it. The reader rejects unknown or duplicate properties, duplicate or empty IDs, invalid JSON and unsupported sizes; an invalid selection never becomes an all-catalog request. It holds the regular input file against concurrent writes through execution, retains the original bytes as `selection-input.json`, and binds their SHA-256 in the session manifest. The resulting IDs use the same discovery, profile expansion, exact filter and raw-result checks as `-CaseId`; the file is an execution request, not a case registry or an impact map.

Each phase records private argv, raw stdout/stderr, process completion and exit evidence. A waiting [launch shim](../../tools/Invoke-TestProcess.ps1) is assigned to a Windows Job before it receives permission to launch the real target, so target descendants inherit the owner. Both pipes drain independently, and phase completion requires process exit, completed drains and zero remaining Job processes. Failure termination and drains share one ten-second allowance while preserving the primary failure. Metadata and discovery phases have bounded execution; build and aggregate framework execution receive no extra 120-second performance deadline. This process ownership does not replace the [legacy root-action watchdog](build-and-release.md#regression-process-isolation).

The driver captures source identity and DLL hashes before execution and requires them to remain unchanged. With `FISHAUDIO_SNAPSHOT_CONTEXT`, its root must match the explicit context and every listed source must remain present with the recorded content. A successful `manifest.json` records both catalogs, exact selected IDs, completed terminal results, artifact digests, phase outcomes and `baselineClaim=false`. A separate failure manifest retains failed/incomplete outcomes. Results directories and admitted files are never silently reused or overwritten.

Ordinary `Full` execution uses the [external framework process owner](../../tools/FishAudio.Testing/Execution/FrameworkExecutionDriver.cs) around standard VSTest. NUnit continues to own discovery, fixtures, execution and assertions. The owner assigns the waiting launch shim to its Windows Job before releasing the target. Independent host and launcher pipes authenticate their kernel-reported client PID against that specific Job before acknowledging startup. Console capture and stdout forwarding do not deliver lifecycle messages or enforce deadlines.

The assembly test action encloses ordinary per-test setup, body, teardown and per-test disposal. It installs the existing `RegressionActionScope`, preserving asynchronous and shared-STA action ownership from queueing through cleanup. Fixture construction and OneTime callbacks remain under external startup/inter-case/pre-final supervision. Twenty-second warnings, 120-second root-action and separate startup guards retain their existing meanings. A hard failure stops the owned process; late results cannot rehabilitate it. Publication is established independently after real VSTest target exit and consumption of host cleanup messages. Exact XML/TRX admission starts one parent-owned ten-second allowance shared by process exit, both original output drains, report writing and held-input release. Finalization invokes its complete operation on background work, including synchronous work before a Task is returned. It uses only the remainder of that original anchor; noncooperative writes, asynchronous disposal or cancellation callbacks cannot keep the owner waiting after expiry. The producer writes supervisor.json.pending, completes serialization, flush and disposal, releases held result/input guards, and checks the same deadline before publishing supervisor.json. Only that final basename can satisfy supervisor admission. Successful CLI exit is independently required after complete finalization; a temporary or late report cannot rehabilitate a failed CLI. Synchronous filesystem work cannot be forcibly interrupted by this helper, so these combined exit/evidence requirements remain mandatory. `supervisor.json` records selected, passed, failed, timed-out, interrupted and not-run identities, control events, raw digests and process completion without claiming a baseline.

Snapshot executions bind the actual Git tree and caller-validated inventory context. A manual workspace run retains its actual source fingerprint with `sourceTree=null`; the fingerprint is never relabeled as a Git tree. Both forms bind the test DLL. The local gate and CI independently admit supervisor artifacts alongside exact framework results. The [external acceptance harness](../../tools/tests/FrameworkExecutionAcceptance.ps1) consumes an already-built frozen snapshot and fresh discovery manifest. Compatibility/envelope scenarios exercise sync/await/STA lifecycle. Explicit fault scenarios retain failed execution evidence separately from expected-fault acceptance. They do not shorten production deadlines or introduce another test runner.

The compatibility fixtures also retain a supervised legacy child case. Framework-envelope evidence does not establish migration or isolation of the remaining legacy native profiles and cold first-use dependencies. The separate independent parallel pair uses a bounded rendezvous only when both cases are selected with at least two workers; ordinary serial execution still runs its product assertions. Its monotonic interval/thread evidence describes scheduling in that invocation, not a performance threshold or a product coverage baseline.

The test-only [PopupCloseObserver](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/TestInfrastructure/PopupCloseObserver.cs) has separate initial RED and subsequent four-case focused GREEN evidence from its [native Closed boundary cases](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/NUnitCompatibility/PopupCloseObserverCases.cs). Those cases verify actual Popup.Closed and retired popup HwndSource before owner disposal, including no-animation and already-closing lifetimes, close-failure identity and preservation of a primary body failure. IsOpen=false alone does not complete that boundary. The first integration retains both Language By-ID popup owners until their actual Closed events, and uses a fresh observer for each Search geometry width before disposing the source and VM. Search reuses the existing awaited viewport observer; the original synchronous matrix observer, first-use order, assertions and execution budgets remain unchanged. A separate focused run passed both original diagnostic cases and the complete 147-case native-popups profile on its recorded snapshot. These results do not replace the full hybrid gate. Other lifecycle paths and the Attach helper's pre-return failure cleanup remain outside this change. The historical Alt before-action mismatch remains unresolved; neither this result nor the helper tests establish its cause or prove that all native cleanup has been corrected.

### Execution metadata and phase planning

The [execution metadata reader](../../tools/FishAudio.Testing/Evidence/NUnitExecutionMetadata.cs) reads the current raw adapter dump and preserves each admitted canonical ID, full name and fixture identity. It handles only four execution properties: inherited `FishAudioFreshHost=true`, `FishAudioExecutionProfile`, `FishAudioProfileOrdinal` and the union of `FishAudioExclusiveResource` values. Profile and resource keys use bounded lowercase ASCII letters, digits, dots, underscores and hyphens. Duplicate or conflicting scalar properties, incomplete profiles and noncanonical ordinals are rejected. Profile ordinals must form one unique, complete zero-based sequence. Existing coverage declarations retain their separate leaf-only interpretation.

The [phase planner](../../tools/FishAudio.Testing/Evidence/NUnitExecutionPlan.cs) accepts specific current canonical IDs. Selecting a profile leaf expands that complete profile with an explicit `complete-profile` reason and orders its phase by ordinal. A fresh nonprofile leaf gets its own phase; it does not share one fresh process with its entire fixture. Ordinary cases share a phase, with concurrency limited to one when any member declares an exclusive resource. The planner checks the exact disjoint phase union and binds its result to the original discovery file's SHA-256. These are execution dependencies, not a file-to-suite impact table or evidence that execution occurred.

The metadata CLI supports `evidence-execution-metadata --discovery <absolute-raw-dump> --output <fresh-absolute-json>` and `evidence-execution-plan --discovery <absolute-raw-dump> --selection <absolute-json> --output <fresh-absolute-json>`. The plan selection has `schemaVersion: 1`, a nonempty `ids` array and integer `maximumConcurrency` from one through four. An unknown or duplicate ID, malformed metadata, empty request or invalid concurrency fails before publishing an output. Raw discovery bytes are not rewritten.

`Full` uses those plans and emits session schema 2; `Discover` and `DiscoverCoverage` retain schema 1. Each assembly records the requested selection, expanded selection, captured raw discovery and plan with their digests. Every execution phase owns an exact filter, runsettings, supervised request, runtime directory, NUnit XML, TRX, supervisor and independently verified terminal record. Fresh nonprofile cases run in separate processes. Complete profiles run in ordinal order with one worker. Ordinary phases retain framework parallelism unless an exclusive resource requires serialization. `-Workers 0` retains NUnit's serial execution setting. A phase result belongs only to its declared selection; the assembly result is the disjoint union of admitted phases, without synthesizing a merged raw report.

The installed hybrid gate rebuilds each plan from captured discovery. CI rebuilds it from both captured and fresh discovery, allowing adapter runtime IDs to change while requiring the same canonical identities, full names, selection expansion, reasons, phase order, resources and execution policy. [Assert-FrameworkExecutionPlan.ps1](../../tools/Assert-FrameworkExecutionPlan.ps1) rejects malformed or inconsistent plans and phase records. Each phase request must also bind its ordered canonical IDs and full names to the independently admitted catalog; matching case counts or a self-consistent request/supervisor pair cannot establish that binding. The existing source, process, raw-result and receipt checks remain required. No phase, coverage session or derived union claims a complete baseline.

The metadata command `evidence-hybrid-plan --reference <legacy-reference> --legacy <current-catalog> --discoveries <discovery-paths> --migrations <migration-records> --output <fresh-json>` derives transitional execution ownership. It preserves the original five logical partition slots, requires a migrated native slot's complete successor union to match one ordered, desktop-exclusive, single-worker profile in one assembly, and assigns every other discovered framework case to one disjoint tail. The current legacy catalog must preserve its original retained order; partial native retirement, duplicate ownership, missing successors and split profiles fail. This command records input digests and does not execute scenarios or authenticate their source/build freshness.

The runner's metadata-only `--verify-snapshot-partition-report <report> <tree> --partition <name> [--catalog-output <fresh-json>]` admits one nonempty current legacy partition through the existing authoritative generation reader. It compares the actual snapshot or live source identity, full-catalog dirty scope, Release configuration, SDK, exact ordered partition IDs and passing terminal results. Its optional export includes that actual source, run ID and admitted generation. The full gate and CI independently admit these remaining legacy owners alongside migrated framework owners through the complete current hybrid plan. Native retirement still requires its exact verified successor ownership; these metadata APIs alone do not establish execution or a baseline.

Failure manifests distinguish admitted passes, phases not started and attempted phases whose evidence remains unresolved. A planning failure retains the known selection as not started with `planningUnresolvedIds`; it cannot turn a rejected plan into an empty successful run. An observed failure in the two-case fresh-host probe under `StopOnError=true` caused the pinned adapter to report a stop timeout and then reach the external cleanup deadline without publishing raw results. A bounded diagnostic changing only `StopOnError` to false produced both terminal results. This observation does not establish a general root cause or fix; production fail-stop behavior and the external deadlines remain unchanged, and incomplete evidence still rejects the run.

The four framework-specific installed-hook faults also have ordinary named NUnit rows in [FrameworkHookAdmissionCases](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/NUnitCompatibility/FrameworkHookAdmissionCases.cs): platform command failure, missing terminal results, the wrong case, and late evidence mutation. They reuse the existing signed disposable-repository process owner. These new checks have no original migration ordinal; the original hook scenarios retain their existing responsibilities during migration.

New framework supervisor reports retain the exact held request bytes' SHA-256 and the actual concurrency/order policy passed to the watchdog. Callers of [Assert-FrameworkSupervisor.ps1](../../tools/Assert-FrameworkSupervisor.ps1) can supply all four optional policy-binding arguments: request path, request SHA-256, expected concurrency and expected order. Partial bindings are rejected. A complete binding verifies request/source/case identities, output relationships, policy and observed lifecycle/case order as well as the existing successful process and raw-result boundary. Historical version-one reports without these arguments retain only their previous admission boundary and establish no new fresh-host or ordered-profile claim. No timeout, cleanup allowance or native first-use rule changes here.

## Compiler and coverage evidence
The [build source inventory](../../tools/FishAudio.Testing/Evidence/BuildSourceInventory.cs) binds caller-supplied source/build identities, tracked-file hashes, compiler-document maps and generated-source roots to an explicit matching DLL/PDB pair. Tracked documents must match trusted hashes; missing tracked inputs cannot be replaced by generated files. Generated documents must belong to exactly one declared root. Coverage builds enable `EmitCompilerGeneratedFiles` in [Directory.Build.props](../../Directory.Build.props) so these bytes remain available. The [portable PDB reader](../../tools/FishAudio.Testing/Evidence/PortablePdbSource.cs) checks source bytes against compiler checksums and retains method tokens, sequence points and async kickoff associations.

The [PE method inventory](../../tools/FishAudio.Testing/Evidence/PeMethodInventory.cs) reads the held DLL/PDB pair without executing it. MethodDef tokens remain scoped to the complete binary identity. Structural signatures retain AssemblyRef identities, resolution scopes, generic positions and constraints, parameter flags, accessor relations and PDB kickoff links. Constructors, generated methods and definitions without IL bodies remain distinct; unsupported relationships retain unresolved reasons. File, text, nesting and cumulative-work bounds include repeatedly decoded array shapes.

The [source-candidate reader](../../tools/FishAudio.Testing/Evidence/CoverageSourceCandidates.cs) independently reimports the raw isolated session and binds its Product identity to that metadata and checksum-verified documents. Aggregate container counts do not create method edges. Namespace fragments are validated and joined in their original order before Type segments, followed by an exact, unique full PE type-name lookup. Reversed, foreign and post-Type namespaces remain unresolved. Supported member hints retain all matching overloads; unknown members retain explicit type or assembly scopes for later conservative expansion. Constructors, accessors and async associations come from metadata. PDB positions describe compiler provenance, not executed source lines. Candidate-reference and sequence-point limits bound parsing work without adding test execution deadlines.

Schema-1 PE evidence uses the AssemblyRef Flags uint32 V1 encoding. Only `PeAssemblyReferenceIdentity.Flags` has the dedicated converter: it writes an unquoted unsigned 32-bit integer and rejects non-integer, quoted, negative and overflowing values. Unknown bits remain raw metadata; this does not establish PE validity. Other enums keep the caller's strict string policy. The converter validates occurring values; outer schema admission owns field presence. Tool and artifact identities bind this encoding, so older string-flags artifacts require explicit revalidation.

Empty Product coverage requires a repository-resource explanation and matching dependency bytes. The independent importer also requires hash-verified discovery declarations for that canonical case: exactly one `RepositoryResourcesOnly` reason and a unique, complete matching dependency set. A supplied explanation cannot exempt an undeclared Product case. Unknown symbols with observed Product coverage remain unresolved work, rather than legal empty coverage.

These readers retain caller-supplied authority. Their path, byte and metadata checks do not authenticate the complete compiler, generator or dependency input closure. `BuildInputClosureProven`, `GeneratorInputClosureProven`, `SourceMappingsResolved`, `CompleteBaseline` and `BaselineClaim` remain false. Test execution, collection, source-candidate import and baseline publication have separate outcomes; a passing isolated sample does not publish a complete baseline or activate TIA.

## Signed Git fixtures

All real commit writers, including disposable fixtures, request signatures. Normal repository commits keep the contributor's configured key. Test fixtures use [GitFixtureSigning](../../tools/FishAudio.Testing/Fixtures/GitFixtureSigning.cs) with a separate, freshly generated Ed25519 SSH test key and allowed-signers file. The helper supplies command-level configuration; it does not mutate global Git configuration or own a new test runner, agent or deadline. Runtime generation uses the fixture's existing process owner. Discovery generates no key and starts no process.

The foreign-checkout owner and hook acceptance keep ordinary `git commit -S`; successful hook acceptance still requires the real installed hook and receipt chain before verifying the exact resulting OID. Tree-object fixtures use `git commit-tree -S` only to replace their former raw fixture-object writer. This plumbing path is not used for normal code commits or hook acceptance. Every created object must pass `git verify-commit` using its fixture's exact public-key trust context. Signing materials use a separate Temp sibling outside fixture archives; cleanup validates ownership and deletes only known material files. Subprocesses omit `SSH_AUTH_SOCK`, so these fixtures do not borrow a user agent. No unsigned fallback exists.

The normal executable resolver prefers the SSH key generator bundled with the resolved Git installation. Explicit `FISHAUDIO_TEST_GIT_EXECUTABLE` and `FISHAUDIO_TEST_SSH_KEYGEN_EXECUTABLE` paths support controlled diagnostics; invalid overrides fail. The Git installation therefore needs SSH commit-signing support. The actual binary identities and signed-object results belong to execution evidence, not a claim that every installed Git version is compatible.

## Frozen staged tree

The unit validated by a commit is the Git index tree, called `S` here. It is neither the live working directory nor merely the current HEAD commit. The existing pre-commit hook runs first, then the gate captures `S`, validates it and requires that same tree again before success. Existing prepare/message hooks retain their normal Git order. The final commit-msg guard runs after the prior commit-msg hook and rejects any change to the validated index. A prior hook failure or a change to `S` blocks the commit. Unstaged changes and untracked files are excluded from the test source snapshot, including when they would make a live working-directory run pass.

An ordinary commit captures `S` itself. A caller that has already frozen the intended staged state may set `FISHAUDIO_EXPECTED_TREE` to the output of `git write-tree`; the gate requires the actual staged tree to equal that value. The environment value does not replace the actual index check. Changing staged files after freezing them requires a new freeze and validation.

The snapshot is materialized from the selected tree's raw Git blob bytes, without checkout filters or line-ending normalization. This preserves captured evidence and other byte-sensitive fixtures. The gate does not copy live working files or include untracked helpers. Build outputs and reports are private run artifacts, not staged sources.

Source files and build outputs use a short temporary directory named `fa-s-<run-id>` under the process's temporary directory. They are independent of the repository's Git-private evidence directory so a deep worktree/Git path does not lengthen the Windows runner apphost path. Before materializing sources, the gate rejects a runner apphost path of 260 characters or more. This is an execution-path preflight, not evidence that a build or regression run succeeded.

## Snapshot-root identity

The gate supplies `FISHAUDIO_SNAPSHOT_CONTEXT` as the path to a private JSON context file with `schemaVersion: 1`, the explicit snapshot `root`, staged `tree`, `sourceCommit` and tracked `files`. The source commit records provenance; it does not replace `S` when the index contains uncommitted changes.

The legacy runner and framework driver bind repository input lookup and source reporting to that context. A snapshot lookup is confined to the explicit snapshot root and listed files. A missing source, specification, fixture or other repository file fails there; lookup must not walk upward into a live ancestor checkout or another repository to obtain a passing result. Framework evidence additionally binds the validated root and context-file SHA-256. The source report marks `snapshot=true` and identifies the supplied tree and source commit. Snapshot recognition establishes source identity only and is not a formal test-impact baseline.

## Hook installation and execution

[Install-TestHooks.ps1](../../tools/Install-TestHooks.ps1) exposes `-Install` and `-Check`, with optional `-RepositoryRoot <path>` on either operation. Installation creates worktree-private hook state, including a private copy of the tracked [TestGate.ps1](../../tools/TestGate.ps1), and installs the tracked [pre-commit entry](../../.githooks/pre-commit) and [commit-msg entry](../../.githooks/commit-msg). Existing pre-commit runs before validation. Existing prepare/message hooks retain their normal order and failure behavior; prior commit-msg runs before the final receipt guard. Each worktree installs and checks its own hooks.

Installation schema 2 requires gate protocol version 3. Reinstall an older worktree-private copy with `-Install`, then run `-Check`. Installation prepares a fresh immutable bundle containing both hook entries, TestGate.ps1 and the minimal HybridReceipt.ps1 consumer; it checks copied digests, renames the complete bundle, then switches the worktree hooksPath once. Existing bundles remain intact. A failed preparation does not activate partial files. Schema-1/protocol-2 installations and inherited managed worktree paths resolve to their preserved original hook chain. The existing multi-worktree configuration safeguard remains. No pre-push test entry is installed.

`-Check` requires the actual effective bundle, repository/common-directory ownership, protocol and all four tracked/installed file digests, then checks one-use exit-code challenges. It runs no product tests. A successful source check does not establish a package, regression or baseline result. Hook entries resolve the invoking worktree's actual effective hooks directory; an inherited foreign installation cannot claim ownership of a linked worktree.

The current gate mode remains `bootstrap/full/hybrid`. After the prior pre-commit hook, it captures `S` and materializes raw blob bytes as before. It separately invokes the snapshot's `build.ps1 -Release`, which builds and inspects the current distributable without executing legacy scenarios. The same two test projects then build with the standard normal Release flags. The snapshot's `tools/TestHybrid.ps1 -NoBuild` uses the existing Test.ps1 framework and generation-aware legacy runner to execute the complete fixed logical slot plan followed by its disjoint framework tail. Every current legacy owner and every discovered NUnit leaf must be covered exactly once. A migrated native profile stays in its original ordered slot and is excluded from the ordinary tail. Planning derives the current catalogs and pinned migration identities; it does not assume that the native migration has already happened.

The outer phase wrapper reuses the existing waiting launcher and Windows Job owner before GO. Genuine target exit, original stdout/stderr drains and an empty Job are required. A nonzero target exit is latched before descendant cleanup, retaining the actual target exit code. Remaining cleanup uses the same original target-exit anchor; no retry, warmup, additional test action deadline or renewed ten-second allowance is introduced. This boundary rejects incomplete execution; it cannot repair an external process termination.

The snapshot's independent `Assert-HybridSession.ps1` then obtains fresh metadata/current catalogs and reconstructs the full owner union. It uses the real partition-report verifier and existing framework plan/request/supervisor/XML/TRX readers. Source/build identity, exact current selections, order, phase policy, actual raw results and zero-selected other assemblies remain admission requirements. Producer complete flags or passed counts alone are insufficient. No synthesized complete legacy report or merged framework result substitutes for these owners.

The gate retains the authoritative admission, all raw and fresh verification artifacts, the snapshot context and current package in its private run directory. Every returned retained artifact must stay inside that run root. Source/build identities are data pins; deleted snapshot DLL paths are not final receipt artifacts. The installed minimal receipt consumer has no scenario runner, metadata tool, compiler or snapshot-root lookup. Its code digest and installation descriptor digest are bound into the completed gate manifest.

The protocol-3 receipt freezes that completed manifest's SHA-256, `S`, actual index path and index-file SHA-256. After the prior commit-msg hook, the final guard loads only the digest-bound installed consumer, holds the index and retained evidence, and checks both frozen bytes and the actual physical attempt/committed-generation inventories. A newly added failed generation or unlisted later attempt cannot borrow an earlier pass merely because existing artifact hashes remain unchanged. It repeats the directory-set guard immediately before consuming the receipt. No source snapshot or build output is required after cleanup, and no build/test/discovery is repeated at commit-msg.

The public `build.ps1 -Release -Clean -Test` route uses the same TestHybrid producer and independent consumer after current package inspection. The producer performs the standard build/Discover preparation once. The former unconditional legacy-then-all-framework layout is removed, preventing a native profile from running in both its fixed slot and the tail. Explicit legacy selectors, result/rerun/affected options and `-LegacyOnly` remain clearly labelled diagnostics; they do not claim complete hybrid validation. Debug `-Test` likewise retains its diagnostic legacy meaning. This local routing change does not redesign or upgrade CI.

## Results and failure boundaries

Per-run state is under the repository's private `git --git-path fish-audio-testing/runs/<uuid>` location. A gate manifest records `schemaVersion: 1`, `gateProtocolVersion: 3`, mode `bootstrap/full/hybrid`, `snapshotTree`, `sourceCommit`, completion, exit code, full hybrid verification, retained artifact/inventory digests and references to raw reports/logs. Preserve the complete hybrid session and independent admission records, including framework raw phases, legacy reports and immutable generation sidecars. The generation reader establishes the authoritative latest committed legacy evidence rather than trusting a stale requested JSON projection. Controlled diagnostics retain stage/reason tokens and exception types without arbitrary exception text. Public documentation and diagnostics must not disclose private machine paths, credentials, user text or signed resource URLs.

After publishing a failed child's authoritative snapshots and final event, the runner attempts an optional `.child.json.failure-<ordinal>.json` sidecar within the existing shared exit/drain allowance. It binds the request, run, case and source identities to at most twelve physical frames from the test assembly (filename only, source line, type and method) and strictly validated fixed native-keyboard context. An individual native down-bit mismatch can retain the fixed before/after-action phase, one approved controlled-key ID and planned/table/native down-state booleans from the existing reads. This default version-1 diagnostic adds no resampling, message pumping, state repair or retry; the original comparison, failure and restoration remain authoritative. Missing symbols remain partial metadata. Exception messages, raw stack text, arbitrary exception data and absolute paths are excluded. The evidence collector preserves these sidecars byte for byte; they never establish test outcomes, replace the original exception or make a failed run complete.

The real HWND keyboard-table transaction now enforces its synchronous no-pump boundary with the owning Dispatcher's DisableProcessing scope, after the original initial native-context verification and before capture. The same scope retains apply, strict pre/post comparisons, the action, optional follow-up, full restoration and original exception propagation. It does not add a pump, warmup, state repair, retry or execution allowance. The fake API overloads retain their existing behavior. Twenty-two focused guard cases passed complete XML/TRX admission, including an actual rejected nested Dispatcher frame, full-table restoration, original strict mismatch and processing release; deliberate fake-mismatch stderr is captured and exactly asserted. A separately frozen opt-in experiment passed all 147 original native-popup cases in their original order. That observation covers the Search and native keyboard-peer callers; InputClear's native-settings paths remain outside that focused profile and require the full staged-tree gate. The default route has no bypass switch. This establishes a fixture boundary and limited compatibility evidence, without identifying the cause of earlier Shift, Alt or mouse down-bit failures.

For a separately recorded native investigation, `FISHAUDIO_NATIVE_KEYBOARD_FOLLOW_UP=1` explicitly enables one [optional follow-up](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/TestInfrastructure/NativeKeyboardFollowUp.cs). The real HWND entry reads the switch before its transaction and retains only the API owner's already captured thread identities. After the first strict down-bit mismatch has produced its original failure, the helper performs at most one additional table read and one query for that same approved key, before ordinary diagnostic formatting or publication. It records only the ten controlled Down bits and the same key's subsequent table/native booleans. Failed sampling is unavailable evidence; later agreement cannot recover the failure, execute its skipped action or retry restoration. A validated projection uses sidecar version 2 and twelve fixed primitive fields, without serializing an exception, arbitrary Data, a raw table or unrelated key identities. Publication remains after the authoritative failed result within the original shared exit/drain allowance. An unrecognized nonempty switch fails. Five offline helper/integration cases and fifteen existing default-mode diagnostic cases passed on their recorded build. A single ordered native investigation subsequently reproduced the caption/keyboard case failure and retained a changed later table value; it did not establish a cause or fix. This switch is a diagnostic experiment, not a complete-gate or baseline admission path, and does not authorize automatic reruns.

Before source cleanup, the gate retains an available snapshot distributable as `package.spkg` in the private run directory and records its SHA-256 in the gate manifest. This also preserves a package produced before a later regression or validation failure. Retention does not establish that the build, package checks or regressions passed; the recorded current outcomes establish those claims. A run that produced no package, or whose retention failed, may have no retained distributable. Reports, context, logs and a retained package remain separate from the temporary source/build directory.

The gate cleans its owned temporary source/build directory on success and failure, requiring creation ownership, checking the resolved directory's parent and run-specific name, and rejecting a reparse-point root before recursive removal. Cleanup must not remove a pre-existing or foreign directory and must preserve an earlier validation failure. Package-retention failure must not prevent the independent source-cleanup attempt. Cleanup failure prevents a successful gate result. The retained snapshot context records provenance after cleanup; its temporary root is not a permanently retained checkout or a reusable baseline.

A pass requires completed successful build/package execution for `S`, independently admitted complete coverage of all current legacy and NUnit owners through the hybrid plan, and the final receipt guard's unchanged index, retained bytes and physical inventories. A nonzero prior hook or child exit, interruption, incomplete evidence, missing snapshot file or staged-tree drift cannot become a pass. A previous gate result is evidence for its recorded tree and invocation; it does not skip a new commit's gate or establish a reusable baseline. The [verification policy](../policies/verification.md#incremental-verification-and-failure-recovery) governs focused diagnostic recovery and accurate reporting of failures and not-run coverage.

The installed-hook [acceptance fixture](../../tools/tests/TestHookAcceptance.ps1) uses disposable Git repositories and synthetic build/platform/metadata controls to verify the outer boundary, including command failure, missing terminal evidence and a matching-hash result containing the wrong case. Those controls establish hook and evidence-admission behavior only; product and NUnit execution require their own actual runs.

## Current CI and later switch points

The pinned artifact downloader extracts a single pattern match directly into its destination, and wraps multiple matches in artifact-name directories. Hybrid CI admission supports both explicit layouts. A regular root `ci-owner.json` locates a canonical attempt for the flat layout; only that file and the `session` and `producer-admission` directories are accepted there. Wrapped mode requires canonical hybrid artifact-name directories and rejects loose files. Mixed layouts, unknown entries and reparse points are rejected. Both layouts then use the same full owner/inventory, actual execution/latest-attempt, merge source, current catalog and raw-result checks; a cached advertised attempt does not create a new artifact owner. Raw absolute paths are supported only when the producer and aggregate have the same checked runner roots; byte-preserving restoration is confined to the fresh expected bundle computed from trusted event context.

Pull-request validation binds two distinct identities. The checkout, artifact owner, source manifest and fresh discovery remain bound to `GITHUB_SHA`, the tested synthetic merge commit. Cached-attempt witnesses and failed/unfinished-attempt rejection remain unchanged; no current moving PR REST ref supplies historical identity.
