# Settings and TTS model policy

Status: current Unreleased implementation; schema version is **2**. See [Settings](../../STranslate.Plugin.Tts.FishAudio/Configuration/Settings.cs), [migrator](../../STranslate.Plugin.Tts.FishAudio/Configuration/SettingsMigrator.cs), [converter](../../STranslate.Plugin.Tts.FishAudio/Configuration/SettingsJsonConverter.cs) and [normalizer](../../STranslate.Plugin.Tts.FishAudio/Configuration/SettingsNormalizer.cs).

Canonical JSON writes SchemaVersion first. Missing or invalid version markers are interpreted as legacy version 0. Supported schema 0/1 settings migrate to 2 with MP3 as the missing/malformed/duplicate/unsupported audio-format fallback, preserving valid bitrate. Explicit supported PCM/MP3 choices survive. New configurations and current schema-2 invalid/missing formats default to PCM. Valid current VoiceId/CachedVoice values take precedence over ReferenceId/CachedModel independent of property order; wrong-type current fields may recover valid legacy fields. Ordinary malformed/duplicate properties fall back independently. Supported schemas are canonically saved after migration/normalization or unknown/deleted-field cleanup. A duplicate SchemaVersion or future schema is read-only: compatible fields remain usable in memory but host saves are skipped.

API Key input changes, including clearing the password field, update the ViewModel and settings storage immediately before focus leaves the control. The password binding explicitly uses `TwoWay` and `PropertyChanged`: SDK 1.0.15 already defaults to two-way binding, but its default `LostFocus` update trigger would delay this save. Editing the key does not itself call Fish Audio or clear displayed voices; the [browsing contract](voice-browsing-and-preview.md) retains existing results and selected/favorite metadata while retiring old credential operations.

The API Key card gives its complete native header, Fish Audio link and icon priority in the native Right state; the password field uses the remaining room and stays right-aligned. It grows continuously until reaching the native natural width of the current two-action input. The added clear lane reserves 28 DIP of additional native content padding; the field retains its existing minimum width. Native responsive boundaries, header priority and wrapped/narrow behavior remain intact, including after template replacement. This is scoped to the API Key card; other cards retain their native templates and behavior. See the [compiled API Key layout suite](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/Settings/ApiKeySettingsCardSuite.cs).

API Key, Search and By-ID each have a native 28-DIP icon-only clear action inside the input, immediately before the existing Paste or Adjust action at the four-DIP right inset. Clear is visible exactly when the bound text is nonempty, including spaces. Both action lanes remain reserved when clear is hidden, so long text, password bullets and the caret cannot overlap them and the focused viewport keeps its resting width. Native built-in delete adornments remain disabled locally; the explicit plugin actions retain native hover, keyboard focus, disabled state and localized tooltip/automation text. API Key stays in Hidden password mode. Clear returns focus to its surviving enabled input. The By-ID lookup action remains outside the input and uses the same magnifier as Search. Voice ID typing and both paste paths accept only lowercase hexadecimal drafts up to 32 characters; lookup requires exactly 32. An invalid raw paste is rejected whole without trimming, extraction or case conversion, preserving the current draft/result. API Key clear uses the existing immediate-save setter, saves one effective change and honors the key lock in command availability and execution. Failed persistence or a retired write lease restores the accepted key without retiring its credential operations; accepted clear retains the displayed voices while canceling their old pending credential work. Search clear edits only its draft; By-ID clear uses the existing input generation/error/lookup retirement. Neither saves, queries or clears the selected voice. See the [input clear request](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/Input/InputClearSuite.cs) and [compiled native input](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/Input/InputClearControlSuite.cs) regressions; an ID lookup still only inspects a voice.

The compiled clear-action Space pair runs inside the shared calling-STA native keyboard-table fixture, with verified neutral modifiers and actual released left button. Its full 256-byte snapshot restores before the existing drain, preserving the original native events, actual focus and clear/save/no-query assertions. The input-clear group remains thirty-four separate actions under the common execution profile with 680 seconds of cumulative successful-action allowance. This offline state fixture does not establish physical keyboard or installed-host acceptance.

| Latency | `normal`; supported values `normal`, `balanced`, `low`. |
| Normalize text | false. |
| Audio format | PCM for new configurations; PCM/MP3 choices; legacy migration defaults to MP3. |
| MP3 bitrate | 192; supported values 64/128/192. Retained under PCM; the whole bitrate card is hidden for PCM, visible for MP3, and the value is sent only for MP3. |
| Condition on previous chunks | true; describes chunks within the same synthesis request. |

Non-finite/out-of-range stored numeric values use their defaults; valid values round to the displayed decimal precision with midpoint-away-from-zero rounding. All four values round to two decimal places, and `0.01` interaction steps preserve off-tick values from older configurations. PCM sample rate is fixed at 44100, not exposed as another setting. All new fields participate in conversion, cloning, transactional save/rollback, ViewModel initialization and auto-save. CachedVoice contains selected voice display metadata and a sample URL; it is not an audio-byte cache. Its optional `Languages` array stores normalized language codes, with a backward-compatible empty default and no schema increment. The migrator recognizes this field, salvages valid string entries from mixed arrays, and canonically cleans null/malformed/duplicate or noncanonical values independently of the other cached fields. Language collections are detached read-only values in settings snapshots and leased copies; missing metadata and authoritative empty refreshes cannot retain former codes. Code normalization and provider-order retention follow the [voice language metadata contract](voice-browsing-and-preview.md#voice-language-metadata).

Values that round to zero use positive zero. Volume applies that rule before ViewModel equality and save notifications; supported editor and wheel input and storage normalization use the same precision rule. The slider also preserves native range coercion while correcting near-zero local values, so its native bubble and the resting label show `0.00` from either direction. Valid negative values such as `-0.01` remain negative. Supported writable settings repair a stored negative-zero representation on canonical save; future/duplicate-schema read-only protection remains unchanged, with no schema increment.

For top_p specifically, stored zero and smaller positive values become at least 0.05 after decimal rounding; negative/non-finite/>1 values retain the 0.7 fallback. The shared bounds/default/floor guard also protects native and HTTP payloads from raw in-memory settings, while preserving valid fractional request precision such as 0.82. Storage precision normalization does not change that request-boundary contract. Normal canonical saves repair old values, while future/duplicate schemas remain read-only. Temperature keeps its separate zero-inclusive rule. Both sliders retain aligned physical track endpoints and value labels. See [DD-057](../adr/current/DD-057.md) and the [official range discrepancy](../references/tts-fields.md#nucleus-sampling-boundary).

All four sliders use native click-to-point behavior: clicking the track moves directly to that position at the existing hundredth precision, while native thumb dragging and value tooltips remain active. All four slider values use a reusable inline numeric editor. Before editing, the number appears as text; clicking it opens a same-size input containing that displayed text, while units remain separate. The draft does not update settings until a valid focus-loss or Enter commit. Escape and invalid, empty, non-finite or out-of-range input restore the committed value. The slider immediately reflects a valid commit, and off-tick values such as 0.82 survive save/reload. Parsing follows the display culture with decimal-point fallback. Input accepts only ASCII digits, one decimal separator and a leading minus for Volume. Speed, Temperature and top_p permit at most four characters and two fractional digits; Volume permits six characters and two fractional digits, including `-10.00`. Typing and paste validate the entire proposed draft; invalid clipboard text is rejected rather than truncated. Commit rechecks lexical validity independently. See [DD-059](../adr/current/DD-059.md) and [DD-058](../adr/current/DD-058.md) and the [compiled editor suite](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/Numeric/InlineNumericEditorSuite.cs).

Every resting display button and input is 52 DIP wide and 32 DIP high, with 2-DIP horizontal padding and a fixed 1-DIP border. Resting numbers align right; editing drafts center in the same native 46-DIP viewport. The resting outline is transparent; keyboard focus changes its brush without moving the text. The custom display template honors the control padding and content alignment. Speed's × and Volume's dB both use 11-DIP descriptive text with the dynamic secondary text brush; the number retains its native font size and primary text brush. Units inherit the numeric font family, weight, style and stretch. Their original line allocation derives from that font's metrics. A measured unit-only render translation aligns the actual native glyph outline bottoms with the complete active numeric text, including comma descenders. Read every resolved native glyph run and its placement after pending rendering; retain native text drawing and fallback fonts. Live drafts invalidate alignment; digit-free partial drafts use the committed display as a stable anchor without changing text or settings. A single pending dispatcher callback and per-control context cache cover font, language, flow, formatting, actual DPI, geometry and template changes; unload retires that work and reload measures the latest committed value. The adjacent auto-width unit column has no extra margin: the field's existing 3-DIP right inset supplies the compact layout gap. This allocation is not asserted equal to a literal space advance. Temperature and top_p collapse that column completely. Units retain separate hit and wheel ownership in both states. The outer 270-DIP settings rows and 180-DIP sliders retain their native layout. The native delete adornment stays hidden locally; complete signed dot/comma drafts and both caret positions fit at 100/125/150% actual WPF root DPI. The [compiled typography checks](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/Numeric/NumericTypographySuite.cs) compare every glyph's font, size, paint, numeric placement, horizontal advance and suffix extent with an independent native single-line number/space/11-DIP secondary-unit reference. Preserve that reference's shared baseline as historical characterization; its expected suffix translation now derives independently from actual contour bottoms, within the existing .01-DIP tolerance. Fixed crops of opaque native glyph draws independently check nonzero-alpha support within one physical row for the default Ideal-formatting matrix. Display formatting also retains exact outline alignment and live-context coverage, while its grid-fitted raster support is characterized separately: equal outlines can produce a two-row support difference for comma text and × at 150% DPI. No universal physical-row equality is claimed. Both formatting modes retain fixed ±3-physical-pixel contour and aligned-reference raster displacement probes; Ideal additionally rejects those probes against the number-versus-unit one-row bound. Keep the compact-gap upper bound, runtime theme changes and inert unit hit/wheel routes. These compiled fixtures do not establish installed-host visual or pointer acceptance.

REST metadata, credit and sample downloads retain host HTTP routing. Native WebSocket always uses the system proxy (`HttpClient.DefaultProxy`) and exposes no plugin proxy settings or network group. Former `StreamingProxyMode` and `StreamingProxyAddress` fields are obsolete: their values are ignored and removed on ordinary canonical saves without changing schema 2. Old direct/custom/invalid values cannot affect routing or block synthesis. Future/duplicate-schema read-only protection remains active. Private request values are captured in a class without generated record value printing; raw exception contents and API Keys are never logged. See [DD-055](../adr/current/DD-055.md).

Favorites do not add any Settings property or change schema 2. Their separate ID-only file uses the SDK's persistent `PluginSettingsDirectoryPath`; the shared in-memory metadata cache and existing disposable cover-image cache have different lifetimes. See [voice browsing and preview](voice-browsing-and-preview.md) and [DD-054](../adr/current/DD-054.md).

Audio-format settings use the same native SettingsCard header icon, header, description and content slots as existing settings. [Compiled layout tests](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/Settings/SettingsLayoutSuite.cs) exercise native card geometry and PCM visibility; [installed-host acceptance](../evidences/favorites-host-2026-10-20.md) and [final input/navigation acceptance](../evidences/favorites-controls-host-2026-10-22.md) distinguishes superseded proxy controls from the final interface.

[FishAudioModelPolicy](../../STranslate.Plugin.Tts.FishAudio/Configuration/FishAudioModelPolicy.cs) uses an exclusive cutoff of `2026-12-01T00:00:00Z`. Before it, the ordered list is `s2.1-pro-free`, `drama-3`, `s2.1-pro`, `s2-pro`, `s1`, and the default is `s2.1-pro-free`. At/after it, the list is `drama-3`, `s2.1-pro`, `s2-pro`, `s1`, and the default is `s2.1-pro`. List order and default selection are distinct functions. Existing valid selections are not replaced merely because the list is reordered. An unavailable selection normalizes through the default policy. Streaming checks exact membership before connect/send and during its watchdog, including the free cutoff.

`normalize_loudness` is enabled by the explicit three-model S2-family capability policy. The complete card is hidden and the field omitted for `s1` and `drama-3`, while its stored value survives switching. Official documentation says the field has no effect on S1; Drama 3's effect is unconfirmed, so its omission is client policy rather than proof of provider incompatibility. The description says the setting supports the S2 family. Drama 3 request/UI compatibility has offline coverage; no paid real test is asserted. The promo card has a stable placeholder; clicking selects the free model without dismissing the card, while close persists dismissal. Startup uses local UTC first and a three-second online UTC attempt with local fallback.

**Future maintenance fact, verified 2026-10-20:** the [official native WS page](https://docs.fish.audio/api-reference/endpoint/websocket/tts-live) says S1 is deprecated and retires on December 31, 2026, after which S1 requests are served by S2.1-Pro. The current client list deliberately retains S1; no client migration is implemented here. Revisit the list and user guidance before retirement. Exact client selection cannot override a future provider-side migration.

These are current application rules, not independent evidence of provider billing eligibility. Apply the [zero-cost testing policy](../policies/api-evidence.md) before any real synthesis.

## Numeric wheel interaction

The resting numeric text and its paired slider handle vertical mouse wheel input after continuous hover on that target for at least 350 ms, measured with monotonic elapsed time. Before qualification the event remains unhandled for ordinary page scrolling: values, bubbles and partial-notch accumulation remain unchanged. Leaving/reentering, entering text editing, unloading and template replacement require a fresh dwell. Moving within a slider's track/thumb descendants preserves its continuous hover; moving to the numeric text starts a separate target's dwell.

Once qualified, one complete wheel notch adjusts all four values by 0.01; decimal rounding follows the displayed precision and the result is clamped to the existing bounds. A handled gesture updates the shared bound value and normal auto-save, while preventing page scroll even at a bound. Slider tracks, thumbs and drag ticks use the same precision. Wheel adjustment shows the native thumb value bubble and resets its one-second idle timer; pointer leave, unload or a real drag retires wheel ownership without disrupting real drag feedback. Partial-notch input accumulates only within the qualified current target's hover session and resets on leaving; entering text-edit mode also resets the numeric label's remainder.

The editing TextBox, units and surrounding card retain ordinary page scrolling. A wheel over the slider may update the committed value while a text draft is open; an actual value change cancels that stale draft through the existing external-value rule. At an unchanged bound there is no new value to replace the draft. Existing draft syntax, focus-loss/Enter commit, Escape cancellation and compact display/editor geometry remain active. The shared 0.01 step and two-decimal formatting apply to direct input, dragging and both wheel targets; this is a client interaction policy, not an upstream quantization constraint.

## Project support link

The native Support card links to [this repository](https://github.com/Cirnouo/STranslate.Plugin.Tts.FishAudio) using ordinary keyboard-focusable hyperlink text preceded by the GitHub Octocat vector mark. It uses the same native card content/header layout as the other settings cards. The API Key card retains its Fish Audio link; the Support card does not duplicate it or add an About/update feature.

Navigation opens only that fixed HTTPS repository URI through the default browser. A shell launch failure produces localized transient feedback with default-browser recovery guidance and no raw exception text. The [Octicons mark](https://github.com/primer/octicons/blob/ad7dcd0ec8659f89fc1972dc6c65c571f99c950e/icons/mark-github-16.svg) retains its complete MIT notice in `Assets/Licenses/Octicons.LICENSE.txt` in the plugin package; Git attributes preserve the copied notice bytes. Compiled-control tests use a fake launcher; those checks do not establish actual browser launch on an installed host.

Selected CachedVoice additionally carries nullable UTC `CreatedAt` without advancing schema 2. Its manual nested-field migrator independently clears malformed/wrong-type/duplicate dates and requests canonical cleanup, while old absent/null values remain compatible. Snapshots, leased saves, conditional updates and rollback copy the date with the existing metadata. Future or duplicate schema markers remain read-only. ## Actionable pointer cursors

The plugin's [instance-scoped cursor behavior](../../STranslate.Plugin.Tts.FishAudio/Presentation/View/ActionCursor.cs) answers routed QueryCursor only for enabled, visible, hit-testable actions inside its SettingsView and owned popup surfaces. Buttons, generated combo items, noneditable combo bodies, native ToggleSwitch controls, slider and scrollbar tracks/thumbs, and the explicit promo action show Hand. Native SettingsCard is actionable only when IsClickEnabled is true. Transparent native track regions remain actions: opacity alone does not remove mouse input. Existing avatar sample/active visibility and hit-test gates remain authoritative.

Nearest input/link ownership preserves TextBox, PasswordBox, editable combo text, Hyperlink and HyperlinkButton cursor results. Embedded paste buttons still count as actions. Numeric units, card metadata, passive pills and blank native cards stay passive. No cursor query executes a command, saves settings or changes a value. Styles, templates, focus and wheel routing stay native. Each scope owns its event handlers; each native combo dropdown attaches its current popup surface only while open and detaches on close, unload or scope removal. Temporary child unload removes every dropdown handler and strong entry immediately, retaining only a passive Loaded notification whose combo and scope references are weak. Pending notifications are bounded to one per combo discovered during that scope load (four fixed SettingsView combos). Foreign reloads retain only this passive weak notification, with no active dropdown or query handler on the foreign control. It detaches and restores dropdown handling when that same combo returns under its original still-loaded scope, without resetting the scope. Scope unload or removal disposes all pending notifications, including a removed combo that stays alive and unloaded. Collected controls are never retained by the pending wrapper; no timer, LayoutUpdated polling or repeated full-tree scan is used. There is no application-wide class hook, ForceCursor or root Hand setting. [Compiled routed regressions](../../tests/STranslate.Plugin.Tts.FishAudio.Tests/Suites/Input/ControlCursorSuite.cs) exercise actual template children/InputHitTest, generated popups, native peers and lifecycle cleanup; installed-host physical-pointer behavior is a separate acceptance boundary. The cursor group has thirty-one separately bounded shared-STA actions: construction; six independently hosted workflows in each 320/640-DIP and light/dark context (fresh format/dropdowns, selected/shared Search cards, By-ID cards, Favorites cards, general native controls/inputs and owned overlays); two fixed-500-DIP native parts cases; two independently owned fixed-500-DIP native template-replacement cases; and two combo/scope lifecycle cases. All thirty-one owners, including construction and both continuous Lifecycle cases, use the [common execution profile](../policies/verification.md#test-ownership-and-budget-preflight): 31 × twenty seconds = 620 seconds, excluding separately bounded startup. There is no special lifecycle execution exception. Each workflow owns its ViewModel, compiled view, native source and cleanup. Format starts with PCM and observes the three visible/four visual native combos before its one saved MP3 transition and all four dropdown interactions, before any scope reset. Other workflows construct settings with the resulting MP3 value without a setter/save; general controls and overlays start in Favorites, with overlays then switching to Search. Each workflow retains its own no-query-save check. Card actions retain the complete selected/shared avatar runtime sequence and action/passive-role assertions; general controls retain busy/recovery, native input/link comparisons and numeric editing; overlays retain actual adjustment and language-popup actions, passive pills and scrollbars. Native parts then template replacement run in that order for each theme, followed by the existing two lifecycle actions. The template owner retains a real original dropdown open/layout/generated-item Hand assertion and close before template-null/layout, original-template restore/layout and reopen/current-item Hand assertion. It owns the same native peer construction as the parts owner, rather than an initially unopened combo or synthetic template. Native parts and lifecycle sequences retain both themes, including foreign-to-original return before scope reset and live-unloaded retirement. Every action uses the same execution duration, while failure observation remains separately diagnostic. The existing bounded observer records safe monotonic phases and, after an outer deadline, observes only that same action off the STA for at most twenty seconds while preserving the original failure. A failed Lifecycle envelope is at most about forty seconds excluding startup, and dispatch/logging use the same configured duration. Earlier aggregate and native-peer deadlines remain failed evidence. In the later full gate the combined native parts/template action completed assertions at 5,206 ms and cleanup at 5,208 ms after its five-second outer failure; its separate native routing and template-replacement owners preserve every oracle without identifying a product performance cause. In the later complete gate, the first plugin composite reached source setup at 469 ms, format/dropdowns at 2,893 ms, Search/By-ID/Favorites at 3,876/5,055/6,043 ms, general native controls/inputs at 6,576 ms and owned overlays at 8,496 ms; it completed at 8,501 ms after the outer failure at 5,013 ms. Those measurements motivate these workflow boundaries without establishing the underlying cause or passing the whole gate. The later full-02 Lifecycle/False action failed its five-second envelope at 5,003 ms and completed the original chain, assertions and cleanup at 11,938 ms; this sample stays failed. Local reload, scope reload, foreign reparent, return before scope reset, scope removal and live-unloaded retirement remain one source-owned sequence. The common guard is bounded regression headroom, not a production latency guarantee or observed maximum. Focused cursor verification and final whole-run/current-package verification are separate evidence boundaries.
