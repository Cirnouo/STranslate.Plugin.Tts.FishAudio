# Verification policy

Choose verification that exercises the changed contract. The repository uses an executable regression runner, not a test-discovery framework: new regression scenarios must be invoked by its Program entry point. Keep normal tests deterministic and offline; do not make a credential or provider availability a prerequisite for CI.

- Use fake network/storage/audio boundaries for request shape, cancellation, timeouts, stale results and failure cleanup. Use fixed local fixtures when real decoding is relevant.
- Test asynchronous preview ownership separately from shared Voice ID state: removing the originating card must invalidate its work even when another card has the same ID, and local collection persistence/rebuild must preserve selection until an explicit Apply.
- Run WPF fixtures that share process-global theme resources on one STA Dispatcher with a dispatcher synchronization context; preserve real background-thread completion and command-listener checks.
- For responsive settings changes, exercise the compiled themed controls at narrow and normal widths. Compare icon, header and content geometry with existing native cards, including visible validation text; correct header alignment alone does not establish content alignment. Apply pending binding/layout and responsive visual-state work before measuring.
- For documentation moves, validate local targets, preserved anchors and the existing repository assertions affected by the move. Do not add large sets of source/text assertions that merely mirror the documents.
- For behavioral changes, test meaningful before/after cases and affected compatibility paths. Repeat or broaden checks when the final changes, a failure or an unresolved risk justify it.
- Build/package validation must inspect the package produced by the current sources and configuration, including required dependencies and resource files. A leftover package is not evidence of a successful current build.
- For plugin class libraries, verify private runtime dependencies inside the distributable, not only in the test project's output. The test runner can resolve a NuGet assembly that the package omits. Copy resolved private runtime assets deliberately; do not accidentally bundle a second host contract or UI framework to repair a missing dependency. Missing required runtime files must fail the build rather than emit a warning.
- Validate the final state intended for review and commit. If code, tests, a spec, resources or CHANGELOG changes after a successful check, rerun the affected checks before claiming final verification. Report exactly what was run and any remaining limits.

On Windows with .NET 10, the standard combined release verification is `./build.ps1 -Release -Clean -Test`. Debug is the default; `-Test` runs regressions and `-Clean` cleans intermediates after the operation. See [build and release behavior](../specs/build-and-release.md) for the implementation contract.

Published release-contract checks protect the content and ordering of historical version sections. They must not require the Unreleased section to stay empty or demand that an old architecture remain the current implementation forever. Adapt location assertions when a document is moved while retaining its historical meaning. The [release policy](releases.md) owns baseline/category selection, notes and publication. Keep parser, tag-admission and draft/asset/final-state failure tests deterministic with fake Git/GitHub boundaries; never publish a real release as a test of those fixtures.

Distinguish a completed command from a passing check, and a passing offline check from live service/audio success. A final report states what changed, the checks and final file state they cover, failures or skipped work, and material limitations. The [API evidence policy](api-evidence.md) governs all real network or synthesis claims.

For editable numeric labels, compare the resolved display and editor bounds, keep units separate, and test draft isolation, blur/keyboard completion, culture parsing, invalid input and persistence/reload through the bound slider. A compiled focus/template test does not establish physical pointer or installed-host behavior; record those observations separately.

Inspect the actual text viewport as well as outer input bounds: theme-provided clear buttons and other adornments can clip valid formatted values. An offline fixture that applies a native theme setter must be labeled as a theme-state fixture; use installed-host acceptance for real focus behavior. Keep independent themed test groups on the shared STA without combining all work into a single timeout envelope.

For icon alignment, compare rendered glyph centers as well as button bounds. For sliders, compare against the native content inset after responsive wrapping. For mode switches, compare all navigation positions and the following section's vertical position with equivalent empty content; selected font metrics, hidden validation space and native adornments can move neighboring controls even when explicit sizes match. Exercise supported locales and narrow/normal widths.

Font drawing bounds can include padding beyond the actual outline. For mixed font/vector action rows, inspect physical raster ink at fractional DPI and inherited text-formatting/layout-rounding states; equal line boxes or `Drawing.Bounds` alone can miss the reported visual displacement. Keep the known pre-fix raster failure and distinguish edge quantization from an actual row offset. Preserve button hit targets, commands and keyboard focus while correcting visible glyph alignment.

Synchronize asynchronous assertions on the event they actually inspect. A fake device's Play counter can become visible before Play returns and before the caller's output-start notification; it is not a completion signal for that notification. Await an explicit task/event with appropriate publication ordering, retain independent clock/deadline assertions, and preserve the failed evidence. Do not repair a scheduling race with an arbitrary sleep, a longer timeout or changed production ordering merely to satisfy the fixture.

Separate first compiled-view construction from binding assertions when they are distinct fixture phases. Retain explicit per-phase bounds on the same shared STA and log safe monotonic enqueue/entry/completion timings. This changes the combined fixture budget and must be reported; a broad timeout alone does not prove cold loading, a framework stall or a deadlock. A later phase timeout remains a failed check, not a reason for automatic retries or a larger global limit.

The first compiled SettingsView construction in the input-binding fixture has a dedicated fifteen-second queued-action budget. A recorded CI action entered after 1 ms and returned after 5,254 ms, exceeding its former five-second budget; this establishes a finite late completion, not its underlying cause. Fifteen seconds is explicit CI construction headroom, not an observed maximum or production performance promise. Dispatcher startup, default Action/async fixtures and the separate binding assertions retain five seconds. Construction plus binding execution budgets therefore increase from ten to twenty seconds. On construction timeout, observe the same action for at most twenty further seconds and still rethrow the original failure: the construction/observation bound changes from about twenty-five to thirty-five seconds, excluding dispatcher startup. Never retry, replace the action or move it to another thread to obtain a pass.

For wheel interactions, test routed event ownership as well as the value: the intended resting target consumes it, bounds do not leak page movement, and editors/units/other content retain ordinary bubbling. For folded empty states, test the transition that removes the final item while the prior body is collapsed. Copy-action tests use a fake clipboard boundary, require write-before-success feedback, and verify that author/description clicks and selection/playback state remain independent.

The activity-dispatcher regression runs failure and cancellation as separate sequential actions on the same shared STA, each retaining five seconds. This changes the two-case successful action budget from five to ten seconds; it does not change dispatcher startup, global/default action timeouts or the inner two-second startup and three-second playback waits. Keep the playback wait synchronous: the assertions deliberately inspect state before queued UI retirement is drained. Record safe monotonic queue/entry/stage/cleanup timings. When the outer action deadline expires, observe that same action's completion off the STA for at most twenty further seconds and still throw the original failure; do not retry, pump, cancel or replace it. Distinguish an action's own timeout exception from the outer deadline. An uninstrumented CI timeout identifies a failed envelope, not a proven cold-control, scheduling or production root cause.

For credential edits, verify the retained presentation fields, object identity, applied navigation state and saved display snapshot separately from future request authorization. Cover A → B and A → B → A, cancellation-ignoring responses, deferred dispatcher callbacks, and a cache subscriber that reenters before another subscriber receives the same notification. Check accepted identity at conditional persistence as well as at the response check. Failed saves, ordinary same-key writes and uncommitted facade construction must not advance identity or let an old candidate restore it. A retained display snapshot is not evidence of a valid cache hit in a different credential partition.

For native popup feedback, attach the compiled fixture to an owned presentation source and pump its dispatcher. An unattached native tooltip may close independently of the feature's idle/leave logic, so it does not establish that lifecycle. Compare derived controls with an actual themed native peer, and verify repeated updates, idle reset, leave/unload/template replacement, real drag ownership, original tooltip restoration and save counts. Refreshing feedback must not simulate a value-changing drag or re-snap an already valid value. Distinguish hidden-presentation-source fixtures from installed-host pointer acceptance.

For numeric zero boundaries, exercise signed-zero bits, displayed text, the native bubble, the TwoWay source and persisted/reloaded values together. Floating-point equality treats positive and negative zero as equal, so correcting a dependency property's local value does not by itself prove the source was corrected. Verify supported drag, wheel and committed-entry paths from both directions, valid negative neighbors, and exactly one save per effective change. Fix representation at the owning value boundaries instead of masking a minus sign in formatted text; distinguish supported input paths from arbitrary direct dependency-property injection.
