# Voice search, cards and numeric controls design

Status: approved design, 2026-10-24. This document describes the requested change; current implementation specifications are updated with each completed task.

## Intent and approach

Make explicit search adjustments useful without losing browsing state, expose voice creation dates consistently, and improve precise numeric input. The selected approach is a compact search-adjustment popup. The latest approved language picker is a two-column multiselect grid with equal 32-DIP tiles and 6-DIP gaps. All languages is alone in the left cell of its first row; specific tiles use the existing embedded flags. This supersedes the original Task 4 single-select dropdown.

## Required behavior

- Add an icon-only, borderless-at-rest adjustment action inside the search input. Use the requested two horizontal slider-knob silhouette, not a funnel. Reserve the text/caret viewport for the action.
- Use a 324-DIP popup design width, clamped to the settings viewport and monitor work area, with native opaque theme resources, Close, Reset and Apply.
- Offer All languages plus en, zh, de, ja, fr, es, ko, ar, ru, pt. Specific tiles show the same embedded flags/names as voice language pills. All languages has text/check only, is exclusive with specifics, and returns when the final specific is cleared. All ten specifics remain a filtered preset set. Capture validated, detached, deduplicated immutable selections in preset order and send repeated language keys in one request. Provider AND/OR semantics remain unspecified. Long captions trim with full tooltips/accessibility; header/footer stay reachable around the scrolling body.
- Sort choices are Relevance first, Most used first and Newest first, mapped to score, task_count and created_at. The user's 2026-10-24 wording refinement sets Simplified Chinese titles to 相关优先, 热门优先 and 最新优先. The three radio choices display titles only, without helper descriptions. Default is score. Relevance first is the plugin's display name for the provider's score order; no client ranking is introduced. Popularity is generation count descending and creation order is newest first, observed on the public endpoint on 2026-10-24; the documentation does not specify directions or the score formula.
- Every Apply closes the popup and immediately issues exactly one page-one request using the visible search text and draft language/sort, including unchanged criteria. New requests cancel/replace prior ones. Draft selection, Reset and dismissal issue no requests. Reset restores All + score; Close, Escape, outside click and browse-tab changes discard drafts.
- Commit successful current-owner criteria, results and pagination together. Failure retains the last successful state. Paging uses the last successful criteria. Criteria are ViewModel-session state, not durable preferences.
- Coordinate the adjustment popup and language-overflow popup with one overlay owner per settings view. Keep native tile/radio Enter/Space local and explicit Apply independently operable. Support keyboard focus, dismissal, scrolling, deactivation and cleanup.
- Rework all voice cards: Search, By-ID, Favorites and the current selected voice. Put actions at the title row's right; title, bounded description, language pills and author precede one stretching row with popularity left and creation date right. Keep existing copy/favorite/preview/progress/apply/clear behavior and placeholders. Preserve 40-DIP list avatars and the selected card's 48-DIP avatar.
- Add nullable CreatedAt throughout provider DTO, detached metadata cache, visible cards, selected CachedVoice, startup and preview refresh. Parse malformed/wrong-type provider date metadata locally as null, consuming the whole value. Store UTC; display system-local yyyy-MM-dd with a full offset-bearing tooltip. Missing/invalid dates show an em dash. Authoritative null refreshes clear former dates.
- Keep settings schema 2 and ID-only favorite persistence. Extend date migration/copy/save/rollback while preserving unknown/future-schema read-only behavior and existing credential partitions, leases, cache TTL and card identity.
- Enable native slider click-to-point, retaining hundredths, bounds, bindings and zero normalization. Change the shared slider/resting-text wheel dwell from 250 to 350 ms, retaining all rearm and event-ownership rules.
- Make all four resting numeric fields/editors 52 DIP wide and 32 DIP high, with 2-DIP horizontal padding and 1-DIP border reserved in both states. Right-align resting numbers and center editable drafts in the unchanged native viewport (the later Task 9 refinement supersedes Task 2's same-right-edge requirement). Resting borders are transparent; focus changes only the brush. Fix the hardcoded centered ContentPresenter. Keep the native clear adornment locally disabled. Use 11-DIP secondary-colored × and dB on the number's font baseline, with the native-size primary number and the field's existing right inset supplying a compact text-like gap. Task 15 supersedes Task 9's caption-size × and numeric-size dB; the allocation-derived gap is not asserted equal to a literal native space. Preserve separate unit hit/event ownership and an auto unit column collapsed when empty. Preserve the surrounding native settings-card layout and 180-DIP sliders.
- By-ID errors expire after exactly five seconds, restart on every occurrence including identical text, and clear immediately on input edits/new lookups. Use injectable time, cancellable versioned ownership, UI dispatch and retirement so old timers/responses cannot affect newer messages. Expiry changes only the error.
