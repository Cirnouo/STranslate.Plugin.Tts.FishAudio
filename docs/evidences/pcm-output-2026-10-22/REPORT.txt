One recorded synthesis and offline playback evidence

This bundle preserves selected artifacts from one successful synthesis of the same 950-character English input used to investigate intermittent electrical noise. It is a selected-artifact publication, not a complete copy of the original capture directory. The original raw upstream PCM file is omitted because its exact bytes can be reconstructed from the twelve audio payloads in the thirteen retained incoming MessagePack messages. The twelve outgoing MessagePack messages are retained unchanged. The original request summary is omitted and replaced by an allowlisted sanitized projection. The original capture summary is retained unchanged; its artifact list therefore includes original names and hashes for files intentionally omitted here. The manifest distinguishes exact copies, renamed exact copies, sanitized projections, new verification artifacts, and omitted originals.

The request selected exactly s2.1-pro-free and PCM, with no retry or model fallback. The request voice ID, all twelve non-key settings, input text, endpoint, parameter snapshot, and production/audio/harness assembly fingerprints are retained in the sanitized request summary. Speed was 1, volume 1 dB, temperature 0.2, top_p 0.25, normalization enabled, loudness normalization enabled, and condition_on_previous_chunks enabled. The recorded capture enforced the earlier of a 120-second deadline and the free-model UTC cutoff. The binary capture budget was 18 MiB and was not reached.

The source contains 6,053,526 bytes: 68.6340816 seconds of signed 16-bit little-endian mono PCM at 44,100 Hz. Its SHA-256 is 3a7783c5ccb27cbebf977a5c75c6f954b1ec6bf50359882b808d584feb32397f. The rendered provider stream begins with those exact bytes in order, without any modification, loss, duplication, or inserted silence. Its remaining 5,814 bytes are zero-valued padding after the final real sample. There are two padded reads, both at the tail, and the last real sample is zero. Cursor accounting identifies real and padding spans; legitimate zero-valued source samples are retained. The device position reached 6,054,444 bytes, beyond the final real PCM position of 6,053,526 bytes.

There were no full-scale or 99%-full-scale source samples. The sample range was -17,071 to 20,751, with a peak near -3.97 dBFS. The first server audio payload contains 7.7555 seconds, so an onset near one second lies inside one unchanged server payload. The largest raw server-message boundary delta was 155 sample units. Larger changes occur inside the source waveform, including the largest adjacent-sample delta of 11,000 near 24.208 seconds. These measurements do not by themselves identify audible noise.

Provider calls were nominally 50 ms apart, with a median interval of 49.988 ms and maximum interval of 60.923 ms. The maximum measured provider Read duration was 0.3447 ms. Sampled device positions and refills support healthy scheduling during this run. They do not prove uninterrupted physical sound. The software trace is before the driver/mixer and contains no microphone or acoustic loopback recording. Instrumentation adds bounded allocation, copying, locking, and timing work.

The capture establishes byte continuity and correct tail accounting for this synthesis. It does not establish whether the reported intermittent symptom occurred in that run, identify an upstream or device cause, or validate a production fix. No fade, latency, codec, or volume fix follows from these data alone. Separate offline comparisons, if present in this bundle, use the same saved waveform and are experiments rather than a production change. Subjective listening outcomes remain distinct from byte-level verification.

Run python verify.py from this directory with Python 3. No network, credentials, third-party Python packages, audio devices, or local application installation are required. The verifier checks every retained file against the publication manifest, decodes the raw MessagePack, reconstructs upstream PCM, validates request/input consistency, recomputes source/provider equality and exact padding positions, and checks device drain. The manifest excludes itself from its own hash inventory to avoid a circular hash.

Offline comparison and observed mitigation scope

After the first fifteen seconds of the saved upstream waveform did not reproduce the reported noise in a listening check, the same saved PCM was replayed through the actual production player, decoder, PCM ring, and WaveOut adapter. A used the production 100 ms/two-buffer default. B changed only the output configuration to 200 ms/four buffers, preserving 50 ms/4,410-byte device buffers. No synthesis, network request, credential, or profile access was involved. The listener reported the same electrical noise with A and did not hear it with B. These are qualitative observations from one sequential, unblinded A/B pair; no microphone or loopback recorded the sound.

Both cases delivered all 1,323,000 bytes of the same fifteen-second source exactly, with SHA-256 3b088864790d89ab35e3f8597a43a0c039ea65e6c0656536fa0668008f5f317b, without speech-time ring padding. The output position passed the real tail and cleanup completed in each case. A read 8,820 bytes of trailing padding; B read 17,640. These extra bytes occur after audio time 15.0 seconds as the queues read ahead. The replay-render files are omitted to avoid duplicating the same waveform. Their exact recorded hashes are retained and verified against reconstruction from the retained source prefix plus the recorded zero suffix. Raw replay read, position, lifecycle, summary, and original runner sources are retained.

A had 35 provider-read gaps over 75 ms, with a maximum of 101.0016 ms. The earliest was at 0.0932 seconds after the playback callback; further gaps occurred near 0.3007 and 0.8593 seconds and recurred throughout. B had one initial prefill-to-first-refill gap of 98.6984 ms at about 0.1014 seconds, while four buffers were already queued. Every later B gap was at most 58.9531 ms. Excluding each case's initial prefill and first-refill gap leaves 34 long gaps for A and zero for B. A also had 34 runs of unchanged reported device position longer than 10 ms after startup; B had none. These are API observations, not direct measurements of a hardware queue or physical sound.

Playback callback to Stop took 15,383.3469 ms for A and 15,050.3949 ms for B. Together with the listening result, the identical source bytes and timing difference support increasing queued output headroom in this case. They do not establish the exact driver mechanism or reliability across all machines and loads. A production change to four 50 ms buffers increases nominal output queue capacity by 100 ms; this does not imply exactly 100 ms of additional measured startup latency or any change in cloud synthesis time.
